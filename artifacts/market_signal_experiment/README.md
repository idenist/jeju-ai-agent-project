# 제주 감귤 경매가격: 시장 정보 추가 효과 탐색 (독립 실험)

**목적:** 현재 가격을 유지하는 A, 기존 규격별 가격/거래량 이력만 사용하는 B, 여기에 **제주산 감귤 경매의 해당 시장 전체 동향**을 추가한 C를 동일 표본에서 비교합니다. 임준억·양정현 파일, 기존 저장소·브랜치·모델 코드는 변경하지 않습니다.

## 실행 (Windows CMD, ZIP 압축 해제 후)

```bat
py -m pip install -r requirements.txt
```

```bat
py run_market_signal.py
```

`py` 명령이 없으면 `python`으로 바꾸세요. 파일이 `data/경매_원본_데이터.zip`에 포함되어 있어 별도 데이터 복사 없이 동작합니다. 원본 ZIP은 **읽기만** 합니다. 결과는 `results/` 아래에 저장합니다. 다른 파일로 실행할 때는 `py run_market_signal.py --input "C:\\데이터\\경매_원본_데이터.zip" --out-dir results`를 사용합니다.

## 실험 사전 고정 사항

| 구분 | 내용 |
|---|---|
| 학습 | 2024-10-01~2025-02-28 (2024-25 시즌) |
| 탐색 검증 | 2025-10-01~2026-02-28 (2025-26 시즌) |
| 제외 | 2026-27 부분 시즌, 시간 외 제주의 출하량 CSV |
| 정답 | 같은 시장·품종 코드·등급 코드·크기 코드·포장 종류·포장 중량의 t+3/7/14 **정확한 달력일** 평균 경락가격 (거래금액÷kg) |
| 정답 선택 | t와 t+h 양쪽에서 등급/크기 미상 없음, 거래 건수 각각 5건 이상; 결측 목표일 보간 금지 |
| A | 오늘 가격이 미래에도 유지된다고 가정 (선택 기준선은 언제나 더 이른 3일) |
| B | A의 현재가 + 요일·월·시즌경과일 + 동일 규격 3/7일 지연가격·최근 7일 이력·거래량·건수 |
| C | B의 모든 정보 + 같은 시장의 제주산 감귤 전체/동일 품종 최근 7일 vs 이전 7일 거래량·가격추세·품종비중 |
| B/C 모델 | 양쪽 동일 HistGradientBoosting, 고정 파라미터 및 random_state=42, 미래/기준 가격 **로그비** 학습 |
| 점수 | 가격 MAE (원/kg), 3일 vs 14일 출하 가상 기회손실(원), 월별 오차·주 단위 블록 부트스트랩 |
| 시점 | **거래정산일 t의 마감 이후** 공개된 자료만 사용된다고 가정. 날짜가 t보다 늦은 것은 입력 금지 |

**시장 전체**란 전국 감귤 출하량이 아니라, 입력 ZIP에 있는 **동일 도매시장 내 제주산 감귤 경매 기록 전체**를 뜻합니다. 숫자에 다른 품종·등급이 섞이므로 시장가격 지표는 구성 변화 영향을 받습니다.

### 왜 출하량 CSV를 쓰지 않았나?

`jeju_shipments(1).csv`는 2025-09-17 이후의 날짜가 없고 날짜 누락도 있으므로 2025-26 검증 시즌의 수급 설명 변수로 유효하지 않습니다. 기존 경매 원본의 과거 **관측 거래량**을 대신 활용하되 이는 제주 전체 생산·출하량이 아닙니다.

### 기존 전처리 코드와의 관계

`integration/agents`의 `scripts/preprocess_auction.py`와 동일한 기본 필터(제주산 감귤·경매만, 숫자 및 중량 검증, 전체행 정확 중복 제거)와 거래금액÷중량 집계를 사용합니다. **정규화된 코드 기반 그룹 키**를 사용하여 표시명 차이만으로 같은 규격이 쪼개지는 문제는 피합니다. 기존 전처리의 출력과 행 단위 100% 동일한 복제 코드는 아닙니다. 따라서 실험 결과를 기존 V1~H6의 절댓값과 직접 비교하지 말고, **이번 실험 안의 같은 표본 A/B/C 비교**로 해석하세요.

예측 기준일 t까지의 현재/시장 가격은 모두 정산일 t까지 알려졌다고 가정합니다. 원본의 `mdfcn_dt`가 실제로 언제 수정/게시됐는지 데이터로 입증할 수 없으므로, 실제 농가가 사전 출하 결정을 내리는 시점에 입력이 이용 가능하다고 보장하지 않습니다.

### 파일 구성

- `run_market_signal.py`: 단일 실험 실행 스크립트
- `requirements.txt`: 실행 의존성
- `tests/test_experiment.py`: 누출 방지·출하 선택·표본 누락 등 단위 테스트
- `data/경매_원본_데이터.zip`: 사용자가 제공한 **원본 그대로** 동봉
- `results/REPORT.md`: 1페이지 요약
- `results/metrics.json`: 원본 품질, 월별 MAE, 기간별 MAE, 가상 비용 기반 출하 판단, 한계
- `results/paired_predictions.csv`: 비교에 쓰인 **동일 검증 사례**별 정답, 세 방식의 예측
- `results/choice_3v14.csv`: 같은 기준일·규격의 3일·14일 예측을 묶어 선택·기회손실 비교

## 결과의 판정 기준

1. **C의 평균 MAE가 B보다 작아야 합니다** (3/7/14일별, 월별 확인).
2. **3 vs 14일 출하 선택 기회손실**도 B보다 줄고, A(항상 이른 출하) 기준선보다 나은지 봅니다.
3. 날짜별 사례가 독립이 아니므로 주 단위 블록 부트스트랩의 불확실성을 점검합니다.
4. 개선되더라도 2025-26 검증은 이미 기존 실험에서 반복 사용한 시즌입니다. **독립 검증, 운영 배포를 주장하면 안 됩니다.**

**실패했을 때:** 시장 정보가 없는 것인지, 표현이 약한 것인지, 독립 시즌이 부족한 것인지 구분해야 합니다. 단일 부정적 결과만으로 특정 입력이 무의미하다고 단정하지 않습니다.

**출하 비교 점수**는 3톤·감모율 3일 1%/14일 4%·수수료 3일 5%/14일 7%·보관비 1만원/일을 가정한 모의 계산입니다. 실제 농가의 선택/손익이 아닙니다.

### 코드·결과 점검

```bat
py -m unittest discover -s tests -v
```

본 패키지는 **기존 GRU 모델을 재현하거나 다시 학습시키지 않습니다.** B/C는 같은 고정된 HistGradientBoosting 모델이므로, 이번 실험의 개선분만 직접 비교하세요. 과거 H5/H6 결과(21일 입력 이력 제한 포함)와 평가행 수·절댓값을 그대로 비교할 수 없습니다.
