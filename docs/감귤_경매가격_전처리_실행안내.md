# 제주 감귤 경매가격 전처리 파이프라인

**목표:** API 수집 원본 `auction_trades.csv`를 팀의 Agent가 바로 조회할 수 있는 일별 가격 데이터로 가공합니다. 원본은 절대 수정하지 않습니다.

## 1. 파일 배치

압축파일을 프로젝트(`C:\SKN projects\jeju`) 폴더에서 풀면 됩니다.

```text
jeju/
├── scripts/
│   └── preprocess_auction.py
└── data/
    ├── raw/
    │   └── auction_trades.csv        # 본인이 수집한 원본을 여기에 복사
    ├── processed/
    │   ├── daily_prices.csv         # 동일 조건(품종·등급·크기·포장)별 평균가
    │   └── daily_variety_prices.csv # 품종별 일일 평균가(현황 파악용)
    └── reports/
        └── auction_quality_report.json
```

**참고:** ZIP에는 이미 실행 결과 CSV가 포함되어 있지만, 2025년 데이터 등을 추가하면 아래 명령으로 다시 생성하세요.

## 2. 실행 방법 (PowerShell)

```powershell
# 원본 데이터가 프로젝트 최상단에 있는 경우에만 실행
Copy-Item .\auction_trades.csv .\data\raw\auction_trades.csv

# Python 3.9 이상, 별도 pip 설치 불필요
python scripts/preprocess_auction.py
```

추가 연도 파일이 별도로 존재한다면 원본을 합칠 필요 없이 여러 파일을 지정할 수 있습니다.

```powershell
python scripts/preprocess_auction.py --input data/raw/auction_trades.csv data/raw/auction_trades_2025.csv
```

결과 저장 위치 변경:

```powershell
python scripts/preprocess_auction.py --input data/raw/auction_trades.csv --out-dir data/processed --report-dir data/reports
```

## 3. 데이터 처리 규칙

| 규칙 | 처리 방법 |
|---|---|
| 품목 | `gds_lclsf_cd=06`, `gds_mclsf_cd=14` |
| 원산지 | `plor_nm`에 제주특별자치도 표기된 거래만 분석 |
| 거래 방식 | `trd_se=경매`만 사용. 정가수의·전자거래는 제외(원본에는 남음) |
| 날짜 | `trd_clcln_ymd` 거래정산일 사용(농가 출하일과 다를 수 있음) |
| 표준 품종 | `gds_sclsf_cd` 기준 8종. `corp_gds_vrty_nm` 자유입력 표기는 사용하지 않음 |
| 등급/크기 | `.` 또는 공란은 `미상`으로 표시, 임의 추정 금지 |
| 가격 단위 | `총낙찰금액(sum(totprc)) / 총kg(sum(unit_tot_qty))` |
| 무효 거래 | 0 이하 수량·금액, 수량×낙찰가 불일치, 중량 불일치 등 제외 |
| 중복 | *모든 원본 필드가 완전히 같은 행*에 한해 제거 |

가격은 거래별 kg당 가격의 **단순평균이 아닌 물량 가중평균**입니다. 예: 5kg 상자 2개가 10,000원/상자에 팔렸다면 총 10kg에 총 20,000원이므로 2,000원/kg입니다.

## 4. 결과 파일과 사용법

### `daily_prices.csv`: 출하 시점 비교용 기본 데이터

한 행의 기준: `날짜 × 시장 × 표준품종코드 × 등급 × 크기 × 포장종류 × 포장중량 × 거래방식`.

주요 컬럼: `date`, `market_code`, `market`, `variety_code`, `variety`, `grade`, `size`, `package_kg`, `avg_price_kg`, `total_kg`, `transaction_count`, `quality_flag`.

**Agent에서는 같은 `market_code`, `variety_code`, `grade_code`, `size_code`, `package`, `package_kg`, `trade_type`를 가진 행만 날짜별로 비교하세요.** `quality_flag`에 `GRADE_UNKNOWN`, `SIZE_UNKNOWN`, `LOW_SAMPLE`이 있으면 해석에 주의해야 합니다. `LOW_SAMPLE`은 거래 5건 미만이라는 알림이지 통계적 정확도 보장이 아닙니다.

### `daily_variety_prices.csv`: 전체 동향 확인용

한 행의 기준: `날짜 × 시장 × 표준품종코드 × 거래방식`.

품종별 평균가격, 총물량, 거래건수와 등급·크기 미상 **물량 비율(%)**을 제공합니다. **등급과 크기가 섞여 있으므로 일자별 평균가격 차이가 순수한 시세 변화를 의미하지는 않습니다.** 참고용 차트/요약에 적합하며 출하 결정의 단독 근거로 쓰지 마세요.

### `data/reports/auction_quality_report.json`: 자동 검증 기록

원본 건수, 통과/제외 건수와 사유, 날짜 범위, 품종별 사용 건수, 결과 행 수를 담습니다. 결과 값과 처리 과정을 발표에서 검증 근거로 제시할 수 있습니다.

### 주의할 점

1. **한 달 남짓의 자료만으로 미래 가격을 예측할 수 없습니다.** 3·7·14일 전후의 *과거 관측값* 비교까지만 가능해요.
2. **도매시장 경락가격 ≠ 농가 실수취액.** 보관비와 감량률은 별도의 사용자 입력·손익 계산 도구가 필요합니다.
3. 품종별 일일 평균은 상품 구성에 영향을 받으므로, 실제 가격 비교는 동일 규격 집계를 우선 사용하세요.
4. 표준 품종명은 `gds_sclsf_cd`별 API 분류를 따른 것이며, 가공품질이나 감귤 세부 계통의 완전한 동일성을 보증하지 않습니다.
