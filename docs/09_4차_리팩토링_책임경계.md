# 4차 리팩토링 — 실행 책임과 원인 추적 기준

## 목표와 제외 범위

3차까지 기존 구조에 남아 있던 코드 소유권 중복과 역방향 의존을 줄입니다.
AI 응답 정책, 프롬프트, 가격 계산, 가격 원천 데이터, 기존 화면의 기능은 **변경하지 않습니다**.
최초 발생한 버그의 행동이 이 리팩토링만으로 사라진다고 주장하지 않습니다.

## 한 곳에서 수정할 책임

| 변경하려는 동작 | 수정 소유자 | 호출 관계 |
|---|---|---|
| 사용자 질문의 A/B 비교 의도 인식 | `agents/future_pair_intent.py` | `AgentSession.run`이 의도 판단 요청 |
| Agent의 모델 호출 및 한도 관리 | `agents/agent.py:AgentSession.run` | `agents/harness.py`의 한도·반복 호출 방어 |
| 모델 도구 요청의 상태·후속 조건 반영 | `agents/agent.py:AgentSession._execute_requested_tool` | `agents/tools.py:execute_tool`로 도구 계산 위임 |
| 도구 결과 중 모델에 전달할 안전한 필드 | `agents/tools.py:model_receipt_for_tool` | 화면에는 원래의 완전한 로컬 계산 결과 사용 |
| A/B 비교 중 현재 입력·누락·다음 질문 | `agents/future_pair_state.py` | `presenters/presentation.py`는 표시만 담당하도록 점진 정리 대상 |
| 가격자료 스냅샷 활성 버전·무결성 검사 | `services/market_snapshot.py` | `data_refresh.py`는 갱신, `evidence.py`는 읽기 |
| 채팅 보고서 요청 판별·버튼 선택 문구 | `ui/chat.py` | UI 공통 상태 소유자는 `ui/context.py` |

## 검증

- 전체 오프라인 회귀 및 평가셋 사전검증 통과 후에만 변경을 staging 합니다.
- 원천 데이터 변경 금지; 파일·도구 계약 명칭 변경 금지.
- 새로 생긴 파일: 서비스 스냅샷 책임 모듈 1개, 아키텍처 계약 테스트 1개, 책임 설명 문서 1개.
- 검증 결과가 나오기 전에는 안정성 향상·성능 향상을 확정적으로 주장하지 않습니다.

## 이미 확인된 제품 결함 — 이번 패치에서 수정하지 않음

사용자가 시장 규격을 모를 때 출하통계 조회로 유도하는 동작은
`agents/future_pair_state.py`의 후속 질문 정책과 `agents/agent.py`의
과거 가격 우선 지시를 검토해야 합니다. 리팩토링으로 실행 경로를
정리한 이후 사용자 목표를 잃지 않는 상담 정책을 별도로 고쳐야 합니다.
