# 04. 사용자 및 운영 가이드

> **대상:** 제주 감귤 출하 의사결정 AI Agent 팀 통합본\
> **기능 코드 점검 기준:** `integration/agents` · `65175656e637d576056da76d5915287a2a68a84e` (2026-11-11)\
> **사용 환경:** Windows CMD · Python 3.13 x64 · Streamlit 로컬 웹 화면\
> **문서 위치:** `docs/04_사용자_및_운영_가이드.md`를 기준으로 코드 링크를 작성했습니다.

이 문서는 **처음 실행하는 팀원·일반 사용자**와 **데이터 및 실행 환경을 관리하는 운영자**를 위한 안내서입니다. 실제 화면의 버튼 이름과 코드 실행 흐름을 기준으로 작성했습니다. 시스템 내부 구조와 데이터·계산식에 대한 상세 설명은 각각 02·03번 문서에서 다룹니다.

## 1. 먼저 알아둘 것

### 1.1 프로그램에서 할 수 있는 일

이 프로그램은 감귤의 현재 판매 조건과 보관 후 판매 조건을 비교해 **보관 후 판매가 현재 판매보다 유리해지려면 필요한 단가**를 계산합니다. 준비된 CSV에서 과거 출하통계와 경매가격을 조회하고, 사용자가 선택한 결과를 보고서로 저장할 수 있습니다.

| 사용 방식 | 할 수 있는 일 | OpenAI API 키 |
| --- | --- | --- |
| **조건 카드** | 물량·가격·보관비·감모율 입력, 출하 대안 손익 계산 | 필요 없음 |
| **자료 직접 조회** | 과거 경락가격, 출하통계, 확보 자료 탐색 | 필요 없음 |
| **분석·보고서** | 가정 범위 비교, 허용 조건 역산, PDF·Markdown·JSON 저장 | 필요 없음 |
| **자연어 대화** | 질문 해석, 조건 추출·변경, Python 분석 도구 선택 | 필요 |
| **자료 관리자** | 지원하는 경매 원본 CSV 검사·미리보기·적용 | 필요 없음 |

**처음 사용한다면** 설치 후 *가상 예시 → 손익 비교 → 과거 가격 직접 조회 → PDF 저장* 순서로 따라 해보세요. API 키 없이 기본 사용 흐름을 확인할 수 있습니다.

### 1.2 주요 용어

| 용어 | 이 프로그램에서 의미하는 것 |
| --- | --- |
| **현재 판매 조건** | 지금 판매한다고 가정했을 때의 물량·제시가격·수수료·비용 |
| **보관 대안** | 며칠 보관할지, 보관 중 감모율과 하루 비용이 얼마인지 설정한 비교안 |
| **감모율** | 설정한 **보관기간 전체**에 걸쳐 줄어드는 판매 가능 물량 비율 |
| **손익분기 단가** | 보관 후 판매 시 현재 판매와 비교금액이 같아지는 미래 판매단가 |
| **과거 경락가격** | 경매시장에서 실제 관측한 가격. 출하 전 농가에 제시된 가격과 구분하여 표시 |

| **자료 스냅샷** | 특정 시점에 수집·정제하고 해시로 검증한 CSV 묶음 |

## 2. 설치하고 실행하기

### 2.1 준비 환경

- Windows PC, 인터넷 연결(최초 패키지 설치에 필요)
- **Python 3.13 x64 및 Python launcher (`py`)**
- Git(저장소를 내려받을 때 사용)
- 로컬 브라우저(Edge, Chrome 등)

Windows **명령 프롬프트(CMD)**를 열고 Python 설치 상태를 확인합니다.

```bat
py -3.13 --version
```

Python 3.13 버전이 출력되면 다음 단계로 넘어갑니다. `No suitable Python runtime found` 등 오류가 발생하면 Python 3.13과 launcher 설치를 확인하세요.

### 2.2 새 PC에서 시작하기

아래 명령을 CMD에서 순서대로 실행합니다.

```bat
git clone --branch integration/agents https://github.com/idenist/jeju-ai-agent-project.git
cd jeju-ai-agent-project
setup-center.cmd
run-juneok.cmd
```

각 명령은 다음 역할을 합니다.

1. `git clone`: 팀 통합 브랜치를 내려받습니다.
2. `setup-center.cmd`: `.venv`를 만들고 `requirements-juneok.lock`에 기록된 패키지를 설치합니다. `.env`가 없으면 `.env.example`을 복사합니다.
3. `run-juneok.cmd`: `.venv`의 Python으로 Streamlit 화면을 실행합니다.

실행되면 브라우저에서 터미널에 표시된 `http://127.0.0.1:포트번호` 주소를 엽니다. 포트번호는 실행 환경에 따라 달라질 수 있습니다. 서버를 종료하려면 CMD에서 **Ctrl+C**를 누릅니다.

> 기존 개발 폴더가 있다면 다시 복제할 필요 없이 해당 폴더에서 `run-juneok.cmd`를 실행하면 됩니다. 코드를 갱신하기 전에는 작업 중인 변경사항을 확인하세요.

### 2.3 자연어 대화에 사용할 키 설정

기본 화면 확인에는 키가 필요 없습니다. AI 대화를 사용할 때만 프로젝트 루트의 `.env`를 편집합니다.

```bat
notepad .env
```

파일에서 다음 항목을 설정합니다.

```dotenv
OPENAI_API_KEY=본인_API_키
OPENAI_MODEL=gpt-6-luna
```

설정을 변경했다면 화면을 새로고침하거나 앱을 다시 실행해 연결 상태를 확인합니다. OS 환경변수에 같은 이름의 설정이 있으면 OS 환경변수가 `.env`보다 우선합니다. 자연어 대화는 외부 모델 API를 호출하므로 **호출 비용과 네트워크 연결**이 발생할 수 있습니다.

운영자의 경매 API 사전 수집에 쓰는 `DATA_GO_KR_KEY`는 별도 선택 설정입니다. 기존 CSV 조회, 손익 계산, 보고서 저장에는 필요하지 않습니다.

## 4. 따라 해보기: 7일 보관 손익 비교

가장 쉬운 방법은 프로그램에 준비된 **가상 예시 조건**을 사용하는 것입니다.

### 4.1 기본 예시 불러오기

1. 프로그램을 실행합니다.
2. `현재 조건 카드` 영역에서 **`가상 예시 조건 불러오기`**를 클릭합니다.
3. 표시된 조건을 확인합니다.

| 항목 | 예시 값 |
| --- | ---: |
| 비교 물량 | 3,000kg |
| 현재 판매 가능 단가 | 3,000원/kg |
| 가격 기준 | 수수료 차감 후 |
| 보관기간 | 7일 |
| 기간 전체 감모율 | 2% |
| 전체 물량 하루 보관비 | 20,000원 |
| 보관 외 기타 고정비 | 양쪽 동일하다고 가정해 비교에서 제외 |

이 예시는 **실제 농가 거래가 아닌 사용법 확인용 가정**입니다. 프로그램은 조건을 불러오면서 현재 판매와 보관 대안을 계산합니다.

### 4.2 결과 읽기

예시의 현재 판매 비교금액은 `3,000kg × 3,000원 = 9,000,000원`입니다. 7일 보관하면 판매 가능 중량은 `3,000 × (1 − 0.02) = 2,940kg`, 추가 보관비는 `20,000 × 7 = 140,000원`입니다.

보관 후 현재와 같은 비교금액을 얻기 위해 필요한 최소 단가는 **3,109원/kg**입니다(정수 원 단위 올림). 이 숫자는 예상 시장가격이 아니라, 입력한 보관 조건에서 계산한 **필요 판매단가**입니다.

### 4.3 감모율을 4%로 바꿔보기

1. **`조건 직접 입력·수정`**을 펼칩니다.
2. `대안 1 기간 전체 감모율(%)`을 `2`에서 `4`로 변경합니다.
3. 같은 7일의 전체 감모율을 입력한 것이 맞는지 확인합니다.
4. **`입력 조건 비교`**를 클릭합니다.

판매 가능 중량이 2,880kg으로 줄어들어 최소 단가는 **3,174원/kg**이 됩니다. 감모율이 높아질수록 같은 수익을 확보하기 위해 필요한 가격도 올라가는 것을 확인할 수 있습니다.

### 4.4 결과 파일 저장

계산 결과 아래의 **`결과와 보고서 미리보기`**에서 `PDF 보고서 내려받기`를 누릅니다. 필요하면 `보조 형식 · Markdown`을 펼쳐 MD 파일도 받을 수 있습니다.

현재 비교조건까지 저장하려면 사이드바의 `비교 건 저장·불러오기`에서 이름을 정하고 **`비교 JSON 내려받기`**를 누릅니다. PDF는 읽기용 보고서이고, JSON은 이후 조건을 불러오거나 변경 사항을 검토하기 위한 파일입니다.

## 5. 과거 자료 직접 조회하기

### 5.1 과거 경락가격 비교

1. **`과거 경락가격 비교 · 직접 조회(키 없이 사용)`**을 펼칩니다. 상단의 `과거 경락가격` 바로가기로도 접근할 수 있습니다.
2. 다음 예시처럼 조회 조건을 입력합니다.
3. **`과거 경락가격 직접 조회`**를 클릭합니다.

| 입력란 | 예시 |
| --- | --- |
| 경매 품종 | `조생귤` |
| 경매 등급 | `특` |
| 경매 크기 | `소` |
| 경매 포장 종류 | `상자` |
| 포장 한 개의 중량 | `5` (kg) |
| 과거 가격 비교 간격 | `7` (일) |
| 시장코드·거래방식 | 선택 입력. 데이터 전체에서 하나로 확정되는 값은 결과에 적용 근거를 표시 |
| 과거 기준일 | 특정 날짜만 보려는 경우 입력. 그 외에는 비워둠 |

이 기능의 `7일`은 **기준 거래일과 정확히 7달력일 뒤 거래일**을 비교한다는 의미입니다. 최근 7일 평균가격 조회와는 다릅니다. 현재 동결 자료에서 만들어 둔 비교 간격은 **3·7·14일**입니다.

결과에는 관측된 가격쌍, 변동률, 자료 품질 경고와 조회 조건이 함께 표시됩니다. 조건이 부족하면 추가로 필요한 품종·등급·포장 등의 후보를 알려줍니다.

**포장중량이 충돌할 때의 처리 방식은 입력 경로에 따라 다릅니다.** 직접 조회 화면에서 포장란에 `10kg 박스`, 중량란에 `5`를 입력하면 입력 오류를 표시합니다. 이때 포장 종류를 `상자` 또는 자료에서 쓰는 포장명으로 정정하고, 중량은 확인된 숫자로 입력한 뒤 **`과거 경락가격 직접 조회`를 다시 눌러야** 합니다. 자연어 대화에서는 10kg·5kg 충돌을 명시적으로 전달한 경우 확인 질문을 거쳐 기존 규격 조건으로 이어갈 수 있습니다.

과거 가격 조회는 출하 손익 계산과 **별도의 조회 결과**로 표시됩니다. 화면을 전환했다면 PDF와 JSON을 받기 전에 현재 표시된 결과가 의도한 분석인지 확인하면 됩니다.

### 5.2 과거 출하통계

1. **`과거 출하통계 직접 조회 · 키 없이 사용`**을 펼칩니다.
2. `출하 통계의 품종`, `조회 월`, `시작 연도`, `마지막 연도`를 선택합니다.
3. **`과거 출하량 조회`**를 누릅니다.

예를 들어 `노지온주`·`11월`·`2018~2024년`을 선택하면 해당 기간의 **신고 출하량(톤)**을 연도별로 확인할 수 있습니다. 자료의 종료일인 2025년 9월처럼 한 달이 완전히 관측되지 않은 경우에는 부분월 정보가 함께 표시됩니다.

### 5.3 자료를 잘 모를 때: 탐색 기능

**`확보 자료 탐색·선택 · 키 없이 사용`**에서 자료 종류를 `경매 거래규격` 또는 `과거 출하 품종·연월`로 고릅니다. 필요한 필터를 선택한 뒤 `실제 자료 후보 탐색`을 누르고, 조회할 후보를 골라 **`선택 후보의 관측자료 조회`**를 실행합니다.

이 기능은 데이터를 처음 접하는 팀원이 **실제 CSV에 어떤 품종·규격 조합이 존재하는지** 확인할 때 유용합니다.

## 6. 자연어 대화와 추가 분석

### 6.1 자연어 대화

`OPENAI_API_KEY`가 설정되면 상단의 **`대화로 조건 확인`** 영역에서 질문할 수 있습니다. 예를 들면 다음과 같습니다.

- `감귤 3톤을 지금 팔지 7일 보관할지 비교하고 싶어요. 현재 가격은 3,000원/kg이고, 하루 보관비는 2만 원이에요.`
- `보관기간 전체 감모율을 2%로 보면 최소 얼마를 받아야 하나요?`
- `조생귤 특·소·상자 5kg의 과거 7일 간격 경락가격을 비교해 주세요.`
- `앞에서 조회한 가격 비교 간격만 14일로 바꿔 주세요.`

모델은 질문을 해석하고 허용된 Python 도구를 선택합니다. 계산 결과는 Python 함수에서 산출되며, 변경한 조건은 `현재 조건 카드`에도 반영됩니다. 채팅에 직접 입력한 문장과 일반 비교조건은 모델 API 요청의 입력으로 사용됩니다.

조회 조건이 불완전하면 추가 질문이 나올 수 있습니다. 대화로 입력한 뒤에도 **현재 조건 카드와 결과에 표시된 단위**를 확인하세요.

### 6.2 가정 범위 비교

**`내 가정 범위로 비교하기`**에서 보관 대안을 선택하고 감모율·미래 단가를 쉼표로 구분해 입력할 수 있습니다.

예: 감모율 `2,4,6` / 미래 단가 `3100,3300,3500`

**`가정 범위 비교`**를 누르면 최대 7×7개 조합에 대해 필요 판매단가와 가정 판매금액을 비교합니다. **`판단이 바뀌는 조건 설명`**은 같은 가정 범위에서 금액 비교가 어떻게 달라지는지 보여줍니다.

### 6.3 제안가격으로 허용 조건 역산

**`제안가격에서 허용 감모·보관비 확인`**에서는 예를 들어 제안가격이 3,300원/kg일 때 다음 중 하나를 계산합니다.

- 현재 비교금액을 유지하는 **기간 전체 감모율 상한**
- 감모율을 고정했을 때의 **전체 물량 하루 보관비 상한**

보관 대안과 제안 단가를 입력한 뒤 `제안 단가의 허용 조건 계산`을 클릭합니다. 하나의 변수를 계산할 때 나머지 조건은 유지됩니다.

### 6.4 자료와 조건을 함께 보고 싶을 때

**`자료와 조건을 함께 검토하기`**에서는 현재 비교조건, 선택한 과거 출하자료, 선택적인 경매 참고가격과 사용자 가정을 한 결과로 정리합니다. 품종·연도·월, 필요한 경매규격을 직접 선택하고 `출하 검토 브리핑 만들기`를 사용합니다.

## 7. 비교 JSON 저장·확인·복원

비교 JSON은 현재 조건, 조건 변경 이력, 최근 결과, 자료 버전 등의 정보를 담습니다. 형식 버전은 **v2**이며 기존 **v1·v2** 파일을 읽을 수 있습니다.

### 7.1 저장

사이드바 **`비교 건 저장·불러오기`**에서 `저장할 비교 이름`을 입력하고 `비교 JSON 내려받기`를 누릅니다. 저장 버튼은 화면의 직접 조회·비교가 완료된 다음 현재 결과를 기준으로 생성됩니다.

### 7.2 저장한 비교를 확인하거나 복원

1. 같은 영역의 **`저장한 비교 JSON`**에 파일을 올립니다.
2. **`비교 파일 확인`**을 누릅니다.
3. 이름·저장 시각·자료 버전 변경 여부·보관된 결과 수를 확인합니다.
4. 목적에 따라 다음 중 하나를 선택합니다.

| 버튼 | 동작 |
| --- | --- |
| `현재 조건과 변경 사항 검토 · 복원하지 않음` | 현재 조건과 저장된 조건을 비교하고 변경 내용을 확인 |
| `확인한 조건 복원 · 현재 기준 재계산` | 저장된 **조건**을 현재 작업공간에 적용하고 현재 자료 기준으로 새로 계산 |

복원 시 기존 대화는 초기화되며, 파일에 들어 있던 이전 결과는 **당시 기록**으로 남습니다. 복원한 조건에 대한 현재 결과는 다시 계산한 값을 사용합니다.

> 서로 다른 PC에서 같은 자료를 사용해도 현재의 `data_revision()`에는 로컬 데이터 경로가 포함되어 있어 **자료 버전 변경으로 표시될 수 있습니다.** 운영자가 실제 파일 내용·해시와 활성 자료를 확인해야 하는 개선 과제로 관리합니다.

## 8. 출하 후 실제 기록·정산 검산

화면의 **`실제 출하 기록·정산 검산 · 개인 확장`**은 출하 전 비교를 기준으로 출하 후 입력값을 기록하고 정산 내역을 검산하는 기능입니다. 기본 손익 비교와는 별도의 기록으로 관리됩니다.

### 8.1 기록 만들기

1. 먼저 출하 전 비교조건을 완성하고 계산합니다.
2. 실제로 선택한 대안을 `즉시 출하` 또는 `보관 대안` 중에서 선택합니다.
3. **`현재 비교와 출하 기록 연결`**을 누릅니다. 이때 비교조건의 기준 사본이 보존됩니다.
4. 출하일·출하중량·판매중량·정산서 매출·지급액·입금액 중 확인한 값을 입력합니다.
5. 판매 내역과 공제·별도 비용을 필요한 만큼 입력하고 **`정산 입력 확인·저장`**을 누릅니다.

저장 후에는 입력 금액을 토대로 계산한 검산 결과와 **`정산 근거 보기 · 입력과 계산`**이 표시됩니다. 모르는 금액은 빈칸으로 두고 실제 무료 또는 0원으로 확인한 경우에만 0을 입력합니다.

### 8.2 저장·이동·삭제

- **`개인 출하·정산 JSON 내려받기`**: 기록·이력·검산값을 보관합니다.
- **`정산 PDF 준비` → `개인 정산 PDF 내려받기`**: 확인한 정산 보고서를 PDF로 받습니다.
- **`개인 출하·정산 JSON 가져오기 · 현재 기록 대체`**: 파일을 선택하고 대체 확인 후 복원합니다.
- **`출하 기록 삭제`**: 별도 확인 후 현재 세션의 출하 기록을 비웁니다.

비교 JSON과 개인 정산 JSON은 서로 다른 형식입니다. 개인 정산 파일에는 입력한 금액이 포함되므로 팀 공유·발표에는 가상 예시를 사용하는 편이 안전합니다. 개인 기록은 세션에서 관리되므로 **작업을 종료하기 전에 JSON을 내려받아 보관**하세요.

## 9. 운영자: 데이터와 실행 환경 관리

### 9.1 어떤 자료가 준비돼 있나요?

| 종류 | 현재 동결 데이터 | 운영상 의미 |
| --- | --- | --- |
| 경매가격 | 2026-10-01~2026-11-03, 가락시장 수집·정제본 | 직접 경매 참고 조회와 과거 가격쌍의 기준 원천 |
| 과거 가격쌍 | 동일 거래규격의 3·7·14일 비교 | 기준 원천과 일치하는 버전에서 조회 |
| 제주 출하통계 #855 | 2018-01-01~2025-09-17 | 과거 품종·연월별 신고 출하량(톤) |

앱 사이드바의 `실행과 자료`에서 **현재 선택한 경매 스냅샷과 관측기간**을 확인할 수 있습니다. 새 PC의 Git 동결 자료와 운영자의 별도 수집 스냅샷은 관측 범위가 다를 수 있습니다.

### 9.2 경매 원본 CSV를 추가하는 화면 절차

1. 사이드바 **`자료 관리자 · 경매 CSV 추가`**를 엽니다.
2. 기존 배포 원본과 같은 컬럼을 갖는 경매 CSV(UTF-8 또는 CP949, 최대 20MiB)를 선택합니다.
3. **`CSV 검사 · 변경 내용 미리보기`**를 누릅니다.
4. 유효/제외 거래 수, 제외 사유, 기존 마지막 관측일과 적용 후 관측일을 확인합니다.
5. 자료가 적합하면 **`확인한 자료 적용 · 대화 초기화`**를 누릅니다.

검사 단계에서는 실제 활성 자료가 유지됩니다. 적용 시에는 검증된 새 스냅샷을 `artifacts/data-refresh/`에 보관하고 `artifacts/market-active.json`이 선택 버전을 가리키도록 갱신합니다. 이전 대화가 초기화되고 공유 비교조건은 유지됩니다. 경매가격은 **기존 자료보다 최신인 유효 관측**이 있는 파일만 적용할 수 있습니다.

### 9.3 과거 가격쌍 조회와 CSV 갱신의 관계 — 운영 시 중요

현재 경매 CSV 갱신 기능은 **새 경매가격 스냅샷의 생성·선택**까지 처리합니다. 반면 `price_comparisons.csv`와 `price_comparison_availability.csv`는 기존 동결 가격 원천에서 만든 별도 파일입니다.

새 스냅샷을 선택하면 `get_price_history`는 선택한 경매가격과 과거 가격쌍의 해시가 일치하는지 검사합니다. 최신 경매가격이 적용됐지만 가격쌍이 이전 버전이라면 `VERSION_MISMATCH` 등 **자료 검증 실패**가 나올 수 있습니다. 이때는 먼저 사이드바에서 활성 스냅샷과 자료 범위를 확인하세요. 과거 가격쌍까지 함께 갱신·검증하는 운영 절차는 후속 개발 항목입니다.

일반적인 현재 조건 손익 계산과 자료 직접 조회는 서로 다른 기능이므로, 어떤 기능에서 오류가 나는지 구분해 기록하는 것이 중요합니다.

### 9.4 재현 점검 명령

프로젝트 루트에서 실행합니다.

```bat
.\.venv\Scripts\python.exe -m unittest discover -s tests
.\.venv\Scripts\python.exe -m unittest discover -s evals -p "test_*.py"
.\.venv\Scripts\python.exe -m scripts.evaluate_integrated_agent --validate
```

위 명령은 자동 테스트와 평가셋 형식을 확인하는 **무과금 검증 경로**입니다. 전체 인수 점검은 다음 명령으로 수행합니다.

```bat
.\.venv\Scripts\python.exe -m scripts.verify_integration_handoff --full --require-clean
```

**중요:** 최종 인수 점검기는 로컬 `artifacts/integration-e2e/`에 저장된 **실제 모델 전체 평가 증빙의 소스 해시**까지 확인합니다. 새로운 Git clone에는 해당 로컬 증빙이 없을 수 있고, 현재 `6517565`의 코드는 과거 평가 커밋 `3aeaf25` 이후 변경됐습니다. 따라서 무과금 테스트가 통과하더라도 기존 평가 증빙만으로 최종 인수 `PASS`를 기대해서는 안 됩니다. 해당 코드에 맞춘 실제 모델 재평가가 필요합니다. 상세 재평가 절차는 05번 테스트 및 평가 문서에서 다룹니다.

### 9.5 운영 시 파일과 정보 관리

| 대상 | 위치·취급 |
| --- | --- |
| 키 설정 | 프로젝트 루트 `.env`; Git 추적 대상에서 제외 |
| Python 설치 패키지 | `.venv/`; 설치 스크립트가 관리 |
| 활성 경매 스냅샷 | `artifacts/data-refresh/`, `artifacts/market-active.json`; 로컬 버전 기록 |
| 검증 로그 | `artifacts/integration-handoff/`, `artifacts/integration-e2e/`; 로컬 실행 증빙 |
| 사용자 저장 비교 | 사용자가 내려받는 `감귤_비교기록.json` |
| 개인 출하·정산 기록 | 사용자가 내려받는 `감귤_개인출하정산.json` |

현재 앱은 로컬 `127.0.0.1`에 바인딩됩니다. 운영자가 다른 PC로 옮길 때는 저장한 JSON·자료 스냅샷·필요한 실행 설정을 구분해 이전하세요. `.env`와 개인 정산 파일은 공개 저장소나 팀 공용 제출 패키지에 포함되지 않도록 확인합니다.

## 10. 문제 해결

| 상황 | 확인할 사항 | 해결 방법 |
| --- | --- | --- |
| `setup-center.cmd`가 Python 오류로 종료됨 | Python 3.13 x64, `py` launcher | `py -3.13 --version`을 확인하고 설치 상태 점검 |
| 실행했는데 브라우저가 열리지 않음 | Streamlit 프로세스·터미널 주소 | CMD에 출력된 `http://127.0.0.1:포트번호`를 브라우저에 입력 |
| AI 대화 입력창이 비활성화됨 | API 키 설정·조건 카드 편집 상태 | `.env` 확인 후 새로고침. 카드 수정 중이면 `입력 조건 비교` 또는 편집 취소 |
| 계산 결과에 `NEEDS_INPUT` 표시 | 누락된 물량·가격 기준·감모·비용 등 | 화면에 표시된 미확인 항목만 채우고 다시 계산 |
| 감모율을 입력했는데 재확인을 요청함 | 보관기간 변경 여부 | 변경된 기간 전체에 대한 감모율을 새로 확인 |
| 과거 경락가격에서 데이터 오류 | 새 CSV 스냅샷과 가격쌍의 버전 | 사이드바 자료 버전을 확인하고 원천/가격쌍 일치 여부 점검 |
| 최신 가격 조회는 되지만 과거 가격쌍은 조회 실패 | 각각 사용하는 데이터 경로가 다름 | 9.3절의 버전 검사 절차를 확인 |
| CSV 업로드가 거부됨 | 원본 컬럼·인코딩·크기·관측일 | 경매 원본 36개 컬럼, UTF-8/CP949, 20MiB 이하, 더 최신인 유효 관측 확인 |
| PDF 생성 오류 | `reportlab`, 글꼴·파일 읽기 권한 | 설치 스크립트와 `assets/fonts/` 구성 확인 후 재시도 |
| JSON 복원에서 자료 변경 표시 | 내용 변경 또는 PC별 데이터 경로 차이 | 현재 자료의 해시·버전 확인 후 현재 기준으로 재계산 |
| 기존 결과가 숨겨짐 | 카드 미저장 수정·자료 변경·조회조건 수정 | 수정 내용을 적용 또는 취소하고 다시 조회 |
| 전체 인수 점검 `FAIL` | 평가 증빙 유무·소스 해시·테스트 상태 | `summary.json`의 `evidence`·`data`·`tests`를 나누어 확인 |

- [ ] API 키 없이 **가상 예시 → 조건 수정 → PDF/JSON 저장** 흐름을 확인했습니다.
- [ ] 과거 경락가격 및 출하량 직접 조회를 확인했습니다.
- [ ] 개인 정보가 담긴 JSON과 공개 시연용 가상 데이터를 구분했습니다.
- [ ] 현재 활성 경매 스냅샷과 과거 가격쌍의 원천 버전을 확인했습니다.
- [ ] 검증 결과에는 **실행한 커밋**과 **실제 모델 호출 여부**를 함께 기록했습니다.
