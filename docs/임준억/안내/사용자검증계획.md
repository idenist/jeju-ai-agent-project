# 사용자 과제와 농가 실용성 검증

현재 기준(2026-11-09): 참여자를 확보할 수 없다는 사용자 확인에 따라 [공개 업무 근거·기존 실제 모델 사례](../검증/2026-11-09_공개사양과업무적합성.md)를 검토했습니다. 실제 사람은 0명이며, 아래 사람 과제는 향후 참여자가 생길 때 사용할 계획입니다. 현재 개발은 조건부 업무 적합성을 근거로 진행합니다.

## 현재 판정

계산·CSV·모델 도구 호출·조건 수정은 자동 검사로 검증할 수 있습니다. **농가 실용성은 아직 사람에게 검증하지 않았습니다.** 팀원·비전문가 과제의 측정도 아직 수행하지 않았습니다. 아래는 실행 가능한 과제와 기록 기준이며 가상의 참여자·시간·만족도를 결과로 만들지 않습니다.

## 농가에게 확인해야 할 핵심

1. **선택권:** 농가가 출하일을 바꿀 수 있는가? 계약·공판장·APC·수거 일정이 정해져 있다면 계산이 맞아도 해당 농가가 행동에 옮기기 어렵습니다.
2. **입력 확보:** 실제 제시가격·수수료·보관비를 알 수 있는가? 감모율은 스스로 정할 수 있는가? 모르는 값을 채우라고 요구하는 부담이 큰지 확인합니다.
3. **비교 기준:** 경락가격과 실수취가격, 포장 단가와 원/kg, 추가 보관비와 이미 포함한 비용을 사용자가 구분할 수 있는가?
4. **실행 조건:** 저장 공간·품질·납기·출하 변경 조건을 실제로 충족할 수 있는가? 경제성 표와 실행 가능성을 별도로 이해하는가?
5. **가치:** 기존 전화 문의·메모·엑셀보다 필요한 시간·누락·이해도에서 이점이 있는가? 어떤 숫자나 근거가 다음 행동에 도움이 되는가?

농가의 판단과 실제 수익 개선을 입증하려면 농가/유통 담당자의 사례가 필요합니다. 비전문가 화면 검사는 질문·표의 이해도에 대한 초기 근거입니다. 대상 농가가 출하 선택권이 없다면 개별 출하 농가·유통 담당자 등 실제 선택 가능한 주체로 대상과 업무 흐름을 재검토합니다.

## 준비된 과제와 독립 정답

모든 숫자는 **실험용 가상 조건**입니다. 실제 농가의 저장 적합성·감모나 미래가격을 뜻하지 않습니다. 물량 3,000kg, 현재 수수료 차감 후 단가 3,000원/kg, 포함비용 수수료만, 기타 고정비는 양쪽 동일 제외, 전체 물량 하루 보관비 20,000원을 기본으로 합니다.

| 과제 | 참가자에게 줄 목표 | 관찰/정답 |
| --- | --- | --- |
| U01 현재 vs 7일 | 7일 전체 감모 2%에서 필요한 최소 단가 찾기 | 판매가능 2,940kg, 보관비 140,000원, 최소 3,109원/kg |
| U02 조건 변경 | 다른 조건을 유지하고 7일 전체 감모를 4%로 변경 | 최소 3,174원/kg. 물량·현재 단가 보존 |
| U03 가정 범위 | 7일 감모 1·2·4%, 미래 단가 3,000·3,300원 가정의 표 비교 | 최소 단가 각각 3,078·3,109·3,174원/kg. 3,300원 가정의 차이 661,000·562,000·364,000원. 원래 조건 미변경 |
| U04 자료 판단 | #855의 2025년 11월 노지온주 자료가 있는지 확인 | 자료 없음. 0톤으로 해석하지 않음. 과거 출하량과 현재 시세를 구분 |

각 과제를 수기/엑셀과 Agent 방식으로 비교합니다. 방법 순서를 참가자 간 바꾸거나 같은 계산 난도의 별도 조건을 사용해 순서·학습 효과를 줄입니다. 안내자가 대신 입력하거나 정답을 알려준 경우도 기록합니다.

## 기록표: 아직 미실시

참가자 식별은 익명 코드로 기록합니다. 농가·유통·팀원·비전문가 역할은 구분하고 동의받은 관찰만 보관합니다.

| 참가자 코드·역할 | 과제·방법·순서 | 완료 시간 | 잘못된 입력/결과 | 질문·도움 횟수 | 이해 0~2점 | 다음 행동 설명 | 상태 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 미기록 | 미기록 | 미측정 | 미측정 | 미측정 | 미측정 | 미기록 | 미실시 |

이해도: 0=핵심 의미 오해, 1=일부 설명 가능, 2=조건·단위·자료 한계까지 설명. 단순히 정답 표를 얻은 것과 이해한 것을 별도로 봅니다. 소수 참가자 결과를 일반 농가 전체에 대한 통계로 해석하지 않습니다.

완료 시간·입력 부담이 기존 방법보다 나빠지거나 핵심 값을 확보할 수 없다면 기능 추가 전에 질문 방식·대상 업무를 재설계합니다. 실제 농가 사례 전에는 farmer_usability_verified를 false로 유지합니다.
