# 개인 도구와 상태 계약

공통 결과는 `status`와 필요한 `input`, `source`, `warnings`를 포함합니다. 상태는 OK, NEEDS_INPUT, NO_DATA, INVALID_INPUT, DATA_ERROR입니다. 모델이 생성한 숫자 문장을 화면·보고서 수치로 사용하지 않습니다.

## 제주 출하 조회

`agents.juneok.evidence.get_historical_shipment_context(args)`

입력: shipment_variety, target_month(1~12), start_year와 end_year(선택).

출력: 실제 series(연도·톤·관측일수·경고), years_covered, 부분월을 제외한 min/max/median, 출처·관측범위. 2025년 11월 등 관측하지 않은 기간은 NO_DATA입니다. 시장의 조생귤을 출하의 노지온주로 자동 변환하지 않습니다.

## 시장 참고가격

`agents.juneok.evidence.get_market_evidence(args)`

입력: market_code, variety, grade, size, package, package_kg, as_of(선택 ISO 날짜).

출력: 동일 거래조건의 실제 관측일, 총금액/총kg로 재계산한 원/kg, 거래 건수·원천 품질 경고·자료 범위. 기준일이 확보기간 밖이면 NO_DATA입니다. 기간 안에서 이전 관측을 사용한 경우 실제 관측일과 경고를 표시합니다.

## 대안 계산

`agents.juneok.comparison.compare_shipment_options(scenario)`

공통 입력: quantity_kg, current_price_per_kg, price_basis, current_fee_percent, cost_policy, included_costs, current_costs, storage_available, shipping_flexible, options.

- price_basis: commission_net은 수수료 차감 후 단가, gross는 차감 전 단가입니다. net에서 수수료를 다시 차감하지 않습니다.
- cost_policy: equal_excluded는 사용자가 보관비 외 고정비가 동일하다고 확인해 제외한 경우입니다. itemized는 항목별 비용을 입력한 경우입니다.
- included_costs: 단가에 이미 포함된 비용을 표시합니다. commission, sorting, packaging, transport, storage, other.
- current_costs 및 대안 costs: category와 amount_krw 목록. 빈 목록은 별도 차감비용 없음을 확인한 값이고 null은 모름입니다. commission은 비율 필드로만 처리합니다.
- options는 1~3개. id, delay_days, loss_percent(기간 전체), daily_storage_cost, fee_percent, future_price_per_kg(선택), costs, loss_confirmed_for_period.

출력: 현재 비교금액, 대안별 판매가능kg·보관비·비용·손익분기·원 단위 최소단가. 미래 단가는 사용자가 제공한 경우에만 해당 가정의 비교금액과 차액을 계산합니다. recommended_option은 생성하지 않습니다.

실행 가능성의 CONFIRMED_BY_USER는 사용자의 확인을 뜻하며 농학적 적합성 검증이 아닙니다. 출하 변경 또는 저장 불가 입력은 CONFLICT, 미확인은 UNCONFIRMED입니다.

## 조건 변경

`ScenarioStore.update(patch, expected_version, clear_fields=None)`은 버전이 맞고 부분 입력이 유효할 때만 원자적으로 반영합니다. null patch 필드는 기존값을 유지합니다. 명시적으로 모름으로 철회할 필드는 clear_fields에 넣습니다. 같은 필드를 동시에 갱신·초기화하면 거부합니다. 대안은 전체 목록을 교체합니다.

기간 변경 시 새 기간 감모를 명시 확인하지 않았다면 감모를 null로 되돌립니다. loss_confirmed_for_period는 해당 변경에만 쓰고 저장 후 false로 소비하므로 과거의 확인을 새 기간에 재사용하지 않습니다.

CLI·화면·보고서는 reporting.py의 같은 결과 렌더러를 사용합니다. 실제 도구 이름과 입력·오류 상태는 자연어 하네스 없이 다른 팀 Agent에서 재사용할 수 있습니다.

모델용 모든 도구는 `finish_turn: boolean`을 받습니다. 중간 단계는 false, 이번 요청의 조건 반영·조회가 끝났으면 true입니다. 조건 저장을 마치면 하네스가 최신 조건을 Python으로 비교하거나 필요한 항목을 안내합니다. 입력·데이터 오류는 완료 신호가 있어도 복구 기회를 유지합니다. 직접 Python 호출에서는 생략 가능합니다.

snapshot의 provenance는 변경된 값의 대화 턴 ID·버전·철회·감모 해제를 추적합니다. 진술의 사실성이나 농학적 타당성을 보증하지 않습니다. `presentation.select_results()`가 고른 최신 결과 집합을 대화와 다운로드가 공유하고, 원시 tool_results는 진단·평가용으로 보존합니다.

모델이 계산 후 조건을 변경하고 재계산을 생략하면 Python이 최신 버전으로 다시 계산하고 이전 버전 금액을 최종 표시에서 제외합니다. 전체 호출 이력은 진단용으로 유지합니다.

용어·자료 해석 질문은 explain_term의 사전 정의된 설명을 사용합니다. 가격 기준, 감모, 비용 정책, 자료 범위, 예측 한계를 설명하며 무관한 물량 입력을 요구하지 않습니다.

## 민감도·CSV 버전

`compare_sensitivity(expected_version, option_id, loss_values, price_values)`는 현재 조건에서 하나의 보관 대안에 사용자가 지정한 감모·미래 단가 목록만 대입합니다. 목록별 최대 7개, 최대 49조합입니다. 미래 단가 null은 손익분기만, 감모 목록 null은 NEEDS_INPUT입니다. 원래 state는 변경하지 않습니다. 감모 목록으로 기간별 감모를 자동 추정하지 않습니다.

`scripts.refresh_juneok_market`의 수집·검증·선택은 개발/운영자 작업입니다. Agent는 `data_refresh.resolve_market_root()`로 선택된 로컬 CSV를 읽습니다. 선택 자료의 해시가 다르면 DATA_ERROR이며 경매 API를 자동 호출하지 않습니다. 공통 파일을 덮어쓰지 않고 artifacts/data-refresh에 별도 보관합니다. 센터 패키지에는 선택 CSV와 명세를 명시적으로 포함합니다.

## 기여와 원본 보존

개인 구현은 공통 main 28e8af97의 데이터와 기존 팀의 명세·검산 사례를 참고해 작성했습니다. 다른 개인 브랜치의 Agent 소스 전체를 복제하지 않았습니다. 3톤 기본 산술은 승혁 브랜치 305eb580의 검산 사례와 독립 검산하여 회귀 기준으로 삼았습니다. 차등 수수료·항목별 비용·원자 상태·새 하네스·데이터 어댑터는 개인 구현입니다.

원본 CSV와 공통 수집·전처리는 수정하지 않았습니다. 과거 가격쌍 분석의 재사용은 정현 브랜치 2197cc5f를 후속 연결할 때 출처와 변경 범위를 추가 기록합니다.

## 대화·조건 카드·보고서의 공유 상태

app.py의 SharedWorkspace는 AgentSession.store 한 개를 사용합니다. 카드 초안은 별도의 확정 시나리오가 아니며 기준 버전과 대안 ID를 유지한 채 ScenarioStore.update(expected_version, clear_fields)로 적용합니다. 빈칸 철회는 clear_fields, 대안 내부 null은 전체 목록 교체에서 명시 철회입니다. 저장된 감모 값의 일회성 확인 플래그가 소모됐다는 이유로 감모 자체를 지우지 않습니다.

카드 왕복 시 숫자 표현과 비용 배열 순서가 의미상 같으면 이전 값·순서·provenance를 보존합니다. 카드 수정의 origin_turn_id는 None으로 직접 입력을 구분합니다. 기간 변경 시 감모 재확인은 기존 계약을 따릅니다.

작업 시작 시 자료 토큰을 고정하며 조건 버전·자료 토큰이 현재와 다르면 내보내지 않습니다. 자료 교체는 대화 근거/결과를 무효화하고 조건은 보존합니다. API 실패 후 부분 결과를 내보낼 때 미완료 상태도 함께 포함합니다. Markdown 미리보기와 PDF는 같은 entries를 사용하고 PDF 생성은 수치 재계산이나 모델 호출을 수행하지 않습니다.
