# 운영자 인수 매뉴얼

기준일 2026-11-09 KST. 이 설치본의 로컬 운영 안내이며 실제 센터 장비에서 실행했다는 기록은 아닙니다. 일반 사용 순서는 [사용자 매뉴얼](사용자매뉴얼.md)에 있습니다.

## 설치·실행

1. 인수 ZIP을 쓰기 가능한 별도 폴더에 풉니다. 기존 운영 폴더 위에 덮어쓰지 말고 검토용 폴더에서 확인합니다.
2. Python 3.13 x64와 Python launcher를 준비하고 setup-center.cmd를 실행합니다. 이 스크립트는 .venv 생성·lock 설치·.env가 없을 때만 예시 복사를 수행합니다. 최초 설치에는 패키지 저장소 접근이 필요합니다.
3. run-juneok.cmd로 실행하고 터미널에 표시된 localhost 주소를 엽니다. 파일·글꼴과 PDF를 쓸 수 있는 권한이 필요합니다. 실행 서버는 127.0.0.1에 바인딩합니다.

수동 설치 명령은 제품을 푼 폴더 안에서 실행합니다.

```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-juneok.lock
```

.env가 없을 때만 .env.example을 복사하세요. 기존 키 파일을 덮어쓰지 않습니다. 설치 후 다음 명령은 키 값을 출력하지 않습니다.

```powershell
.\.venv\Scripts\python.exe -m pip check
.\.venv\Scripts\python.exe -m agents.juneok.cli --check
.\.venv\Scripts\python.exe -m scripts.doctor_juneok
.\.venv\Scripts\python.exe -X utf8 -m scripts.prepare_juneok_handoff_demo
```

## 키·모델·통신

| 항목 | 필요한 때 | 안내 |
| --- | --- | --- |
| OPENAI_API_KEY | 자연어 대화 | 제품 루트 .env에 직접 입력. 채팅·문서·영상·ZIP에 넣지 않기 |
| OPENAI_MODEL | 자연어 대화 | 배포 .env.example과 기존 검증 모델은 gpt-6-luna. 계정 접근권한 확인 |
| DATA_GO_KR_KEY | 운영자의 선택적 사전 경매수집 | 카드·CSV 조회·PDF 실행에는 불필요 |
| 외부 HTTPS | 모델 대화/선택적 수집 | 모델 호출은 api.openai.com. 데이터 수집은 apis.data.go.kr의 명세 주소 |

Settings 코드와 배포 예시의 기본 모델은 모두 gpt-6-luna입니다. OPENAI_MODEL이 없거나 비어 있으면 이 기본값을 사용하고 명시한 다른 모델은 유지합니다. OS 환경변수가 제품 .env보다 우선합니다. UI의 키 설정 표시는 실제 인증·모델 접근·이용한도 성공을 뜻하지 않습니다. 실제 호출 성공 표시는 해당 실행 결과로 확인합니다.

모델 또는 키를 바꾼 뒤 설정 상태를 새로 확인하거나 서버를 재실행합니다. 서버에 남은 OS 변수 우선순위도 운영자가 확인하되 키 전체를 로그로 출력하지 않습니다.

## 폴더·데이터·글꼴

- data/raw, data/processed, data/reports: 공통 배포 자료. 직접 덮어쓰지 않습니다.
- data/metadata/juneok_manifest.json: 공통 스냅샷 출처·파일 해시.
- artifacts/data-refresh와 artifacts/market-active.json: 검증한 별도 가격 버전과 선택 포인터. 수동 편집하지 않습니다.
- assets/fonts: TTF 2개·OFL.txt·SOURCE.json. PDF 생성에 필요하므로 함께 배포합니다.
- requirements-juneok.lock: 설치 버전 고정. PDF는 reportlab/pypdf를 사용하며 OS 글꼴이나 생성 시 인터넷은 필요하지 않습니다.

#855 출하자료는 2018-01-01~2025-09-17입니다. 가격의 활성 스냅샷은 market-through-20261108이며 실제 마지막 유효 관측은 2026-11-06입니다. 조회한 날짜와 관측한 날짜를 구분하세요. 실제 다른 센터 CSV가 같은 명세라는 검증은 없습니다.

## 경매 CSV 갱신

사이드바 `자료 관리자 · 경매 CSV 추가`에서 배포 원본과 같은 36컬럼 원본 CSV를 선택합니다. UTF-8/CP949·최대 20MiB를 지원합니다. 가공가격표·#855 교체·임의 명세는 지원하지 않습니다.

검사→유효/제외 내역·기간·버전 미리보기→명시적 적용 순서입니다. 기존 원본에 추가하며 완전히 동일한 거래만 중복 제외합니다. 같은 날짜 수정 거래를 대체하는 기능은 아닙니다. 기존보다 최신 유효 관측이 없으면 적용하지 않습니다.

적용 전에는 자료를 바꾸지 않고 오류·변조·검사 뒤 다른 선택이 생기면 거부합니다. 적용하면 비교 조건은 보존하고 구자료 대화·내보내기를 비웁니다. 설치본 전체에 공유되므로 여러 관리자 동시 적용을 운영 절차로 허용하지 마세요. 문제가 있으면 보관한 정상 ZIP을 새 폴더에 풀어 비교한 뒤 새로 적용합니다. 포인터를 임의로 고쳐 과거 자료를 최신이라고 표시하지 않습니다.

## 검증과 인수 기록

새 개발환경의 회귀는 scripts.verify_juneok, 공개 사양 검사는 scripts.verify_juneok_center_spec입니다. Git이 없는 배포본 인수는 doctor와 시연 준비 명령을 우선 사용합니다. verify_juneok의 Git 제외/공통 원본 검사까지 독립 ZIP에서 그대로 요구하지 않습니다.

유료 모델 평가는 scripts.evaluate_juneok --live와 scripts.verify_juneok_shared_live입니다. 자동 재생은 모델을 호출하지 않습니다. 실행할 경우 비용·계정 권한을 확인하고 원시 로그는 키 없이 보관합니다.

인수 확인자는 날짜·환경·키 없는 과업·모델 과업·자료 버전·결과·문제를 별도로 기록합니다. 공개 사양 적합성과 실제 센터 실행, 팀 검수와 농가 검수를 구분합니다.

## 확장 기능 운영

브리핑·판단 조건 설명·JSON 저장/복원은 키 없는 직접 사용을 지원합니다. 자연어 호출은 기존 모델 키가 필요합니다. 로컬 다운로드 파일의 보관·폐기는 사용자가 관리하며 계정·서버 DB 저장 기능은 없습니다. JSON의 해시는 작성자 인증이 아니므로 가져온 조건을 확인합니다.

원격 체크포인트에는 artifacts의 추가 가격 스냅샷이 없으므로 새 clone과 동결 ZIP의 관측범위가 다를 수 있습니다. 화면의 실제 자료 범위를 기준으로 안내합니다. 확장 시연 준비는 scripts.prepare_juneok_review_demo, 실제 모델 연결 검증은 scripts.verify_juneok_extensions_live를 사용합니다.

## 하네스 운영 변경 · 2026-11-09

`agents/juneok/harness.py`의 ExecutionPolicy가 기본 실행/입력 예산을, `task_context.py`가 이번 비교 건의 구조화 맥락을 담당합니다. SDK 자동 재시도는 0회로 바꿨습니다. 반복·예산 초과를 API 키 오류로 안내하지 마세요. 원문 예외·키를 화면에 출력하지 않고 반환의 termination/metrics로 사유와 단계를 확인합니다.

데이터 버전 변경 때 이전 맥락/대화/결과를 비우고 사용자 조건은 유지합니다. JSON v2는 v1 읽기 호환이며 반대 방향은 보장하지 않습니다. 이전 결과를 현재 관측으로 재사용하지 않습니다. 과업 맥락은 현재 세션/명시적 저장 파일에 한정하며 계정/사용자 장기 프로필 DB가 없습니다.

전체 회귀는 `python -m scripts.verify_juneok`, 유료 모델 평가는 `python -m scripts.evaluate_juneok --live`, 한국어 맥락 반복은 `python -m scripts.verify_juneok_task_harness_live --repeat 3`입니다. 오류 주입은 회귀에서 재현하므로 실제 장애를 발생시킬 필요가 없습니다. [검증 기록](../검증/2026-11-09_하네스실패와과업맥락.md)과 패키지 latest.json을 함께 확인합니다.

## 개인 출하·정산 기록 운영

출하·정산 기록은 세션 메모리와 사용자의 명시적 로컬 JSON/PDF 내려받기만 사용합니다. 카드 검산은 모델/데이터 키가 필요하지 않습니다. 자연어 검산은 같은 로컬 결과를 표시하고 모델 이력에는 금액 없는 처리 상태만 남깁니다. 직접 입력한 채팅과 기존 비교 조건은 모델 입력이며 카드의 상세 정산값/근거 제외와 구분합니다. 원문/OCR·기관/은행 연동·자동 실제값 저장·서버 DB는 없습니다. 개인 금융 기록을 제출/발표 자료나 샘플 데이터로 옮기지 마세요. 기본 빌더는 알려진 `jeju-shipment-record` JSON 형식을 발견하면 중단하며 범용 개인정보 탐지기는 아닙니다.

검사: `python -m scripts.verify_juneok`, 가상 PDF/JSON 재생성: `python -m scripts.prepare_juneok_settlement_demo`, 유료 모델 과업: `python -m scripts.verify_juneok_settlement_live --repeat 3`. `artifacts/settlement-review/implementation`의 JSON도 개인 기록과 같은 형식이라 패키지에는 넣지 않습니다. C의 당시 가정 대조·자연어 입력 확정은 아직 지원하지 않습니다.
