# 개발계획 최종 자체 검토

검토일: 2026년 11월 9일 KST. 사용자 요청에 따라 3개 독립 검토 에이전트가 6개 역할을 나누어 검토하고 주 담당자가 종합했습니다. 실제 심사위원·팀원·농가·외부 전문가 인터뷰가 아닌 역할 관점 평가입니다.

## 주 담당자 판단

주제와 장기 확장 기록을 유지하고 구현에 착수합니다. 더 많은 아이디어보다 입력·계산·상태·수치 표시의 일관성이 먼저입니다. 사용자 단가 계산과 공공자료 조회는 독립 경로로 구성해 한 자료 조회 실패가 다른 계산을 막지 않게 합니다.

손익분기 단가가 낮다는 이유로 실제 최선 출하일을 추천하지 않습니다. 시장 관측가격과 사용자 제시가격을 구분하고, 과거 출하량은 현재 공급이나 미래 시세의 검증된 설명변수로 사용하지 않습니다.

API 키가 없는 동안 G0·G1과 모의 모델 하네스 검증을 진행할 수 있습니다. 실제 모델 성공은 사용자가 제품 .env에 키를 넣고 실제 실행한 뒤에만 기록합니다. 다른 프로젝트의 키·환경 파일은 읽지 않습니다.

## 수용기준

- #855 실제 값과 자료 부재·부분월이 검증된다.
- 사용자 단가가 있으면 불필요한 시장 규격을 질문하지 않는다.
- 미입력 비용·감모를 임의의 0 또는 범위로 채우지 않는다.
- 단가에 이미 포함된 비용을 다시 차감하지 않는다.
- 기간 변경 시 이전 기간 전체 감모를 조용히 재사용하지 않는다.
- 잘못된 변경·오래된 버전 변경은 기존 상태를 손상하지 않는다.
- 오류 후 재호출이 성공해도 검증된 Python 수치가 유지된다.
- 미래 단가 없는 대안에 수익 순위·최적일 추천을 붙이지 않는다.
- 같은 결과 객체가 CLI·화면·보고서에 사용된다.
- .env가 Git에서 제외되고 제품 외부의 .env를 탐색하지 않는다.

## 검토 한계

농가 실효성·사용성은 실제 사용자 검증이 남아 있습니다. 기존 테스트 80개는 기존 팀 코드의 결과이며 새 개인 Agent 성능과 별도로 집계합니다. API 실호출과 실제 센터 네트워크 접속도 별도 검증 대상입니다.
