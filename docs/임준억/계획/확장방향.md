# 제주 감귤 Agent 확장 방향 기록

기록일: 2026년 11월 9일 KST

사용자가 제시한 두 확장 방향을 보존합니다. 현재 MVP의 필수 기능을 추가하는 결정은 아니며, 이후 제품 방향을 검토할 때 다시 참조합니다.

## 사용자 제안

1. 감귤의 다른 품종, 다른 과일, 다른 농작물도 사용할 수 있는 범용성.
2. 감귤 출하 의사결정을 넘어 감귤의 생애주기를 다루는 방향.

## 현재 의견

단일 작물 지원 자체가 작은 제품을 뜻하지는 않습니다. 실제 사용자 과업을 얼마나 끝까지 지원하는지가 중요합니다. 단순 손익계산만 제공하면 실용성이 제한적일 수 있습니다.

우선 검증할 확장 순서는 감귤의 출하 대안 비교 → 수확 준비·선별·저장·출하·정산의 연결 → 검증된 공통 기능의 다른 작물 적용입니다. 이는 현장 인터뷰로 입증된 우선순위가 아니라 공개 업무자료와 기술 구조를 바탕으로 한 의견입니다.

## 방향 1 여러 품종과 작물

공통으로 재사용할 부분은 대화 상태 관리, 입력·단위 검증, 대안별 수취액 비교, 손익분기 계산, 출처 표시, 보고서입니다.

작물별로 검증할 부분은 품목·품종 코드와 거래규격, 가격자료, 저장 가능 조건, 감모·품질변화, 비용과 가능한 출하 대안입니다. 감귤의 저장조건이나 손실률을 다른 작물에 그대로 적용하지 않습니다.

작물 선택 메뉴만 추가했다고 범용성을 입증한 것으로 표시하지 않습니다. 두 번째 작물의 실제 데이터와 사용 시나리오에서 재사용 범위·추가 변경·테스트 결과를 확인해야 합니다. 두 번째 작물은 관련 자료를 실제 확보한 뒤 선정합니다.

## 방향 2 감귤 생애주기

출하와 인접한 업무 확장과 재배 전체 확장을 구분합니다.

- 인접 업무: 수확 준비, 선별·등급별 물량, 저장 기록, 출하, 실제 정산, 예상과 실제 결과 비교.
- 재배 전체: 전정, 관수, 시비, 병해충, 생육, 수확 판단. 개별 과원·작업·생육 기록과 전문 근거가 추가로 필요합니다.

같은 농가의 수확물·저장·출하·정산 기록을 연결하면 과거 결정을 이어받고 실제 감모·비용을 다음 비교에 활용할 수 있습니다. 반복 사용 가치가 생길 가능성이 있지만 기록 입력 부담과 실제 사용 의향을 검증해야 합니다.

생애주기 확장도 일반 재배지식 질의응답만 늘리는 방식보다 농가 기록과 상황을 연결하는 업무 지원을 우선 검토합니다.

## 현재 설계에 남길 원칙

- 작물·품종 정보와 데이터 소스 설정을 대화·계산 로직과 분리합니다.
- 품종별 거래·출하 분류를 구분하고, 미검증 매핑은 자동 적용하지 않습니다.
- 가격·감모·비용이 관측값, 사용자 입력, 가정 중 무엇인지 기록합니다.
- 조건 변경과 계산 결과를 추적할 수 있도록 시나리오 버전을 둡니다.
- 아직 필요한지 검증하지 않은 범용 플러그인 구조나 대규모 프레임워크를 먼저 만들지 않습니다.
- 현재 MVP는 단일 감귤 물량의 대안 비교에 집중합니다. 다른 작물·부분 출하·생육 관리·실제 거래 실행은 현재 필수 범위에 넣지 않습니다.

## 확장 검토 조건

다음 중 하나가 실제 사용 또는 검증에서 드러나면 확장 우선순위를 다시 판단합니다.

1. 같은 농가가 저장·출하·정산 기록을 이어서 쓰려는 수요가 있다.
2. 다른 작물 사용자에게 같은 출하 비교 과업이 반복되며 필요한 자료를 확보할 수 있다.
3. 현재 제품의 입력 부담이 커 농가 기록 자동 연계가 필요하다.
4. 단순 비교보다 수확·선별·재고 배분이 주요 문제라는 증거가 생긴다.
