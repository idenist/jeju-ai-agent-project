# 대화형 출하 Agent 사용자 여정과 개발 계획

> 2026-11-14 · [통합 브랜치 1707c56](https://github.com/idenist/jeju-ai-agent-project/commit/1707c560d153009e5bd5e53a3134e2c4ec855a7b)와 그 위의 로컬 UI 개선본 기준 · 임준억 담당 범위의 구현 전 계획

농가가 “3일 뒤와 10일 뒤에 팔면 얼마나 차이 날까?”라고 말하면, Agent가 이미 받은 조건을 기억하고 필요한 자료를 찾습니다. 사용자는 판단에 필요한 값만 확인하고, 비교 결과를 읽고, 같은 대화에서 결과를 저장하거나 조건 하나를 바꿀 수 있습니다.

## 첫 화면과 Agent의 역할

첫 화면의 중심은 **출하 고민을 말하는 대화창**으로 잡는다. 입력창 옆에 “지금 팔지 일주일 보관할지 비교”와 “3일 뒤와 10일 뒤 비교” 예시를 둔다. 사용자가 비교 유형이나 도구 이름을 선택해야 하는 부담은 Agent가 맡는다. **직접 입력**과 **예시 결과 보기**는 첫 화면에서도 찾을 수 있게 둔다. 모델 연결이 없을 때는 직접 비교를 주 행동으로 보여준다.

| 대화 시점 | Agent가 실제로 하는 일 | 사용자에게 보여줄 것 |
| --- | --- | --- |
| 요청을 받음 | 이미 받은 물량·날짜·단가를 현재 조건에 반영하고, 오늘과 나중 비교 또는 두 미래 출하일 비교를 선택한다. | “3톤 · 3일 뒤와 10일 뒤”처럼 이해한 조건과 바로 수정할 방법. |
| 가격을 모름 | 사용자가 과거 근거를 요청하면 동일 규격과 날짜 간격으로 자료를 조회한다. 규격이 모호하면 조회 결과에 있는 후보로 확인하고, 자료가 없으면 직접 단가 입력으로 이어간다. | 조회한 자료의 범위, 지금 필요한 질문, 자료 없음의 이유와 다음 행동. |
| 비용을 모름 | 확인된 값은 유지하고, 조회할 수 있는 가격 근거부터 보여준다. 손익에 필요한 비용은 확인할 곳을 알려준다. | “저장고에 전체 물량의 하루 요금을 확인해 주세요”처럼 바로 실행할 수 있는 안내. |
| 비교 가능 | 검증된 계산 도구로 차액과 최소 단가를 계산한다. 조건이 바뀌면 영향받는 값만 확인해 다시 계산한다. | 날짜가 들어간 결론, 사용한 가격의 근거, PDF와 결과 JSON, 현재 결과에 맞는 후속 행동. |

한 문장으로 시작한 뒤 화면에서 숫자를 확인하거나 버튼으로 답할 수 있어야 한다. 예시는 입력 방법을 익히는 보조 수단으로 쓰고, 주요 검증은 정해진 예시 문구를 보지 않은 사용자가 자기 표현으로 요청하는 경우로 잡는다. 사용자가 확정할 값은 거래규격·농가 비용·가정 단가이고, 자료 조회·비교 계산·결과 작성은 도구가 맡는다. Agent의 진행 표시는 실제로 확인된 도구 결과를 바탕으로 제공한다. [Anthropic Agent 설계](https://www.anthropic.com/research/building-effective-agents#agents) · [DAKER 공식 공지](https://daker.ai/public/hackathons/jeju-ai-bigdata-agent-challenge)

## 승혁님 화면 피드백 재점검

| 피드백 | 체크포인트에서 확인한 상태 | 다음 구현의 통과 기준 |
| --- | --- | --- |
| **탭은 필요한 것만 남기기** | 기능을 출하 비교·자료 조회·추가 도구로 모았다. 출하 비교 안에 두 비교 유형의 탭이 있고 대화는 그 아래에 있다. | 첫 화면에서 대화와 시작 예시를 바로 찾는다. 사용자가 비교 유형 탭을 고르는 과정 없이 Agent가 목적에 맞는 도구를 선택한다. 직접 입력은 첫 화면에서, 자료 조회와 운영 기능은 보조 메뉴에서 접근한다. |
| **입력 부담 낮추기** | 감모율·비용을 접어두고, 같은 비용의 재사용과 누락 구역 이동을 지원한다. 두 출하일 비교에서는 비용이 비어 있으면 과거 가격 조회 전에 입력 안내가 나온다. | 농가가 물량·날짜·단가를 한 문장으로 주면 이후 질문과 조건 카드에 반영된다. 과거 가격을 요청하면 조회에 필요한 값부터 확인한다. 이미 알려준 값을 다시 요구하지 않고, 모르는 비용의 확인 방법과 현재 할 수 있는 조회를 보여준다. |
| **보고서 결론이 바로 보이게 하기** | P2 화면과 PDF는 차액과 최소 단가를 첫 부분에 표시한다. 대화에서 PDF를 받으려면 비교 탭으로 이동해야 하며, 요약은 A안·B안으로 표시된다. | 대화 결과와 PDF 첫 부분에 출하일·차액·최소 단가를 표시한다. 사용한 단가의 근거를 열어볼 수 있고 같은 대화에서 PDF·JSON을 저장한다. 최신 화면과 파일의 조건·수치가 일치한다. |

세 항목은 기존 [브라우저 과제](#검증에-사용할-과제)에 적용한다. 첫 진입에서는 메뉴 선택 횟수를, 정보가 부족한 과제에서는 같은 값의 재질문과 자료 조회 도달 여부를, 결과 과제에서는 사용자가 결론을 설명하고 저장할 수 있는지를 확인한다.

## 첫 진입부터 재비교까지

새 Chrome 세션에서 키 없는 로컬 화면을 확인했다. 창 높이 765px에서 첫 탭은 **오늘과 나중**이었고, 대화 입력은 화면 위에서 약 1,129px 지점에 있었다. P2 빈 입력으로 계산했을 때 누락 안내와 비용 입력 이동이 작동했다. **자료 조회**와 **추가 도구**도 실제 탭을 열어 확인했다. 대화 연결·결과 저장·버전 판정은 코드와 기존 검증 기록을 검토했다. 이번 계획 검토에서 실제 모델 평가나 농가 인터뷰를 새로 실행한 것은 아니다.

| 여정 | 현재 확인한 마찰 | 개선안 |
| --- | --- | --- |
| **1. 진입** | 조건 카드와 비교 유형 탭이 먼저 보이고, 대화를 시작하는 곳은 아래에 있다. 키가 없으면 비활성 입력창 아래쪽에서 이유를 접한다. | 첫 화면에서 “언제 팔지 고민되는 상황을 말해 주세요”와 입력창을 보여준다. 시작 예시는 **지금 팔지 보관할지 비교**, **두 출하일 비교** 두 개로 제한한다. 키가 없으면 첫 화면에서 직접 비교나 가상 예시로 시작할 수 있게 한다. |
| **2. 요청 이해** | P2와 오늘·미래 비교는 상태가 다르다. 처음 쓰는 사람에게 이 차이를 탭 이름으로 고르게 한다. | 모델은 표현에서 비교 유형을 선택하고, 화면에는 “3톤 · 3일 뒤와 10일 뒤 비교”처럼 이해한 목적을 보여준다. “다음 주”처럼 계산 날짜가 달라질 표현은 날짜를 확인한다. |
| **3. 확인과 자료 탐색** | P2 비용이나 감모율이 없으면 계산이 멈추고, 과거 거래규격 확인까지 도달하지 못할 수 있다. | 사용자가 과거 가격을 원하면 출하일 간격과 거래규격으로 자료부터 찾는다. 모호한 규격은 데이터에 존재하는 후보를 보여준다. 날짜 간격에 자료가 없거나 같은 규격의 유효 표본이 없으면 이유와 함께 B안 단가 직접 입력으로 이어간다. |
| **4. 모르는 조건 처리** | 감모율·비용 입력 설명은 직접 입력 카드에서만 접할 수 있다. 누락 목록만 받으면 어떤 값부터 확인해야 할지 판단이 필요하다. | 현재 가능한 결과와 다음 확인 항목을 보여준다. 예를 들어 보관비는 “저장고 견적의 전체 물량 하루 요금”으로 묻는다. “몰라요”에는 확인 방법을 보여주고 나머지 조건을 유지한다. 이미 받은 값은 반복해서 묻지 않으며, 사용자는 한 답변에 여러 값을 제공할 수 있다. |
| **5. 결과 이해와 저장** | 대화에서 요약을 봐도 P2 상세와 저장은 다른 탭을 열어야 한다. 과거 가격, 가격 가정, 비교금액의 차이를 사용자가 해석해야 한다. | 대화에서 차액과 B안 최소 단가를 먼저 보여주고, 단가 근거·표본·관측기간은 이어서 펼칠 수 있게 한다. PDF와 결과 JSON을 같은 최신 결과에서 제공한다. |
| **6. 수정과 재방문** | 대화와 P2 조건 카드가 상태를 공유하지만, 과거 대화는 일반 비교 버전으로 판정하는 부분이 있다. P2 결과 JSON과 사이드바의 비교 건 저장은 용도가 다르다. | 현재 P2 버전을 기준으로 최신 결과를 판단하고, 오래된 답변은 당시 결과로 표시한다. **B안만 수정**을 선택하거나 말하면 A안을 유지하고 새 보관기간의 감모율을 확인한다. P2 결과 JSON은 결과 보관용으로 명시한다. |
| **7. 연결·실행 문제** | 대화는 외부 모델 연결이 필요하고, 자료 갱신이나 카드 미저장 상태가 대화에 영향을 준다. | 모델 연결 실패, 입력 수정 중, 자료 버전 변경을 각각 설명하고 가능한 다음 행동을 표시한다. 같은 세션의 확인된 조건을 유지한 채 직접 입력으로 이어가고, 자료 변경으로 무효가 된 결과는 다시 조회하도록 안내한다. |

여정에 따른 가정은 세 가지다. **처음 쓰는 농가**는 빈 입력창의 시작 예시와 숫자 단위가 필요할 수 있다. **비용을 바로 확인하기 어려운 농가**는 어떤 정보가 더 필요한지와 그 전에 확인할 수 있는 가격 근거가 중요하다. **반복 비교하는 농가나 출하 담당자**는 한 가지 변경의 영향과 비교에 쓴 조건·근거를 빠르게 보고 싶을 수 있다. 이 가정은 화면 검토와 아래 과제의 출발점이다.

코드 확인 지점은 [첫 화면과 대화 배치](../../../app.py#L507), [P2 필수값 검사](../../../agents/juneok/future_pair_state.py#L89), [P2 파일 내보내기](../../../agents/juneok/future_pair_ui.py#L213), [비교 건 복원](../../../agents/juneok/workspace.py#L247)이다. 일반 비교와 P2는 각각 상태를 가지므로, 첫 화면을 통합할 때도 유형마다 올바른 조건과 결과를 보여줘야 한다.

| **무엇부터 해야 하는지 알고 싶다** | 첫 화면에는 조건 카드와 비교 버튼이 먼저 보인다. 가상 예시를 누르면 결과가 바로 나오며 `seven_days` 같은 내부 이름이 결과에 표시된다. | **예시로 결과 보기**를 첫 화면에 배치한다. 예시 결과 상단에 가상 값임을 표시하고, **내 조건으로 비교**에서 자기 값으로 시작하게 한다. 대안 이름은 “오늘 출하”, “7일 뒤 출하”처럼 표시한다. |
| **내가 쓰는 단위로 말하고 싶다** | P2 카드에는 A/B, 보관 시작일과 보관일, 원/kg, 수수료 차감 전·후가 보인다. 사용자가 생각하는 출하일과 화면이 요구하는 보관일 사이에 변환이 필요하다. | 대화에서 “다음 화요일과 금요일”, “3톤”, “5kg 상자에 1만 2천 원”을 받고, 날짜와 단위가 확정되면 “3,000kg · 2,400원/kg”처럼 반영값을 보여준다. 상자 중량이나 수수료 포함 여부가 모호하면 해당 값만 확인한다. |
| **보관비나 줄어드는 양을 모른다** | 누락된 비용 입력 구역을 열 수 있고, 저장고 견적을 확인하라는 문구도 보인다. 계산을 누르면 여러 누락값이 한꺼번에 나온다. | 대화에서 “비슷한 기간 보관했을 때 판매할 수 있는 양이 얼마나 줄었나요?”처럼 묻는다. **아직 몰라요**를 선택하면 확인할 곳과 현재 가능한 조회를 안내한다. A/B의 비용이 같다는 답을 받으면 해당 항목을 한 번만 받는다. |
| **어느 날이 유리하고 무엇을 확인할지 알고 싶다** | 3일 대 10일 직접 입력 결과에 차액 241,850원과 최소 단가 2,660원/kg이 먼저 표시된다. 첫 결론은 “B안”으로 표현한다. PDF와 JSON은 표와 근거 아래에 있다. | 첫 줄에 “입력한 조건에서는 10일 뒤 출하의 비교금액이 241,850원 높아요”처럼 날짜와 차액을 함께 보여준다. 바로 아래에 “10일 뒤 kg당 2,660원부터 3일 뒤와 같거나 높아요”와 단가 기준을 표시한다. 실제 출하를 결정하기 전 확인할 보관 가능 여부와 출하처 일정은 짧게 안내하고, 공유용 PDF를 결론 가까이 둔다. |
| **나중 날짜만 바꿔 다시 계산하고 싶다** | B 보관일을 10일에서 17일로 바꾸면 A 단가는 유지되고, B 감모율이 비워지며 이전 다운로드가 사라진다. 화면은 재계산을 안내한다. | 결과에서 **나중 출하일 바꾸기**로 이어가고, 새 기간 때문에 다시 필요한 값과 이유를 즉시 보여준다. 예를 들어 “17일 보관할 때 줄어드는 양을 알려주세요.”라고 묻는다. |

1단계에 가상 예시 진입, 출하일 중심 이름, 결과 옆 PDF를 반영한다. 2단계에서 날짜·단위 확인과 **아직 몰라요** 흐름을 검증한다. 3단계는 결과에서 나중 출하일을 바꾸는 과제로 확인한다. 이후 실제 농가가 참여할 수 있으면 사용 설명 없이 이 과제를 제시하고, 첫 행동을 찾았는지, 예시와 자기 조건을 구별했는지, 결과를 보고 출하 전에 무엇을 확인할지 설명할 수 있는지 관찰한다.

## 단계별 구현 및 완료 기준

### 1. 대화에서 P2 요청부터 저장까지 연결

- `app.py`에서 대화와 두 시작 예시를 출하 비교 첫 화면에 배치한다. 예시는 문장을 보여주거나 채우는 동작으로 시작하고, 사용자가 보낼 내용을 확인할 수 있게 한다. 수동 비교는 키 없는 경로 및 조건을 한꺼번에 고치는 경로로 계속 접근할 수 있게 한다.
- `agents/juneok/future_pair_ui.py`에 있는 P2 결과·다운로드를 대화에서도 재사용한다. 같은 렌더링을 공유하고, 내보낼 결과는 기존 `FuturePairState.current_result()`와 P2 조건 버전으로 확인한다. 이전 대화의 성공 응답에 최신 다운로드가 붙지 않도록 한다.
- 이미 있는 `manual_price_required` 상태를 사용해 자료 없음 안내 옆에서 B안 단가를 바로 제공할 수 있게 한다. 입력은 기존 비교 상태의 수정 경로로 반영한다. 이 단계에서는 현재 P2 도구가 자료 없음까지 도달하는 조건으로 회복 경로를 먼저 검증한다.
- **완료 기준:** 키가 있는 새 세션에서 첫 화면의 대화창이나 시작 예시가 스크롤 없이 보인다. 사용자 표현이 서로 다른 요청으로 실제 모델이 P2를 선택하고, 과거 가격 도구와 계산 도구의 결과를 바탕으로 상세 폼 없이 비교와 PDF·JSON 저장을 마친다. 조회 성공과 자료 없음에 따른 다음 행동이 달라야 한다. 키 없는 세션은 첫 화면에서 직접 비교를 시작해 결과를 얻는다. 새 조건 입력 직후에는 이전 파일을 최신 파일로 받을 수 없다.

2026-11-14 로컬 검토본에 첫 화면의 출하 상담, 시작 예시, 대화 안 결과·파일 저장, 자료 없음 후 단가 입력을 구현했다. Chrome에서 `gpt-6-luna`로 7일 간격의 동일 규격 가격쌍 20개를 사용한 비교와 5일 자료 없음 이후 직접 단가 비교를 실행했다. 직접 단가 2,750원/kg을 넣었을 때 A안 금액이 유지됐고, 차액 261,850원과 최소 단가 2,653원/kg이 화면과 내려받은 PDF·JSON에서 일치했다. 과거 조회의 최소 단가 2,660원/kg과 근거도 파일에서 확인했다.

### 2. 가격 근거를 먼저 확인하고 필요한 값만 묻기

- `agents/juneok/agent.py`, `future_pair_state.py`와 기존 과거 가격 도구의 연결을 점검한다. 두 출하일과 확인 가능한 규격으로 과거 자료 조회를 먼저 진행하고, A안 단가가 있어야 과거 변동을 B안 가격 가정으로 환산한다. 비용·감모율은 손익 비교 시점에 확인한다.
- 동일 규격의 정확한 간격, 원천·자료 버전 검사, 데이터에서 반환한 후보를 재사용한다. 조회 결과, 사용자 단가, 과거 변동으로 만든 가정 단가를 화면에서 읽을 수 있게 표시한다. 현재 조회 결과의 조건이 바뀌면 새 조건으로 다시 확인한다.
- 질문은 다음 행동을 결정하는 값부터 묻고, 한 답변에 들어온 여러 값을 함께 반영한다. “모른다”에 숫자를 채우지 않는다. 비용이 없다고 사용자가 확인하면 0을 기록한다. 가격 근거만 확인된 상태에서는 그 근거와 미확인 항목을 보여준다.
- 자료의 역할을 명시한다. 과거 경락가격은 동일 규격 변동과 가정 단가의 근거로 쓰고, 제주데이터허브 #855 과거 출하통계는 출하량 맥락을 요청한 경우 별도로 조회한다. 출하량 자료를 거래규격과 자동으로 연결하거나 B안 단가의 근거로 표시하지 않는다.
- **완료 기준:** 비용이 비어 있어도 동일 규격 가격 근거를 확인할 수 있다. 규격이 모호한 경우 자료에 있는 후보가 나오고, 자료 없음과 자료 검증 실패는 각각 설명한다. 확인한 값의 재질문과 임의 0 입력은 검증 과제에서 0건이다. 완전한 비교 조건을 받은 뒤에만 최신 손익 결과와 파일을 제공한다.

2026-11-14 로컬 검토본에 과거 가격 먼저 조회하기를 반영했다. Chrome의 별도 세션에서 `gpt-6-luna`로 7일과 5일 간격을 검증했다. 7일은 비용 입력 전 가격쌍 20개와 가정 단가를 확인했고, 5일은 자료 없음 안내에서 2,750원/kg을 직접 입력한 뒤 남은 감모율·보관비를 대화로 보완했다. 두 비교에서 최초 물량·단가·수수료·별도 비용이 유지됐고, 완료한 화면과 PDF·JSON의 수치 및 가격 근거를 대조했다.

### 3. 결과에서 조건 하나를 바꿔 다시 비교

- 대화 결과에 **B안 조건 바꾸기**, **가격 근거 보기**처럼 현재 가능한 행동을 제공한다. 날짜 변경 시 해당 기간의 감모율을 확인한 뒤 비교하고, 출하일 간격이 바뀌면 과거 가격 근거도 새로 조회한다.
- 작은 화면에서는 결론, 필요한 답변, 다운로드 순서로 읽히는지 확인한다. 긴 근거와 실행 진단은 필요할 때 펼친다. 대화에서 나가 수동 편집 후 돌아오는 경로에서도 조건이 보존되는지 확인한다.
- **완료 기준:** 3일 대 10일에서 B만 17일로 바꿀 때 A안 입력과 비교금액이 유지된다. 7일 가격 근거는 14일 근거로 갱신된다. 키보드로 수정과 저장을 완료할 수 있고, 이전 결과는 당시 결과로 식별된다.

2026-11-14 로컬 검토본에 대화 결과에서 나중 출하일을 바꾸는 동작을 반영했다. Chrome에서 `gpt-6-luna`로 3일과 10일을 비교한 뒤, 달력에서 나중 출하일을 12월 1일로 바꿨다. 17일 보관에 대한 감모율만 물었고, 14일 간격 가격쌍 15개를 먼저 표시했다. 감모율 4%를 대화로 답한 뒤 A안 비교금액 7,018,750원과 나중 출하 최소 단가 2,686원/kg을 화면·PDF·JSON에서 확인했다.

각 단계에서 관련 자동 테스트와 실제 Chrome 흐름을 먼저 통과시킨다. 최종 검토에서는 기존 전체 회귀, 기존 실제 모델 평가 12문항과 P2 후속 대화, 새 회복 과제, 직접 다운로드한 PDF·JSON을 현재 코드로 대조한다. 간단한 과제 지시만 받고 비교를 끝낼 수 있는지 처음 보는 사람에게 확인할 때는 도움 요청 횟수, 재입력 횟수, 차액·최소 단가·가정의 이해 여부를 기록한다. 농가가 참여할 수 없는 경우 팀원이나 처음 보는 사람의 과제 결과로 기록하고 실제 농가 검증은 별도 상태로 남긴다. 센터 PC 실기와 공개 사양 기준 로컬 실행도 각각 기록한다.

임준억 담당은 대화·조건 카드·공통 계산 연결과 출력 검증이다. 공통 도구의 외부 계약 변경이 필요한 경우 영향 범위를 적어 팀 리뷰를 받고, 가격 가정과 데이터 계약은 기존 구현을 재사용한다. P2 결과 JSON을 다시 불러오는 기능과 장기 사용자 프로필은 팀에서 우선순위를 정할 후속 후보로 남긴다.
