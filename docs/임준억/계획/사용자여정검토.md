# 사용자 여정 관점의 계획 재검토

기준일: 2026-11-09 KST. 사용자의 요청에 따른 설계 재검토입니다. 인터뷰·관찰로 검증한 여정이 아니라 현재 기능·업무 적용 조건에 근거한 가설입니다. 가상의 발언·감정·성과를 사용자 조사 결과로 만들지 않습니다.

## 판단

간단한 여정 지도로 기능 순서의 타당성을 확인하는 것은 유의미합니다. 기능을 늘리는 별도 프로젝트로 만들지 않고, 진입 부담·잘못된 판단·조건 변경·다음 행동을 빠뜨리지 않는 용도로 사용합니다.

일반 사용자와 자료 관리자의 과업을 구분합니다. 일반 사용자에게 매번 CSV 준비를 요구하면 핵심 비교 전에 이탈할 수 있습니다. 준비된 CSV로 바로 시작하고 자료 교체는 선택적인 관리 흐름으로 둡니다. 농가가 자료 관리까지 맡는다고 가정하지 않습니다.

## 계획 반영

후속 4단계 순서는 유지합니다. 1단계는 일반 사용자 온보딩 전체를 CSV 업로드로 시작하지 않도록 정정합니다. 첫 구현은 실제 확보된 경매 원본 CSV 명세를 지원하고, 기존 가격 이력을 유지하며 신규 유효 관측을 추가하는 흐름입니다. #855 출하자료는 현재 배포본을 유지하고 교체 UI·가공본 업로드·다른 센터 명세는 추가 설계 대상으로 둡니다.

2단계는 조건 입력부터 다음 행동까지 연결합니다. 준비 자료를 쓰는 일반 사용자의 완료 경로와 관리자 자료 갱신 경로를 별도로 검사합니다. 예측이나 사용자 대신 거래를 실행하는 기능은 추가하지 않습니다.

## 검증 한계

농가가 직접 출하일을 바꿀 수 있는지, 비용·감모 가정이 유용한지, 설명을 이해하는지는 실제 사람에게 확인하지 않았습니다. 개발 중에는 기존 U01~U04와 CSV 정상·실패·복구 검사로 동작을 확인합니다. 향후 참여자가 생기면 CSV 조작법보다 출하 비교를 끝내고 다음 확인 행동을 설명할 수 있는지를 관찰합니다.

## 공유 상태·PDF 반영

사용자가 후속 구현을 승인해 대화·조건 카드가 동일 상태를 사용하고 미리보기/PDF 중심 출력을 구현했습니다. 미저장 초안·과거 결과·자료 교체·철회·감모 재확인을 구분했습니다. 최신 판정은 [검증](../검증/2026-11-09_공유상태와PDF.md)입니다. 사람의 선호·효과는 미검증입니다.
