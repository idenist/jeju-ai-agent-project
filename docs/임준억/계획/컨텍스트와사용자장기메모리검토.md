# 컨텍스트와 사용자 장기 메모리 검토

최신 우선순위는 [센터·챌린지·팀 기준 재검토](센터와팀기준의하네스재검토.md)를 따릅니다. 아래 내용은 기술 가능성과 당시 권고의 이력입니다.
2026-11-09 KST / 로컬 개인 후보. 사용자 요청은 현재 구조 확인·장기 메모리 필요성 검토·나머지 하네스 보완점의 추가 점검입니다. 이번에는 코드와 공식 자료를 대조하고 모의 클라이언트로 동작을 확인했습니다. 제품 메모리 기능은 구현하지 않았습니다.

## 현재 상태

| 층 | 현재 구현 | 수명·한계 |
| --- | --- | --- |
| 대화 맥락 | AgentSession.messages에 사용자/모델/도구 메시지 누적, 다음 요청에 전달 | 세션 객체 메모리. 자동 trimming/요약/예산 없음 |
| 현재 비교 조건 | ScenarioStore의 scenario·version·history·provenance | 대화/카드 공유. 매 요청에 최신 snapshot 전달. 사용자 프로필이나 장기 기억은 아님 |
| 비교 건 기록 | JSON으로 조건·이력·자료 버전·당시 결과 내려받기/명시적 복원 | 사용자가 파일을 보관·다시 불러와야 함. 대화·선호도·사용자 ID를 담지 않음 |
| 사용자별 장기 메모리 | 없음 | 사용자 식별·프로필 저장·기억 검색/갱신/삭제·유효기간·교차 사용자 차단 구조 없음 |

Streamlit은 workspace를 session_state에 보관합니다. 일반 rerun과 브라우저 세션 종료/재시작은 다릅니다. 공식 [Session State 문서](https://docs.streamlit.io/develop/api-reference/caching-and-state/st.session_state)는 WebSocket 연결에 종속되어 탭 새로고침 등에서 초기화됨을 설명합니다. 이번에 실제 브라우저 재시작 시험을 수행한 것은 아닙니다.

모델 요청은 현재 앱이 input에 messages를 직접 넣고 store=False로 호출합니다. 앱은 Conversations 식별자나 사용자별 저장소를 사용하지 않습니다. store=False를 모든 서비스 로그의 무보존이나 사용자 장기 메모리 제공으로 해석하지 않습니다.

## 코드 점검·모의 실행에서 확인한 것

원시 결과: artifacts/context-memory-review/result.json. 모의 구조 확인이며 실제 모델·브라우저 재시작·실제 사용자 검사가 아닙니다.

- 대화만 비우면 messages는 비워지고 확정 비교 조건은 유지됩니다.
- 새 SharedWorkspace는 이전 물량을 알지 못합니다. JSON 명시 복원 후에만 3,000kg가 돌아옵니다.
- 비교 JSON에 messages/profile/user_id/preferences 필드는 없습니다. 이는 개인정보가 어떤 문자열에도 들어갈 수 없다는 뜻이 아니라 저장 구조에 사용자 메모리가 없다는 뜻입니다.
- 30회 모의 대화에서 요청 input의 JSON 문자 수가 372→11,180으로 증가했습니다. 토큰 수·실제 지연·실패율 측정값은 아닙니다.
- 모의 시간 제한은 API_ERROR/TimeoutError로 기록됩니다. 모델 오류와 앱의 실행 제한을 분리할 여지가 있습니다.
- 같은 존재하지 않는 도구를 호출하는 모의 응답이 6회 실행된 뒤 LIMIT_REACHED가 됐습니다. 현재 조기 반복 차단은 없습니다.
- 전체 조건 초기화 후 활성 scenario는 비지만, 이전 JSON 복원 때의 restored_archive 객체는 workspace에 남습니다. 현재 이 객체는 모델 input이나 결과 영역에 자동 재주입되지 않습니다. 장기 메모리·프로필 전환을 붙이기 전에 종료/삭제 범위를 명확히 하고 함께 정리할 필요가 있습니다.

## 권고하는 4개 층

1. **이번 요청의 컨텍스트:** 시스템 지침·현재 조건·관련 기억·최근 대화/필요 도구 결과만 모델에 전달합니다. 오래된 원시 출력은 전체 보관 기록과 모델 입력을 분리해 관리합니다.
2. **현재 비교 상태:** 현재 수치·모름/가정·기간·비용은 ScenarioStore가 기준입니다. 요약이나 과거 기억이 현재 확정값을 덮어쓰지 않습니다.
3. **사용자 프로필 기억:** 선호 표시 단위·설명 방식·주로 취급하는 품종·사용자가 알려준 시설/업무 조건 등을 출처·확인 시점과 함께 기억합니다. 시설 보유가 이번 저장 가능성까지 보장하지는 않습니다.
4. **과거 비교 기록:** 비교 목적·조건·근거·결정 이유·미확인 사항을 사례별로 보관합니다. 가상 비교와 실제 출하/정산 기록을 구분합니다. 현재 JSON을 이 층의 출발점으로 쓸 수 있지만 현재 데이터는 실제 실행/성과를 입증하지 않습니다.

[OpenAI의 세션 컨텍스트 예제](https://developers.openai.com/cookbook/examples/agents_sdk/session_memory)는 trimming과 압축으로 단기 맥락을 관리하는 방법을 다룹니다. 이는 사용자 장기 사실 저장과 별도 문제입니다. [Conversation state](https://developers.openai.com/api/docs/guides/conversation-state)는 API 대화 이어가기를 설명하지만 저장할 사용자 사실의 범위·갱신·삭제 정책을 대신 설계하지 않습니다.

[Anthropic Memory tool](https://platform.claude.com/docs/en/agents-and-tools/tool-use/memory-tool)은 대화 사이 파일 저장/조회와 애플리케이션이 관리하는 사용자별 저장소 패턴을 제공합니다. 여기서는 구조를 참고하며 Claude로 모델을 교체하거나 해당 도구를 그대로 도입하는 결정을 하지 않습니다.

## 기억의 저장·사용 규칙 제안

| 정보 | 저장·재사용 방식 |
| --- | --- |
| 선호 단위·출력/설명 방식 | 명시적 기억 요청 또는 저장 설정에 따라 프로필에 저장, 조회/수정/삭제 가능 |
| 주 취급 품종·보유 시설 등 | 사용자 진술로 기록하고 출처·확인 날짜·범위 유지. 필요한 경우 현재 조건 재확인 |
| 이번 물량·제시가격·기간·감모·보관비 | 비교 건에 저장. 새 비교의 실제 값으로 자동 적용하지 않음. 반복 기본값을 요청해도 이번 적용을 구분 |
| 가상 예시·미래 단가 가정 | 가정으로만 보관. 실제 농가 조건·관측값으로 승격하지 않음 |
| 기존 기억의 정정/철회 | 새 값의 출처를 남기고 이전 값을 대체 또는 철회. 삭제 후 다시 검색/주입되지 않아야 함 |
| 키·불필요한 개인/계약 정보 | 장기 기억 수집 대상으로 두지 않음 |

명시적 ‘앞으로 톤으로 표시해줘’는 선호 저장 요청으로 다룰 수 있습니다. 반면 모델이 추정한 사용자 특성을 확인 없이 사실로 고정하지 않습니다. 불필요하게 매 대화마다 확인 질문을 추가하는 대신 기억 후보와 사용 근거를 보여주고 수정/삭제할 수 있게 합니다.

첫 구조는 허용된 필드의 구조화 레코드와 프로필/사례 ID로 충분합니다. 예시 필드: memory_id, profile_id, kind, field, value, scope, source_case/turn, user_confirmed_at, valid_until, supersedes, status. 구체적 저장 필드·유효기간은 구현 설계에서 확정합니다. SQLite 또는 개인 프로필 파일이 후보이며 벡터 DB·임베딩·다중 Agent는 초기 필수 조건이 아닙니다.

센터 공용 PC에서는 프로필 식별·선택·접근 구분이 먼저 필요합니다. 임의 이름이나 프로필 ID만으로 본인 인증이 됐다고 간주하지 않습니다. 다른 이용자의 기억을 기본값으로 불러오지 않으며 종료·삭제·내보내기의 동작 범위를 정해야 합니다. 개인 파일 선택 방식과 중앙 사용자 저장 방식 중 운영 조건에 맞는 것을 선택합니다.

## 하네스 나머지 항목 재점검

실패 분류·같은 실행의 무의미한 호출 반복 차단은 모의 실행으로 근거를 추가 확보했습니다. 토큰/문자·지연·호출 예산을 나누고 현재의 90초 검사를 엄밀한 전체 요청 마감시간이라고 부르지 않습니다. SDK 요청/재시도 시간과 검사 위치가 함께 영향을 줍니다.

실행 기록은 run_id·시나리오/자료 버전·도구 인수/결과 식별·종료 사유와 더불어, 장기 기억을 붙이면 읽은 기억 ID·버전·신규 저장/수정/삭제 여부를 남겨야 합니다. 기억 원문 전체나 키를 진단에 무분별하게 복제하지 않습니다.

평가는 함수명을 알려주지 않는 한국어 과업을 반복하고, 기억 저장 전/후·새 세션·다른 사용자·정정/삭제·오래된 비용·가상 조건·문맥 정리 후 철회/기간 확인 보존을 포함해야 합니다. ‘기억해’라는 응답만으로 통과하지 않고 실제 저장 레코드·다음 요청의 입력·최종 비교 조건을 검사합니다.
