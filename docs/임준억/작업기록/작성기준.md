# 작업기록 작성 기준

2026-11-09 사용자가 요청한 기존 프로젝트 방식에 맞췄습니다. 직접 확인한 기준은 졸업 프로젝트의 `docs/작업기록/README.md`와 날짜별 기록입니다. AI중심세상 과제의 `docs/work_log.md`에서도 의도→검수 루프→한계→후속 정정 방식을 확인했습니다. halil 원문을 확인했다고 주장하지 않습니다.

## 위치와 이름

- 개인 문서의 단일 기준은 `docs/임준억/`입니다.
- 기록 파일은 `작업기록/YYYY-MM-DD_순서_한글주제.md`로 만듭니다. 같은 날에도 과업이 달라지면 나눕니다.
- 목차는 날짜·순서·기록 링크·주요 판정·다음 기록을 연결합니다. 계획된 미래 과업을 완료 기록으로 미리 만들지 않습니다.
- 작업기록은 대화 복사나 체크리스트만으로 채우지 않습니다. 상세 수치·원시 결과는 검증 문서와 artifacts의 해당 실행에 연결합니다.

## 매번 남길 내용

1. 수행일과 기록일(KST), 담당, 브랜치, 기준 커밋, 이전 기록. 모르는 수행일은 회고 정리라고 밝힙니다.
2. 사용자의 요청과 문제, 의도와 유지할 범위.
3. 실제 변경 파일/모듈과 변경 전→후 동작. 조사·계획·구현·실행을 구별합니다.
4. 검증 명령·환경·기대와 실제 결과, 실패/수정·재검증, 증거 경로.
5. 한계·미실시·다음 작업, 커밋·원격 반영 여부.

## 정정과 증거

- 최초 실패나 잘못된 평가 전제를 지우지 않습니다. 수정 이유와 재실행 범위를 새 기록에 적습니다.
- 전체 실행과 특정 사례 재시험을 합쳐 전체 통과로 표시하지 않습니다.
- 모델·자동 검사·AI의 역할별 검토는 실제 농가·심사위원·팀원 사람 검수와 구별합니다.
- 공개 사양 기반 적합성과 실제 센터 장비 실행을 구별합니다. 실제 장비 접근을 필수 완료 조건으로 임의 추가하지 않습니다.
- 농가가 없는 경우 공개 근거·업무 시나리오 검토를 진행하되 실제 농가의 효과·만족도·측정 시간으로 표시하지 않습니다.
- 키·원문 인증 URL·다른 프로젝트의 환경 파일을 기록에 넣지 않습니다.

## Git·문서 정리

현재 작업은 main `28e8af97` 기반 로컬 `dev/juneok`입니다. 새 구현의 커밋은 아직 없으므로 가짜 SHA나 과거 시각을 만들지 않습니다. 이후 커밋이 생기면 다음 기록에서 앞 단계 실제 SHA를 연결합니다. 자기 기록에 자기 커밋 SHA를 맞추기 위해 반복 수정하지 않습니다.

문서를 이동할 때 상대 링크·README·설치 안내·패키지 경로를 같이 검수합니다. 당시 ZIP·평가 입력·원시 로그는 변경하지 않고 새 버전을 만듭니다. 제품 동작을 바꾸지 않은 문서 작업은 링크·패키지·관련 경로 검사를 우선하며, 과거 유료 평가를 이유 없이 반복하지 않습니다.

## 커밋 메시지 형식

2026-11-09 사용자 지정 형식입니다. 앞으로 제목은 `type: 구체적인 변경을 서술한다`로 작성하고, 빈 줄 뒤에 주요 변경 사항을 `-` 불릿으로 적습니다. 필요한 경우에만 불릿 아래에 변경 배경·제약·판단 근거를 별도 문단으로 덧붙입니다. 실제 변경 범위와 검증만 쓰고 미완료 계획을 완료처럼 넣지 않습니다.

```text
feat: 경매 CSV를 검사하고 확인 후 적용한다

- 지원 CSV의 형식과 신규 유효 관측을 검사한다.
- 적용 전 관측기간과 제외 내역을 보여준다.
- 기존 이력을 보존하고 자료 변경 후 대화를 초기화한다.
- 오류·변조·중복·적용 흐름을 검증한다.

일반 사용자는 배포 자료로 시작하며, CSV 추가는 자료 관리자가 필요할 때 수행한다.
```

이 형식 지정 자체로 커밋·push를 실행한 것은 아닙니다.
