## 요청과 의도

사용자는 계획대로 진행하되 UI/UX가 지정돼 있는지와 개선 여지를 확인할 가치가 있으면 확인하도록 요청했습니다. 공식 안내에 UI 설명 의무와 비전문가 목적을 확인했고, 확인한 본문에는 고정 양식·프레임워크 지정이 없었습니다. 기존 Streamlit을 유지하며 조건 입력·수정·결과 이해를 개선했습니다.

## 실제 변경

app.py의 직접 입력을 네 구역으로 묶고 입력 구분·조건 표·수정 후 결과 숨김·재계산 버전을 연결했습니다. 제출형 form을 상태가 반영되는 container 입력으로 바꿔 편집 확정 후 과거 결과·다운로드·민감도 표를 숨깁니다. 기간 변경 콜백으로 감모 확인을 즉시 해제해 사용자가 새 기간의 값을 확인하고 한 번에 제출할 수 있습니다. 대화 탭도 현재 Python 상태의 조건 표를 제공합니다. 대화와 직접 입력은 자동 동기화하지 않습니다.

agents/juneok/ui_workflow.py에 입력 스냅샷·변경 항목·계산 입력 변환·조건 구분을 모았습니다. agents/juneok/reporting.py는 직접 비교 UI 메타데이터가 있을 때 버전·입력 구분·변경 항목·다음 행동을 화면과 보고서에 동일하게 붙입니다. 메타데이터가 없는 기존 도구 결과 형식은 유지합니다. 실제 값이라고 표시한 입력도 사실 검증으로 표현하지 않습니다.

검사는 tests/test_juneok_ui_workflow.py와 tests/test_juneok_ui.py에 의미·흐름 7개를 추가했습니다. 모델 프롬프트·도구 계약·산식·공통 자료는 변경하지 않았습니다.
