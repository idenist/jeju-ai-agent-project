# 출하 기록·정산 검산·근거 추적 구현

수행·기록일2026-11-09 KST / dev/juneok. 이전: [공식 자료와 팀 방향 대조](2026-11-09_28_공식자료와팀방향대조.md).

## 요청과 의도

사용자가 보완한 A 실제 출하 기록+B 정산 검산과 citation을 구현하고 기존 기능을 유지하는 검증 루프, 공식 자료/팀 방향 대조를 요청했습니다. 당시 가정 대조C·팀 최종 채택과 분리했습니다.

## 작업과 변경 이유

기존 가정 상태를 실제 값으로 덮어쓰지 않도록 ShipmentStore를 분리했습니다. 원래 비교/선택 대안과 연결하고 확인 이력을 보존합니다. 정산서 공제·외부 비용·입금의 금액 의미를 나눠 검산하며 모름/0·중복·미지원 유형을 조용히 정상 처리하지 않습니다.

입력/계산 근거를 Python이 생성해 같은 수치/ID를 대화·카드·PDF·JSON에 사용합니다. 가져온 결과는 재계산 일치 검사를 거치며 사실 인증은 아닙니다. 모델 전송은 기본 미동의, 동의는 정확한 기록 내용에 묶습니다. 수정/철회 시 이전 대화와 정산 결과를 비우고, 개인 정산 결과가 기존 비교 JSON으로 흘러가지 않게 했습니다. 카드 입력은 키 없이 가능하며 실제 값의 자연어 자동 저장은 넣지 않았습니다.

공식 안내를 재확인해 실제 금융 기록을 제출하지 않고 가상 자료로 검증했습니다. 알려진 개인 정산 JSON이 패키지에 섞이면 빌더가 중단합니다. 대표 하네스/공통 근거 구조·정산 채택은 팀 합의로 남겼습니다. 새 라이브러리는 추가하지 않았습니다.

## 실패·수정·검증

모듈 import 실행 경로를 정정했고 UI 검증의 로컬 소켓 제한은 traceback 확인 후 허용 환경에서 실행했습니다. JSON 키 순서에 따른 citation 변화, 카드 편집 시 먼저 렌더링되는 이전 금액, current 대안 ID 충돌을 발견해 수정했습니다. 후속 검사는 각 원인을 직접 검증합니다.

[구현·검증 결과](../검증/2026-11-09_실제출하와정산검산.md): 기존226+신규31=257개, 최종 신규모델6종×3회18/18, 기존모델25/25, 기존 추가 제품8종8/8. 단계별 실행/소스 차이를 문서에 구분했습니다. 초기 신규18회도 통과했으나 식별 구조 보완 뒤 최종18회를 별도로 실행했고 두 실행을 하나의 반복 수로 합치지 않습니다. 정상/부분 PDF2종4페이지를 렌더링해 확인했습니다.

README·사용자/도구 계약·현재 현황·개발계획을 최신화했습니다. 이전 원격 커밋/인수 ZIP·제출 후보PDF는 해당 시점 산출물이며 이번 로컬 변경을 원격 게시/팀 합의로 표시하지 않습니다. 실제 농가·양식·센터 실측은 미검증이며 C/D와 팀 통합을 후속으로 유지합니다. 이번 요청에는 커밋·push를 수행하지 않습니다.

## 최종 정리

분리한 키 없는 CSV ZIP에서257개·doctor·공개 사양·파일 해시·키 제외 검사가 통과했습니다. 이후 UI 최종 검수에서 정산 변경/삭제의 PDF 캐시 정리와 동의 철회 즉시 화면 반영을 보완하고 같은31개/전체 회귀·패키지를 다시 확인합니다. 모델 검증 이후 바뀐 것은 UI 캐시/표시 경로이며 실행 모듈 해시와 후속 검증을 분리 기록합니다. 기존 재현용 환경을 재사용했으며 새 패키지 의존성을 재설치하거나 실제 센터에서 실행한 것은 아닙니다.
