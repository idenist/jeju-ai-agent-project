## 구현과 단계 게이트

catalog.py/explore_data는 CSV의 실제 결합 거래규격·출하 품종/연월·관측기간·품질·부분월·코드 모호성·페이지를 제공합니다. UI는 같은 후보를 순차 선택하고 상위 선택이 바뀌면 하위를 비웁니다. 대화 탐색 결과를 카드에 반영하고 명시적 후보 조회만 실행합니다. 가격·품종 자동 대입은 없습니다.

limits.py/solve_offer_limits는 제안단가에서 감모 또는 전체 물량 하루 보관비를 한 변수씩 역산합니다. 기존 비용/수수료 검사를 재사용하고 임시0/제안값을 실제 조건으로 저장하지 않습니다. 유한 상한·가능한 해 없음·감모 전체 영역을 구분하고 표시 상한을 내립니다. 예시 경계7.67%/일100285원·전방 계산 전후 정답을 확인했습니다.

최초210개 후 오류 보완을 거쳐212개·새 한국어6종×3회18/18과 PDF 관련24개를 확인한 뒤3번을 시작했습니다. case_changes.py/review_case_changes는 명시 선택한 v1/v2 JSON과 현재 조건의 변경을 읽기 전용 검토합니다. 양쪽 조건을 현재 계산 규칙으로 다시 계산하고 당시 보관 숫자를 현재 사실로 사용하지 않습니다. 가격/비용 기준이 다르면 단가 차이를 만들지 않습니다. 현재 조건 복원은 별도 버튼으로 유지합니다.

## 실패와 보완

부분월 테스트가 노지온주9월을 가정한 오류와0/0.00 표기를 정정했습니다. 실모델 첫12회 중1회에서 역산 미래 단가를 저장한 문제를 찾아 지침을 보강했습니다. 이어 발견한 버전/일회성 확인 플래그만 바뀐 호출과 실제 경제 입력 변경을 구분했고, 미래가격 저장은 계속 거부하는 음성 검사를 추가했습니다. 역산 후 불필요한 전방 누락 질문도 제거했습니다.

PDF 이미지에서 표 행 사이 빈 줄 때문에 표가 문자로 출력되는 문제와 저장 단가/이번 역산 단가의 혼동을 수정했습니다.3번 관련12개·전체224개 이후 가격 표시 검사1개를 더해 최종225개 전체 회귀가 통과했습니다. 최종 기존 모델J25에서 복수 가정표 요청을 단일 비교로 처리한 실제 회귀1건도 발견해 도구 선택 지침을 보강했습니다. 최종25종과 J25 반복·신규24회·맥락18회는 실행별 원본으로 구분합니다.

J25 반복3회와 기존25종은 통과했습니다. 새 탐색 반복의1회는5kg를 포장 종류에 넣어 NO_DATA로 종료했습니다. 포장/중량 스키마 설명과 입력 경계를 보강해 해당 오류를 수정 안내가 있는 INVALID_INPUT으로 반환하도록 했습니다. 하네스의 수정 후 재호출 경로까지 검사해 신규1개를 더했으며 마지막 회귀 대상은226개(기존188+신규38)입니다. 실패 원본과 보완 후 최종 판정을 분리 보존합니다.
