## 요청과 판단

사용자가 사용자 여정 관점으로 계획을 한 번 더 검토한 뒤 진행하고, 이후 커밋은 제목·변경 불릿·필요시 맥락 형식으로 쓰도록 요청했습니다. [여정 검토](../계획/사용자여정검토.md)를 작성하고 [작성기준](작성기준.md)에 커밋 형식을 반영했습니다. 실제 농가 조사나 역할별 검증단을 새로 실행한 것은 아닙니다.

여정에서 일반 사용자의 비교와 자료 관리자의 CSV 갱신을 구분했습니다. 기존 자료로 바로 시작하고 CSV 추가는 선택 기능으로 제공합니다. 새로운 범용 기능보다 진입·조건·결과·수정·다음 행동을 연결하는 기존 순서를 유지했습니다.

## 실제 변경

- agents/juneok/csv_import.py: 배포 원본과 같은 36컬럼, UTF-8/CP949, 컬럼 순서 변경, 20MiB 제한을 지원합니다. 업로드 단독으로 유효 거래와 신규 관측을 확인한 다음 기존 원본에 추가한 후보를 만듭니다. 기존 자료가 잘못된 업로드를 가리는 것을 방지했습니다.
- app.py: 관리 영역에서 파일 선택·검사·유효/제외 내역·기간·품종·버전 미리보기 후 명시적 적용을 제공합니다. 준비 자료로 바로 시작할 수 있음을 안내합니다.
- 적용 전 원본/가공본/명세 변경과 미리보기 이후 선택 자료 변경을 검사합니다. 실패 시 활성 자료를 교체하지 않습니다. 적용 시 대화를 초기화하며 직접 입력 조건은 유지합니다.
- tests/test_juneok_csv_import.py, tests/test_juneok_ui.py: 신규 9개 검사를 추가했습니다. 미리보기 무변경, 중복·인코딩·컬럼 순서, 잘못된 날짜/단위/금액/구조, 제외 행 설명, 변조·선택 변경, 조회 출처, 화면 적용·오류를 확인합니다.
- 개발계획·실행안내·현황·문서안내·기록 목차를 최신화했습니다. 공통 데이터와 전처리 코드는 변경하지 않았습니다.

## 실패·수정·검증

최초 개별 검사에서는 Windows 샌드박스의 기본 임시 폴더 접근이 제한됐습니다. 새 검사도 제품 artifacts/tmp를 사용하도록 수정했습니다. 정상 적용 사례의 처음 실패는 원본 등급/크기 `.`가 전처리에서 `미상`으로 바뀌는 것을 평가 조건이 반영하지 못한 것이며, 평가 조건을 고쳤습니다.

기본 샌드박스 전체 실행은 Streamlit 로컬 소켓 제한으로 UI에서 정지해 중단했습니다. 로컬 소켓을 허용한 환경에서 `.venv/Scripts/python.exe -m scripts.verify_juneok`를 재실행한 결과 108개, 실패0·오류0이며 공통 원본·전처리와 manifest가 유지되고 환경/키/결과의 Git 제외를 확인했습니다. 모델 호출은 0회입니다.

실행 원문은 [검사 결과](../../../artifacts/verification-runs/20261109-csv-journey/verification.json), [검사 로그](../../../artifacts/verification-runs/20261109-csv-journey/unittest.log), [변경 코드 해시·검증 범위](../../../artifacts/verification-runs/20261109-csv-journey/scope.json)에 보존했습니다. UI 검사는 Streamlit AppTest이며 업로드 바이트 주입은 모의 객체로 연결했습니다. 실제 브라우저 파일 선택·실제 센터 장비·사람의 사용성 검증을 수행했다고 주장하지 않습니다.
