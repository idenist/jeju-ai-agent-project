# 출처와 계산 근거 인용 점검

수행·기록일2026-11-09 KST / dev/juneok. 이전: [원격 게시 확인과 실제 출하·정산 검토](2026-11-09_26_원격게시확인과실제출하정산검토.md).

## 요청과 범위

사용자가 실제 출하 기록 A+정산 검산 B 우선 방향에 동의하고 citation 추가 확인을 요청했습니다. 이번에는 제품 개발을 시작하지 않고 근거 표시의 현재 상태와 완료 기준을 점검했습니다. 다음 개발 승인을 다시 요청하는 단계가 아닙니다.

## 확인과 반영

자료 조회·입력 상태·계산·보고서/PDF 코드를 읽고 출하량/시장 조회 두 건을 재실행했습니다. 원문 URL과 조건은 있었으나 결과별 내용 해시·수치별 고정 입력/계산식 참조는 부족했습니다. 선택한 제품 PDF4개와 제출 후보2개의 URI 주석은0개였고 공개 출처 주소는 텍스트 형태였습니다. 계산 전용 보고서에 외부 URL이 없다는 이유로 오류 판정하지 않았습니다.

KAMIS 표본 조사는 업무 배경, 전자송품장 메뉴는 기존 시스템 존재의 근거로만 제한했습니다. #855/공공데이터포털의 이번 웹 읽기 실패를 링크 폐쇄로 해석하지 않았습니다. 가상 정산 수수료5%나 개인 입금 사실의 공식 근거는 확보하지 않았습니다.

[검토 결과](../검증/2026-11-09_출처와계산근거인용점검.md)와 [개발 범위](../계획/실제출하와정산기록개발검토.md)를 연결했습니다. A의 입력/버전 근거 → B의 계산/표시 참조 → 기존 자료 도구 정렬 순서이며 팀 공통 스키마·이용조건·실제 양식은 별도 합의로 남깁니다.

## 검증과 한계

원시 결과 artifacts/citation-review/result.json. 프로그램 코드는 변경하지 않았고 전체226개/유료 모델 호출을 재실행하지 않았습니다. 이번 판정은 근거 추적 보완 필요이며 citation 기능 구현 완료가 아닙니다. 문서 상대 링크와 diff 공백 검사는 별도 실행 결과를 확인합니다.

## 후속: 답변별 인용 방식

사용자가 답변마다 citation을 제공하는 방식을 추가 검토해 달라고 요청했습니다. ALCE 논문 §3.3의 인용 지원 범위/불필요한 인용 구분을 참고하고 agent.py의 도구 기반 최종 표시를 확인했습니다. 제품 설계는 자료/수치/판단에 근거 확인 경로를 제공하고 질문/단순 확인에는 생략하는 방식으로 문서화했습니다. LLM 임의 인용 생성이나 매 응답 웹 검색 없이 Python 근거 레지스트리와 렌더러를 연결할 예정입니다. 농가 검증이나 구현 완료로 표시하지 않았습니다. 앞선 문서72개 상대 링크 누락0건·diff 공백 오류0건이며 후속 문서 수정 후에도 diff 검사를 실행합니다.
