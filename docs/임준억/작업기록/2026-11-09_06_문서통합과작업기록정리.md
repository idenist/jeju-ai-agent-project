## 요청과 의도

개인 문서를 docs 안의 별도 폴더로 모으고 기존 팀 안내처럼 한글 파일명으로 정리하도록 요청받았습니다. 작업기록이 없으면 지금까지를 정리하고, halil 또는 졸업 프로젝트의 기존 기록 방식을 따르도록 요청받았습니다.

## 참고와 실제 변경

졸업 프로젝트의 작업기록 목차·날짜별 실제 GPT 검증·문서 재검토·커밋 작성 기준을 읽었습니다. 인덱스와 과업별 문서로 의도·변경 전후·검증·실패 정정·한계·다음을 연결하는 방식을 채택했습니다. 다른 프로젝트의 환경 파일이나 제품 코드는 읽거나 가져오지 않았습니다.

루트 docs의 개인 계획 4개와 제품 docs의 개인 안내/검증 8개를 `docs/임준억/`의 계획·안내·검증으로 모았습니다. 기존 팀 전처리 안내 두 문서는 그대로 뒀습니다. 루트 docs는 문서 위치 안내만 남겼습니다. 코드·설정·데이터·.review·과거 ZIP과 평가 원본은 이동하지 않았습니다.

[문서안내](../문서안내.md), [작업기록 작성기준](작성기준.md), [이동 대조표](문서이동대조표.md)를 만들고 앞선 작업을 01~05 회고 기록으로 정리했습니다. 모르는 수행 시각·없는 커밋 SHA·실제 사람이 아닌 역할 검토를 실제 검증처럼 만들지 않았습니다.

## 링크·실패와 수정

이동 전 12개 문서의 바이트와 SHA를 artifacts/documentation에 보관하고, 상대 링크를 옛 위치 기준으로 해석해 새 위치에서 다시 썼습니다. 첫 점검에서 새 작업기록의 .review 상대 경로 한 곳을 수정했습니다. 설치 안내의 영문 문서 경로는 README 진입점으로 바꿨습니다.

당시 ZIP은 과거 문서 구성을 담으므로 덮어쓰지 않고 새 ZIP을 만듭니다. 영문 이름의 빈 리다이렉트 문서를 여러 개 남기지 않고 이동 대조표를 사용합니다. 예전 대화의 로컬 링크는 자동 변경되지 않으며 대조표가 현재 위치를 안내합니다.
