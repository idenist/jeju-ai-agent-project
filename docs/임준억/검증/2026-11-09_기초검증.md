### 평가 오류를 수정한 이유

최초 J08은 **2025년 9월 노지온주 부분월** 표시를 기대했지만 실제 해당 월 자료에는 하우스온주만 있습니다. Agent가 `NO_DATA`를 반환한 것은 자료에 맞는 동작입니다. 기존 평가셋·평가기 사본은 [원본 보존 폴더](../../../artifacts/evaluation-runs/baseline-v1-sources/)에 남겼습니다.

J08의 질문을 실제 존재하는 하우스온주로 고쳤습니다. 관련 제품 조회 로직은 변경하지 않았습니다. 유료 평가 전에 자료 전제 6개를 확인하는 사전 검사를 추가하고, 잘못된 품종의 평가 전제를 감지하는 회귀검사를 추가했습니다. 수정 후 전체 20건을 한 번에 재실행한 것은 아니므로 **‘전체 20/20 실측’으로 보고하지 않습니다.**

### 4턴 대화에서 확인한 동작

1. 물량·현재 가격·기간만 주었을 때 미확인 비용·감모를 0으로 채워 계산하지 않았습니다.
2. 비용 기준을 추가해도 감모가 없을 때 계산을 유보했습니다.
3. 7일 전체 감모 2%와 실행 가능성을 확인한 뒤 최소 단가 3,109원/kg을 계산했습니다.
4. 감모를 4%로 바꾸고 출하 변경 가능성을 철회하자 최소 단가는 3,174원/kg, 실행 가능성은 미확인으로 갱신했습니다. 물량·현재 단가·저장 가능성은 유지했습니다.

## 발견한 개선점

- **불필요한 도구 호출:** 기간 변경 반복 중 모델이 즉시 출하 0일을 지연 대안 배열에 넣었다가 도구의 거부 후 수정한 실행이 있었습니다. 잘못된 최종 금액은 나오지 않았지만 시간·토큰이 낭비됩니다. 즉시 출하는 별도 기준이라는 지시와 지연 일수의 스키마 제약을 강화해야 합니다.
- **응답 시간:** 최초 전체 평가의 턴 중앙값 9.01초, 최댓값 25.25초입니다. J03 반복의 턴 최댓값은 27.37초, 한 2턴 사례 합계는 약 39초였습니다. 순차 로컬 소규모 측정으로 부하·일반적 백분위 성능을 뜻하지 않습니다. 중복 상태 갱신과 불필요한 재계산을 줄일 필요가 있습니다.
- **연결 상태 표시:** 실제 호출 성공 후에도 사이드바는 키 존재 여부만으로 ‘연결 검증 전’이라고 표시합니다. 현재 설정으로 마지막 성공·실패를 구분해 표시하도록 개선해야 합니다.
- **질문 부담:** 단가 포함비용을 엄격하게 확인하는 것은 계산에 필요하지만, 사용자가 무엇을 답하면 되는지 더 쉬운 예시·선택지를 제공할 필요가 있습니다.
- **자료의 시점:** 현재 가격 스냅샷은 2026-11-03까지, 출하량은 2025-09-17까지입니다. 현재 사용자 제시 단가로 조건부 비교는 가능하지만 이 자료를 11월 9일 실시간 시세·공급량으로 사용할 수 없습니다.

## 재현 명령

제품 폴더에서 실행합니다. `--live`는 실제 API 사용량을 발생시킵니다.

```powershell
.\.venv\Scripts\python.exe -X utf8 -m agents.juneok.cli --check
.\.venv\Scripts\python.exe -X utf8 -m scripts.verify_juneok
.\.venv\Scripts\python.exe -X utf8 -m scripts.evaluate_juneok
.\.venv\Scripts\python.exe -X utf8 -m scripts.evaluate_juneok --live --case J03 --repeat 3
.\.venv\Scripts\python.exe -X utf8 -m scripts.validate_juneok_dialogue --live
```

`verification.json`의 `live_model_called: false`는 오프라인 검사 스크립트 자체의 무과금 실행을 뜻합니다. 실제 모델 실행 증거는 위 표의 별도 JSON에 있습니다. API 키는 채팅·문서에 복사할 필요가 없습니다.
