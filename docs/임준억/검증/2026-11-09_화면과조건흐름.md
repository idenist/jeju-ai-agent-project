# 화면과 조건 흐름 개선 검증

기준일 2026-11-09 KST. 현재 제품 환경의 회귀 및 로컬 브라우저 검증입니다. 실제 농가 참여자는 0명입니다.

## UI 지정 여부와 개선 판단

[공식 안내](https://daker.ai/public/hackathons/jeju-ai-bigdata-agent-challenge)를 다시 읽었습니다. 비전문가가 직접 실행·활용할 수 있어야 하고 기획서 개발·탑재 계획에 UI 구성을 설명하도록 요구합니다. 확인한 안내 본문에는 특정 화면 양식·색상·프레임워크를 고정한 규정이 없습니다. 이는 모든 별도 공지까지 제한이 없다고 보장하는 해석은 아닙니다. 제출 직전 공지는 다시 대조합니다.

프로젝트의 기존 Streamlit 구조는 유지합니다. 별도 디자인 시스템이나 프런트엔드 교체보다 실제 여정의 긴 입력·현재 조건 확인·수정 후 결과 혼동·다음 행동을 개선할 여지가 있다고 판단했습니다. 이는 사용자 인터뷰가 아닌 구현·화면 검토의 판단입니다.

## 변경 전과 후

| 항목 | 변경 전 | 변경 후 |
| --- | --- | --- |
| 입력 구조 | 긴 연속 입력 | 현재 판매·비용·보관·실행 조건의 4구역과 짧은 설명 |
| 입력의 성격 | 예시 여부를 일부 값으로 추정 | 실제 여부 미구분/사용자 실제 조건 표시/가상 예시·가정 구분, 예시 버튼은 가상 표시 |
| 현재 조건 | 도구 JSON이나 대화에서 확인 | 대화의 현재 버전 조건 요약, 직접 비교의 입력·미확인·가정 표. 두 탭은 독립 |
| 수정 후 결과 | 마지막 제출 결과가 계속 남음 | 입력이 화면에 반영되면 직전 결과·보고서·민감도 표를 숨기고 재계산 안내 |
| 보관기간 수정 | 제출 때 감모 확인 해제, 재확인을 위한 추가 제출 필요 | 기간 편집 시 즉시 해제, 새 기간을 확인한 뒤 한 번 제출 가능 |
| 보고서 | 계산·입력·한계 중심 | 직접 비교의 조건 버전·변경 항목·입력 구분·다음 확인 행동 추가 |

표의 입력됨·사용자 실제 조건 표시는 실제 사실을 검증한 증거가 아닙니다. 미래 단가는 사용자 가정, 감모는 사용자 조건·가정으로 표시합니다. 0·미확인·아니오를 구분하며 누락을 임의 보충하지 않습니다.

## 검증과 증거

`.venv/Scripts/python.exe -m scripts.verify_juneok`를 Streamlit 로컬 소켓을 허용한 환경에서 실행했습니다. 115개, 실패0·오류0입니다. 이전 108개에 새 의미·흐름 검사7개를 추가했습니다. 감모 편집 후 결과/다운로드/민감도 숨김, 재계산 시 물량·단가 보존과 버전 증가, 기간 변경 후 제출 전 감모 재확인, 0/미확인/거부·가정 구분, 보고서 일치와 실행 제약 안내를 검사했습니다. 공통 데이터/전처리와 manifest는 유지됐습니다.
