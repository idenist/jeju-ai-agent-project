# 공개 센터 사양과 농가 업무 적합성 검토

2026-11-09 KST / 로컬 dev/juneok / 새 커밋·원격 반영 없음.

## 검증 기준 정정

사용자는 실제 농가 참여자와 센터 PC 접근이 없다고 다시 확인했고, 공개된 센터 환경에 맞춰 실행되면 개발 검증 기준으로 삼는 것이 적절하지 않느냐고 요청했습니다. 이를 반영해 **현재 개발의 환경 판정은 공개 사양 기준 적합성**으로 합니다. 실제 장비 실행을 개발 진행의 필수 선행 조건처럼 설명했던 부분을 정정합니다.

[공식 규정](https://daker.ai/public/hackathons/jeju-ai-bigdata-agent-challenge)은 센터 최소 사양·탑재 계획·설치/실행 매뉴얼·외부 의존성과 정상 작동 검증을 요구하고 운영진이 실행을 요청할 수 있다고 명시합니다. 확인한 규정에 ‘참가자가 사전에 실제 센터 PC에서 시험해야 한다’는 별도 의무는 없습니다. 이는 현재 개발 통과기준의 해석이며 운영진의 최종 인수·평가를 대신하지 않습니다.

[공식 답변](https://daker.ai/public/hackathons/jeju-ai-bigdata-agent-challenge?section=board&postId=3d8a1ba3-d0d8-4667-9e0e-b6d5d671e6d5)은 Windows 11 26H2, i7-8700·GTX 1060·32GB, 프로그램/패키지 사전 명시, CSV 입력과 외부 LLM 허용을 안내합니다. 이 조건에 맞는 설치·CSV 실행·자원 요구를 검증하고 실제 장비를 사용하지 않았다는 사실은 별도 한계로 남깁니다.

## 공개 사양 기준 판정: 범위를 명시한 통과

새 가상환경의 Python 3.13.12에서 `python -m scripts.verify_juneok_center_spec`를 실행했습니다. 각 자식 프로세스만 논리 CPU 1개로 제한했습니다. OpenAI·경매 키를 모두 비우고 requests·동기 httpx HTTP 호출을 거부한 상태에서 실제 CSV·대화 없는 화면 흐름을 검사했습니다. OS 전체 방화벽을 끄거나 변경하지 않았습니다.

| 범위 | 실제 결과 |
| --- | --- |
| OS·패키지 | Windows 11 x64 계열, Python 3.13.12, 분리 설치한 고정 의존성 |
| CSV 도구 | 비교·#855 실제 조회·민감도 6조합 통과, 단일 논리 CPU |
| 화면 자동 흐름 | 키 없음 → 예시 선택 → 직접 비교 → 과거 출하량 → 민감도 6조합 통과 |
| CSV 프로세스 최대 작업 메모리 | 49,528,832 bytes, 약 47.2MiB |
| 화면 Python 프로세스 최대 작업 메모리 | 75,960,320 bytes, 약 72.4MiB |
| 메모리 점검 | 각 프로세스 작업/커밋 최대치 모두 프로젝트 보수 기준 512MiB 미만 |
| GPU | 로컬 LLM·CUDA 모델을 실행하지 않음. 자연어 처리는 외부 모델 API |
| 외부 모델 | 기존 실제 25/25 결과와 현재 제품 소스 해시 일치 확인. 이번 검사는 모델 재호출 없음 |

[실행 원본](../../../artifacts/center-spec/result.json). [Microsoft 메모리 계측 정의](https://learn.microsoft.com/en-us/windows/win32/api/psapi/ns-psapi-process_memory_counters_ex), [프로세스 CPU 제한 정의](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-setprocessaffinitymask)를 참고했습니다.

이 검사는 i7-8700 성능을 에뮬레이션하거나 RAM을 OS에서 512MiB로 강제 제한한 시험이 아닙니다. 512MiB는 주최측 요건이 아닌 프로젝트의 보수적인 확인 예산입니다. 메모리는 각 Python 프로세스이며 브라우저·다른 프로그램·대용량 임의 CSV를 포함하지 않습니다. 실제 Windows 26H2 이미지·드라이버·보안 프로그램·센터 계정은 재현하지 않았습니다. 따라서 판정은 **공개 사양에 맞춘 실행 적합성 확인**, 사실 기록은 **physical_center_executed=false**입니다. 두 표현은 모순되지 않습니다.

## 실제 제품 결과의 재검토

기존 실제 모델 평가를 코드 해시와 함께 재검토해 다음 9개 조건을 확인했습니다. 새 모델 호출은 하지 않았습니다.

1. 현재 제시가격을 모를 때 생성하지 않음.
2. 감모 미확인을 0으로 채우지 않음.
3. 새 보관기간의 감모를 다시 확인함.
4. 저장/출하 변경 불가를 실행 제약으로 표시함.
5. 확보 범위 밖의 미래 기준일 가격을 만들지 않음.
6. #855 과거 7개 연도를 실제 자료로 조회함.
7. 민감도 가정이 원래 감모 조건을 바꾸지 않음.
8. 가정 목록 미정이면 값을 만들지 않고 입력을 요구함.
9. 미래 단가가 없는 범위 비교에 가정 가격을 채우지 않음.

9/9 통과, 현재 코드 해시 불일치 0. [재검토 결과](../../../artifacts/public-practicality/result.json). 이는 합성 업무 시나리오의 설계 적합성 근거이며 농가의 입력 부담·이해도·수기 대비 시간·실제 수익 효과를 측정한 결과는 아닙니다.
