## 대조 결과와 보완

| 지점 | 판단 | 적용할 경계 |
| --- | --- | --- |
| 답변별 근거 | 출처 명시 요구와 부합 | 공식이 매 문장 인용이나 특정 UI를 의무화한 것은 아님. 자료/수치/판단에 참조, 질문/확인에 생략하는 것은 개인 UX 설계 |
| 지정 데이터 활용 | 기존 #855 실제 조회/집계를 핵심 여정에 유지해야 함 | 개인 정산 기록·외부 경매 데이터만으로 지정 데이터 요건을 대신하지 않음. 모든 계산에 #855를 억지로 인용하지도 않음 |
| 시점·분류 | 기존 팀/개인 검토의 경계와 부합 | 출하량 과거 계절 맥락을 현재 공급·가격 인과로 표시하지 않음. 출처 ID가 있어도 잘못된 조인을 허용하지 않음 |
| 센터 실행 | 기존 CSV 경로와 작은 근거 메타데이터는 방향에 부합 | 매 응답 인터넷/웹 검색/벡터 DB를 요구하지 않음. 최소 하드웨어 공개는 OS·권한·네트워크·API 계정이 모두 제공된다는 증거가 아님. 공개 사양 기반 재현과 실제 센터 실행은 구분 |
| 정산 A+B | 출하 검토→실행 기록을 연결하는 개인 인접 확장으로 적합하다고 판단 | 독립 장부 서비스가 중심이 되지 않게 기존 분석을 유지. 실용성은 가설. 팀 최종 기능 채택·우선순위 합의와 별개 |
| 금융정보와 citation | 기존 계획의 공개/비공개 구분을 더 명확히 할 필요 | 원문 파일명·개인 경로·계좌·사용자 식별자를 답변/공유 PDF에 기본 노출하지 않음. 가명 근거 ID 사용. 금융정보는 식별자 삭제만으로 자동 비민감하다고 간주하지 않음 |
| 팀 통합 | 함수/자료/계산 근거를 분리하면 이식에 유리하다는 설계 판단 | 공통 레지스트리·대표 하네스/UI·팀원 도구 연결·정산 채택은 합의 대기. 다른 브랜치/공통 전처리는 이번 변경 없음 |

## 개인정보·금융정보에 대한 설계 정정

공식 안내는 제출 코드·발표자료·영상에 개인정보/금융정보/인증정보를 포함하지 않도록 하고 분석 결과물에서도 개인정보 노출을 방지하도록 요구합니다. 따라서 실제 정산 금액·원문을 실습 입력으로 처리할 수 있다는 것과 그것을 제출/공유해도 된다는 것은 다릅니다.

A+B의 검증·공개 시연·제출 샘플에는 **명시한 가상 자료**를 사용합니다. 근거 ID만으로 원본 파일명이 드러나지 않게 하고, 민감정보를 citation 라벨/URL/로그로 복제하지 않습니다. 초기 UI/PDF는 가명 입력/계산 근거만 표시하고 실제 파일 원문 인용·OCR을 추가하지 않습니다. 사용자가 의도해 내보내는 개인 기록 JSON은 명시적 로컬 저장이며 공유용 제출물과 분리하고 제출 패키지에서 제외합니다. 실제 사용자 기록/식별정보가 발견되면 패키지 검사를 실패시켜야 합니다. 기본 미저장이나 가명처리만으로 실제 농가 운영 정책까지 검증됐다고 주장하지 않습니다.

## 개발에 적용할 순서

1. 기존 조회/계산/대화의 근거 계약을 유지하면서 A에 불변 비교 연결·입력 상태/버전을 설계합니다.
2. B의 결정론적 검산과 같은 입력을 가리키는 근거 레지스트리·대화/PDF/JSON 참조를 연결합니다.
3. 기존226개 회귀와 신규 독립 정답·참조 무결성·변경 후 무효화·공개 출력의 민감정보 비노출·키 없는 CSV 흐름을 확인합니다. 근거 의미 일치는 고정 사례 내용 대조로 별도 검수합니다.
4. #855의 실제 분석 출력이 보이는 시연을 유지하고 미지원/미검증·가상 예시를 분명히 합니다. 팀 통합 전에는 개인 후보로 보고합니다.

외부 인용 방식은 [출처·계산 근거 점검](2026-11-09_출처와계산근거인용점검.md), 실행 범위는 [실제 출하·정산 계획](../계획/실제출하와정산기록개발검토.md)에 연결했습니다. 이번에는 문서 검토/수정만 했고 제품 구현·모델 재호출·센터 실측·팀 합의 갱신은 하지 않았습니다.
