2026-11-09 KST. 로컬 `dev/juneok`, 사용자 설정 `gpt-6-luna`와 제품 `.env`로 실행했습니다. 키·인증 헤더는 기록하지 않았고 원격 push·PR·병합은 하지 않았습니다.

## 방향과 링크 검토

단일 모델이 질문·도구를 선택하고 Python이 조건·계산·출처·최종 수치를 통제하는 출하 의사결정 지원 Agent를 유지합니다. 이번에는 하네스와 도구의 접점, 사용자 결과, 평가를 개선했습니다. 다른 작물·생애주기 확장은 별도 기록으로 유지합니다.

사용자가 준 [DAKER 해설 글](https://daker.ai/community/jeju-ai-agent-challenge-expert-score-gtx1060)은 완성도·편의성과 센터 실행을 우선하는 참고자료로 사용했습니다. 해설의 해석을 공식 규정으로 취급하지 않았습니다. [공식 공지](https://daker.ai/public/hackathons/jeju-ai-bigdata-agent-challenge)에서 비전문가의 직접 사용, 필수 제주 데이터 1종 이상, i7-8700·GTX 1060·RAM 32GB, 외부 API 의존성·매뉴얼·검증 결과 명시 요건을 대조했습니다.

여러 Agent·새 프레임워크·로컬 대형 모델 도입보다 현재 Python/API 구조의 실행·대화·재현성을 개선하는 것이 적합하다고 판단했습니다. 모델 추론은 외부 API에서 수행하므로 로컬 GPU를 사용하지 않습니다. 실제 센터 PC·네트워크에서 검증했다는 뜻은 아닙니다.

완료 신호는 입력·데이터 오류를 성공으로 바꾸지 않습니다. `INVALID_INPUT`·`DATA_ERROR`에서는 복구 기회를 유지합니다. 자료 없음·추가 조건 필요는 정상적인 업무 결과로 안내합니다. 복합 요청의 중간 도구는 false, 마지막 도구만 true로 실행합니다.

`provenance`의 `conversation_extraction`은 해당 대화에서 모델이 값을 추출했다는 뜻입니다. 진술의 사실성·감모의 농학적 타당성을 확인한 기록은 아닙니다. 가정·관측·사용자 확인의 더 세밀한 구분은 후속 과제입니다.

## 남은 한계와 최신 후속 계획

자동 검사는 수치·조건 변경·자료 전제·보고서 일관성을 확인합니다. 농가에게 질문이 쉬운지, 핵심 입력을 확보할 수 있는지, 엑셀보다 유용한지는 아직 입증하지 못했습니다. 대화 상태는 현재 세션 메모리이며 재시작 후 자동 복원하지 않습니다. 시간 제한은 루프 경계·SDK 요청 제한이며 정확한 벽시계 강제 종료 보장은 아닙니다.

1. **자료 최신화·적합성:** 현재 가격 2026-11-03, 출하자료 2025-09-17까지. 공식 수집/내보내기 경로·단위·품종·거래조건·이용조건을 확인하고 검증 후 CSV와 manifest 교체. 확보 전에는 사용자 제시가격과 관측일을 밝힌 과거 자료 사용.
2. **가정 범위 비교:** 사용자가 정한 감모·미래가격 범위의 민감도와 다음 확인 사항 제공. 모델이 가정을 만들지 않고 예측 모형으로 표시하지 않음.
3. **사용자 과제:** 팀원·비전문가의 동일 자료 수기/엑셀 대비 시간·누락·입력 부담·이해도 기록. 농가 검증과 구분. 핵심 입력 확보가 어렵다면 대상 사용자·업무 흐름 재검토.
4. **센터 재현·제출:** 새 Windows 설치, 실제 PC·네트워크·API 키 제공 주체, 장애 안내, 필수 데이터 활용 시연, 기획서·매뉴얼 검수. 키가 없는 직접 도구 실행과 실제 자연어 Agent 실행을 구분.

모델 교체·다중 Agent·장기 세션 저장·범용 작물 확장은 평가에서 필요가 확인될 때 추가합니다. 현재 모델이 모든 후보보다 적합하다고 판정한 것은 아닙니다.
