# 실제 출하 기록 A·정산 검산 B 구현·검증

아래는 A+B 최초 구현 시점의 검증입니다. 이후 동의 체크 제거·금액 없는 모델 이력으로 변경한 현재 판정은 [발표 정리 검증](2026-11-09_발표흐름과로컬정산정리.md)을 봅니다.

2026-11-09 KST / dev/juneok 로컬 후보. 승인한 A+B와 해당 기능의 citation을 구현했습니다. 기존226개를 보존하고 신규31개를 더한257개가 통과했습니다. 원격 게시·팀 채택·실제 농가 검증을 의미하지 않습니다.

## 구현과 범위

- `settlement.py`: 기존 ScenarioStore/비교 JSON과 분리한 단일 출하 기록. 원래 비교 snapshot·내용/자료 버전 해시·선택 대안 고정, 최대50개 확인 이력, 입력 경로·수정 버전. 종류별 최대12개 판매/공제/외부 비용 행. 형식은 `jeju-shipment-record` v1·최대1MiB입니다.
- `settlement_ui.py`: 키 없는 수동 카드→확인·저장→부분 검산/차액·근거 보기→개인 JSON/PDF. 복원·삭제는 명시적이며 서버 자동 저장하지 않습니다. 새 비교 시작은 출하 기록도 비웁니다. 원문 정산서/OCR·이름·계좌·연락처 필드는 추가하지 않았습니다.
- `reconcile_settlement`: 확인한 기록을 모델 전송 동의 후 읽기 전용 검산합니다. 기록/동의가 없으면 카드 안내, 버전이 다르면 오류입니다. 동의는 정확한 기록 내용 해시에 묶여 정정 시 무효가 됩니다. 자연어 금액의 자동 저장과 원래 가정 대조는 미구현입니다.
- `settlement_reporting.py`: 프로그램이 입력/계산 근거 레지스트리를 만들고 핵심 수치에 참조합니다. 경로·원문 파일명/임의 URL을 인용하지 않습니다. 대화·미리보기·PDF·JSON은 같은 ID/금액을 사용하며 복원 시 계산/근거를 재생성·대조합니다.
- 기존 공개 출처 URL은 PDF에서도 클릭 가능하게 했고 오프라인용 주소 텍스트도 유지합니다. 정산 계산에는 공공 시세/출하량을 개인 지급·입금의 증거로 붙이지 않습니다. 기존 관측 도구 전체를 같은 레지스트리로 통일한 것은 아닙니다.

입력 미확인과0을 구분합니다. G-D와 정산서 지급액N을 대조하고, N에서 정산 공제를 다시 빼지 않습니다. N-E는 외부 비용을 모두 확인하고 이중 차감 미해결이 없을 때 제공하는 ‘입력 비용 반영금액’입니다. 전체 순이익이 아닙니다. 입금은 별도 사용자 입력이며 은행 확인이 아닙니다. 출하/판매중량 차이는 자동 감모로 분류하지 않습니다. 같은 비용 범주가 양쪽에 있으면 서로 다른 비용인지 확인하며 동일 항목 ID는 확인 체크만으로 무시하지 않습니다. 음수·반품·추가 정산·여러 날짜 재고 최적화는 지원하지 않습니다.

## 가상 독립 정답

판매중량2940kg, 매출9702000원, 정산서 공제485100원+60000원, 정산서 지급액9156900원, 별도 보관비140000원이라는 가상 기록을 사용했습니다. 검산 지급액9156900원, 정산 차액0원, 입력 비용 반영금액9016900원입니다. 지급액을9000000원·입금을8900000원으로 바꾸면 정산 차액-156900원·입금 차액-100000원·입력 비용 반영액8860000원입니다. 수수료485100원은 가상 입력이며 공식 수수료5%의 적정성 검증이 아닙니다.

## 수정 루프

1. 처음 검증 명령을 파일 경로로 실행해 프로젝트 import가 실패했습니다. 기존 제품 모듈 실행 방식(`python -m scripts.verify_juneok`)으로 수정했습니다. 제품 계산 오류가 아닙니다.
2. UI 실행은 제한 환경에서 Python 로컬 socketpair 생성에 멈췄습니다. traceback으로 확인하고 허용 환경에서 재실행해 통과했습니다. 테스트 실패를 제품 성공으로 바꾸지 않았습니다.
3. JSON의 정렬된 키 순서 때문에 복원 후 근거 ID가 달라지는 문제를 발견해 필드 순서를 결정적으로 고정했습니다. 저장·복원 전후 ID 일치/변조 결과 거부를 검사했습니다.
4. 정산 카드 수정이 화면 아래에서 감지되면 위쪽 대화/보고서에 이전 금액이 먼저 보일 수 있어, 화면 상단에서 편집을 먼저 검사하고 이전 결과를 비웠습니다. 동의도 기록 해시에 묶었습니다.
5. 수정/삭제 시 개인 PDF 외에 기존 보고서 캐시도 제거하고 전송 동의 철회가 같은 화면에서 즉시 반영되게 했습니다. 저장·수정·철회 UI 여정으로 검증했습니다.
6. 보관 대안 ID가 current일 때 즉시 출하와 혼동할 수 있어 선택 종류와 실제 option_id를 구조적으로 분리했습니다. 기존 임의 ID 계약을 유지합니다.
