# 자료 탐색·허용 조건 역산·변경 검토 검증

2026-11-09 KST / 개인 후보. 사용자가1·2번 개발 후 검증 통과 시3번까지 이어가도록 승인했습니다. 기존188개와 공통 CSV/전처리·가격/감모/비용 계약·공유 상태를 유지 기준으로 삼았습니다.

UI는 키 없이 탐색·선택·역산·변경 검토를 제공하고 동일 도구/ScenarioStore를 사용합니다. 탐색의 상위 선택을 바꾸면 종속 선택을 비우고, 대화 탐색 결과를 탐색 카드에 반영합니다. 역산/탐색 편집 중 이전 결과를 숨기며 조건 카드 미저장 초안이 있으면 실행을 막습니다. 입력 데이터와 자료 버전이 달라지면 현재 보고서로 내보내지 않는 기존 계약을 유지합니다.

변경 검토 파일은 명시적 버튼으로 선택하며 임의 경로를 모델에 제공하지 않습니다. 새 비교·예시 불러오기·복원 때 이전 기준 파일 연결을 비웁니다. 대화만 지우기는 선택한 기준을 유지합니다. 자료가 바뀐 과거 파일도 비교할 수 있으나 버전 차이를 표시하고 CSV 관측을 자동 재조회하지 않습니다. 현재 조건을 바꾸는 복원 버튼은 별도 동작입니다.

## 숫자·계약 검증

- 가상3000kg·현재3000원/kg·7일·일 보관비20000원에서3300원 가정의 감모 상한은7.6767…%. 보수 표시7.67%이며 기존 전방 계산에서7.67%의 차이는+670원,7.68%는-320원입니다.
- 감모2%를 고정한 일 보관비 상한은100285.714…원, 보수 표시100285원입니다.100286원은 경계를 넘습니다. 감모 상한과 비용 상한을 동시에 사용할 수 없습니다.
- 0가격·음수 현재 비교금액·가능한 비음수 해 없음·전체 허용영역·gross 수수료·항목별 비용·보관비 이중계상·미확인/철회·다른 미완성 대안·가격 기준 변경을 검사했습니다.
- 저장 감모2%와 현재4%는 현재 계산 규칙에서3109→3174원/kg, 차이65원/kg입니다. 원인/수익 효과를 추정한 값은 아닙니다.
- 보관된 임의 숫자999999999를 넣어도 재계산/출력에 쓰지 않는 검사, v1/v2·잘못된 파일·오래된 버전·추가/삭제 대안·동등 수치/확인 플래그·누락/부분 결과 검사를 포함합니다.

## 실패와 보완 루프

1. 최초 신규 검사에서는 2025년9월 노지온주가 있다고 잘못 가정해 실패했습니다. 실제 후보는 하우스온주이며 부분월 경고를 확인하도록 정정했습니다.0과0.00 표기 검사는 숫자 동등성을 사용했습니다. 수입한 테스트 클래스가 중복 발견되는 것도 제거했습니다.
2. 기존188+신규22개 전체210개를 통과했습니다. 첫 실모델12회 중1회는 역산용 미래가격을 현재 조건에 저장해 실패했습니다. 가정은 도구 인수에만 전달하도록 지침을 보강하고, 역산 후 기존 전방 계산이 풀 대상의 미확인 값을 요구하지 않게 수정·회귀를 추가했습니다.
3. 다음 평가의1회는 입력은 동일하지만 무의미한 update가 버전/일회성 확인 플래그만 바꿔 전체 snapshot 검사에서 실패했습니다. 평가를 실제 경제 입력과 버전 변경 진단으로 분리했습니다. 미래가격이 저장되면 계속 실패하는 음성 검사를 추가했으며 직접 역산 도구는 전체 상태 불변을 별도 검증합니다.
4. 전체212개와 신규 한국어6종×3회18/18을 확인하고3번으로 진행했습니다. PDF 이미지에서 입력 표의 빈 줄 때문에 표가 문자로 출력되는 문제를 고쳐 관련24개가 통과했습니다.
5. 변경 검토 신규12개와 전체224개가 통과했습니다. 마지막으로 저장된 미래가격과 이번 역산 단가가 다를 때 이번 단가를 표시하는 회귀1개를 더했습니다. 최종225개·모델·분리본 판정은 아래 원시 기록을 기준으로 합니다.
6. 최종 기존 모델 재실행의J25가 복수 감모 가정표 대신 단일 비교를 호출해24/25였습니다. 실제 요구 미충족으로 판정했으며 평가 기준을 완화하지 않았습니다. 단일 조건 비교/복수 가정표/허용 상한 역산의 도구 선택 지침을 보강하고 J25 반복 확인 후 전체를 재실행합니다. 실행별 실패를 보존합니다.

8. 최종 신규8종×3회는 자료 종류와5kg 중량까지 직접 검사해24/24, 맥락 반복18/18입니다. 마지막 기존25종은21건 성공 후4건이 APIConnectionError로 요청 단계에서 실패했습니다. 같은 소스/원시자료 해시·동일 과업을 확인하고 실패4건만 재시도해 모두 통과했습니다. 한 번의25/25로 표시하지 않고21건+연결 실패4건 재시도를 별도 판정에 연결합니다.
