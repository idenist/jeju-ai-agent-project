## 제품의 혼동 제거

기본 대화 검산의 모델 전송 동의 체크를 제거했습니다. 카드에서 확인한 기록은 로컬 Python이 읽고 전체 금액/근거는 기존 대화 렌더러·PDF·JSON에 표시합니다. Agent의 function_call_output에는 model_receipt의 고정 필드(status, analysis_type, record_revision, local_result_displayed, 안내)만 넣습니다. 상세 금액/입력/근거/원래 snapshot·해시는 넣지 않습니다. 후속 도구 호출·다음 사용자 턴에도 같은 이력만 전달하므로 금액을 나중에 다시 노출하지 않습니다.

이는 **카드의 상세 정산 기록**에 대한 경계입니다. 직접 쓴 채팅과 기존 출하 비교 조건은 모델 입력입니다. 사용자가 실제 금융정보를 직접 입력해도 차단한다는 뜻이 아니고 전체 서비스의 비전송/익명성 보증도 아닙니다. 로컬 입력 확인·정정·버전 검사·PDF/JSON·누락/중복/입금 구분은 유지했습니다. 정산 자유 해석을 위해 모델에 원문을 보내는 별도 기능은 추가하지 않았습니다.

- FakeClient로 finish_turn=false 뒤 후속 모델 요청 및 기록 수정 후 다음 턴을 재현했습니다. 실제 provider 요청에 매출/지급/비용·금액 필드·citation이 없고 사용자 화면에는 최신 검산값이 있는지 검사했습니다.
- 전체 자동 회귀257개가 통과했습니다. 탭 부재를 고정하던 불필요한 assertion1개만 제거했고 테스트 함수 수를 줄이기 위한 재작성은 하지 않았습니다. 금액/상태·근거·키 없는 흐름은 유지합니다. 분리 패키지 판정은 artifacts/package-shared-latest.json을 확인합니다.
- 발표 주 여정을 실제 모델로 한 번 수행했습니다: 대화3109→카드감모4%3174→다음대화3174, 기간3일로 바꾸면 재확인→3082, PDF 동일 값/버전. 이는 실제 모델을 쓴 자동 과업이며 사람 리허설 시간/이해도를 검증한 것은 아닙니다.
