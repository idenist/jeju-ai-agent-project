## 적정성 판정

257개가 존재하는 것은 확인됐고 자동 실행비용은 작습니다. 금액 정답·수수료/비용 이중 차감·미확인과0·철회/버전·불변 기준·잘못된 파일·진위 과장 방지 검사는 유지 가치가 높습니다. null/0을 계산과 카드·저장·보고서에서 각각 검사하는 것은 다른 연결 오류를 막을 수 있어 이름이 유사하다고 모두 중복은 아닙니다.

다만 MVP에 비해 테스트/보고 운영이 무거워진 부분이 있습니다. 다음은 정리 후보이며 이번에 삭제하지 않았습니다.

- test_juneok_ui.py의 test_keyless_screen_has_offline_tools_and_disabled_chat 안 `app.tabs == []`는 사용자 결과보다 현재 레이아웃 구조를 고정합니다. 키 없는 실행/대화 비활성 검사는 유지하고 탭 부재 고정은 제거 후보입니다.
- ‘3109·9000000·실행 미확인’ 문자열은 ReportTests의 기본 보고서 검사, UiWorkflowTests의 보고서 맥락 검사, PdfTests의 PDF 검사에서 반복됩니다. 금액이 각 경계를 통과하는지는 의미가 있지만 모든 동일 문구를 각 층에서 재검사할 필요는 없습니다. 층마다 독립 역할을 남기고 공통 장문/정확한 문구 의존은 줄일 후보입니다.
- ‘257개 통과’만 앞세우면 사용성/실용성이 검증된 것처럼 읽힙니다. 앞으로는 핵심 위험이 무엇이고 어떤 경로를 검사했는지를 먼저 보고하고 함수 수는 부록으로 둡니다.
- 일상 변경은 영향받는 검사, 계산/상태/저장/하네스 변경은 전체 회귀, 모델 입력/도구 계약 변경은 관련 모델 과업, 배포 패키지 고정은 분리 실행으로 범위를 맞춥니다. 문서/단순 배치 수정마다 유료6×3+25+8을 반복하지 않습니다.

이는 정적 내용 검토에 따른 판단이며 전체257개가 최소·충분하다는 입증이나 형식적 중복/변이 테스트 결과는 아닙니다. 이미 통과하는 검사를 숫자를 줄이기 위해 재작성하는 작업도 우선하지 않습니다.

## citation과 모델 전송을 분리한 정정

이전 답변에서 citation 설명에 ‘모델 전송 별도 동의’를 이어 붙인 것은 부정확했습니다. citation 레지스트리·계산·카드/PDF/JSON 표시는 로컬 Python에서 동작하며 이 체크나 모델 호출이 필요하지 않습니다.

현재 settlement_ui.py의 체크는 **카드에 저장된 정산 정보를 대화 도구에서 사용할지** 결정하는 개인 설계입니다. 금융 금액이 대화 결과에 들어가 후속 모델 입력으로 이어질 수 있어 추가했으며 공식 대회가 ‘매번 동의’를 요구한다는 근거는 없습니다. 기본 미동의이고 기록 수정 시 해제가 됩니다. 일반 대화 전체를 통제하는 장치는 아닙니다. 사용자가 채팅에 직접 쓰는 금액과 기존 비교 조건은 평소 모델 입력 경로로 들어갑니다.

전송 시점도 구분합니다. 첫 요청에는 정산 카드의 상세 금액 대신 기록 유무/버전/동의 상태만 넣습니다. 도구의 검산 결과는 Python에서 만들어 function_call_output으로 대화 이력에 추가합니다. finish_turn=true로 종료하면 그 턴의 검산 결과를 다시 모델에 보내지 않고 화면에 바로 표시합니다. 반면 추가 도구 호출/후속 턴에서는 저장된 tool output이 모델 입력에 포함될 수 있습니다. 따라서 체크를 곧바로 ‘매번 정산 금액을 전송하는 버튼’으로 설명해서도 안 됩니다.

더 적합한 후속 설계는 기본 대화 검산도 ‘모델은 도구 선택, Python은 금액 계산/citation/표시’를 끝까지 유지하고 모델 쪽 대화 이력에는 금액 없는 처리 상태를 전달하는 방식입니다. 실제로 모델에 상세 정산 해석을 요청하는 기능을 둘 경우에만 전송 범위를 분명히 안내하는 선택을 검토합니다. 카드 검산 자체를 동의 절차로 막을 이유는 없습니다. 현재 구현은 카드 검산을 막지는 않지만 대화 검산까지 선택을 요구하므로 그 UX는 줄일 여지가 있습니다.

이 문서는 재검토 결과이며 자동 테스트 삭제·동의 흐름/모델 이력 구조 변경은 아직 하지 않았습니다. 팀 공통 저장/전송 정책은 계속 미합의로 구분합니다.
