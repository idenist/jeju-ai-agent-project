# 출처와 계산 근거 인용 점검

2026-11-09 KST / 기준: dev/juneok 6c0ff9c. 사용자 승인 방향은 실제 출하 기록 A + 정산 검산 B입니다. 이번 점검은 개발 전 citation 요구를 보완하며 제품 기능은 변경하지 않습니다.

## 판정

출처 URL·관측시점 표시의 기반은 있으나 **핵심 수치에서 원자료·입력 버전·계산식으로 이어지는 추적은 보완해야 합니다.** 출처를 나열하는 것과 그 출처가 개별 주장을 뒷받침하는 것은 다릅니다. 모든 계산값에 외부 웹 문헌을 붙이는 대신 자료, 사용자 입력, 계산 근거를 구분합니다.

## A+B에 적용할 근거 계약

1. **공공 관측 자료:** 자료 ID, 제공처/원문 URL, 관측일과 조회 조건, 파일 내용 해시, 집계·변환 방식. 페이지 수정일과 실제 관측일을 별도 표기합니다.
2. **사용자 입력:** 입력 ID/필드/기록 버전, 수동·대화 초안 등 입력 경로와 확인 상태. “사용자 확인”은 외부 기관의 진위 확인이 아닙니다. 과거 가정을 실제 값으로 승격하지 않습니다.
3. **파일 근거:** 실제 제공된 파일이 있을 때만 파일명/해시와 확인 가능한 행·페이지·필드를 참조합니다. 첫 A+B는 수동 카드·JSON 범위이며 정산서 OCR/은행 연동을 추가하지 않습니다. 파일 해시는 동일성 확인이며 진실성을 보증하지 않습니다.
4. **계산 근거:** 계산 ID, 식/규칙 버전, 고정된 입력 참조, 단위/반올림/비용 포함 범위. G-D와 정산서 지급액N의 대조, N-E의 외부 비용 반영을 각각 설명합니다. 미입력 비용을0으로 간주하지 않습니다.
5. **표시:** 핵심 금액 옆에 [입력1]·[계산1]처럼 짧은 참조를 두고 상세 근거를 펼쳐 보게 합니다. PDF에는 같은 ID의 근거 목록과 공개 URL, JSON에는 같은 구조를 보존합니다. 공개 URL은 클릭 가능하게 개선하되 오프라인에서도 주소를 읽을 수 있어야 합니다. 개인 파일 경로나 계좌 정보는 공개 URL로 만들지 않습니다.
6. **변경과 신뢰:** 입력 정정 시 연결된 계산을 무효화/재계산하고 이전 버전은 남깁니다. 가져온 파일의 인용은 검증할 데이터이며 실행 지시가 아닙니다. 외부 링크는 http/https만 허용하고 LLM이 만들어낸 출처를 근거로 채택하지 않습니다.

## 통과 조건과 우선순위

A의 스키마/저장 단계부터 입력 근거와 버전을 넣고, B에서 계산 근거와 PDF/JSON 공통 참조를 연결합니다. 그다음 기존 관측 자료 도구에도 같은 구조를 확장합니다. 출처 목록을 늘리는 것보다 근거가 없는 핵심 금액을 없애는 것이 우선입니다.

- 없는 참조·중복 ID·다른 기록/버전 연결·변경 전 계산 재사용을 탐지할 것.
- 가정/미확인/실제라고 입력한 값이 섞여도 상태를 보존하고, 파일 미제공 시 페이지·정산서 근거를 꾸미지 않을 것.
- 같은 입력에서 UI·PDF·JSON의 금액/근거 ID/자료 버전이 일치할 것.
- 공공 시세로 개인 입금을 증명하거나 가상 수수료에 공식 근거를 붙이는 사례를 거부할 것.
- 외부 URL 도달성, 계산 재현, 출처가 해당 주장을 지원하는지의 세 검사를 구분할 것. 네트워크 실패는 자료 부재와 구분할 것.

이는 앞으로의 구현 완료 기준입니다. 현재 citation 보강이 구현됐다는 판정은 아닙니다. 팀 합의 항목은 공통 근거 스키마 채택, 자료 재배포/출처 표기 정책, 실제 양식 확보·시연 범위입니다. 개인 A+B 구현과 분리합니다.

## 추가 검토: 대화 답변마다 citation을 붙일 것인가

사용자 후속 요청에 따라 답변 유형별 표시 정책을 정리했습니다. **자료·금액·판단을 담은 답변마다 근거 확인 경로를 제공하고, 단순 질문/확인에는 생략합니다.** 모든 답변에 외부 URL을 의무화하지 않습니다. 아래는 제품 설계 판단이며 농가 사용성 실험으로 입증한 정책은 아닙니다.

참고한 [ALCE 논문 §3.3](https://aclanthology.org/2023.emnlp-main.398.pdf)은 주장이 인용 근거로 지원되는지와 불필요한 인용이 있는지를 구분해 평가합니다. 해당 연구는 문헌 기반 질의응답이며 우리 제품의 계산/정산 UI 효과를 직접 검증한 자료는 아닙니다. 여기서는 인용 개수보다 근거의 지원 범위와 누락 여부를 점검하는 원칙을 참고합니다.

| 답변 유형 | 표시 정책 | 확인할 근거 |
| --- | --- | --- |
| 과거 시세·출하량·거래규격 조회 | 주장/수치 옆 자료 참조 필수 | 조회 결과, 조건, 관측일, 파일 버전/해시, 집계 방식과 원문 URL |
| 비교·허용조건 역산·정산 검산 | 금액/경계값 옆 계산 참조 필수 | 확인한 입력 버전, 가정, 식/규칙, 단위/반올림. 실제 사용하지 않은 공공자료를 붙이지 않음 |
| 조건부 해석·다음 확인 항목 제안 | 판단임을 표시하고 그 판단을 지원하는 자료/계산 참조 | 관측 사실, 사용자 가정과 해석을 한 문장에 섞지 않음. 독립 근거 없는 확신/수익효과 주장 금지 |
| 입력값 확인·수정 완료 | 짧게 확인, 외부 citation 생략 | 변경된 필드/값과 버전으로 확인. 이후 계산에는 해당 입력 참조 필요 |
| 누락 정보 질문·인사·사용 안내 | 인용 기본 생략 | 구체적 사실 주장이 포함될 경우 그 주장에만 근거 표시 |
| 자료 없음·도구 실패·오래된 결과 | 이유/조회 범위/확인 시점 표시 | 실패 결과와 시도한 조건. 성공한 관측 자료처럼 인용하거나 과거 결과를 최신 근거로 재사용하지 않음 |

화면은 핵심 문장 옆 [자료1]/[계산1]과 답변 아래 ‘근거 보기’로 상세를 펼치는 구성을 우선합니다. 같은 답변 안에서 같은 근거의 긴 서지는 한 번만 표시하지만, 후속 답변도 참조를 열면 당시 고정된 근거를 볼 수 있어야 합니다. PDF/JSON은 기존 계약대로 같은 ID를 보존합니다. 세션 밖 복원 시에도 참조가 끊기지 않아야 합니다.

현재 agent.py는 자유 생성한 최종 문장으로 시장 사실/금액을 확정하지 않고, 선택된 도구 결과를 render_dialogue/report_for로 표시합니다. 이 경로를 유지하며 Python이 만든 근거 레지스트리의 ID만 렌더러가 연결하도록 설계합니다. LLM이 URL이나 ID를 임의 생성해 표시하는 흐름은 넣지 않습니다. 일반 용어 설명도 앱 정의와 외부 사실을 구분합니다. 매 답변 웹 검색은 필요하지 않으며 센터의 CSV 기반 실행을 유지합니다.

추가 통과 사례: 숫자 답변에 근거가 없음, 유효 ID지만 다른 조건의 자료를 연결, 계산 입력 수정 후 이전 근거 연결, PDF/복원 시 참조 소실, 질문만 하는 답변에 무관한 출처 첨부를 검사합니다. 자동 구조 검증만으로 주장-근거 의미 일치를 입증했다고 표시하지 않고 고정 사례의 내용 대조도 수행합니다.
