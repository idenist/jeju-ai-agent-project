### Git에서 보존하는 것과 보존하지 않는 것

- **보존:** UI·계산·분석·보고서 코드, 테스트, 시즌별 집계 CSV, 품질보고서.
- **별도 보존 필요:** `data/seasons/<시즌>/raw/`에 보관한 원본 CSV는 로컬 원본 데이터 보존 정책 및 실제 Git 추적 여부를 별도 확인해야 합니다. 원격에 집계 파일이 존재한다는 사실로 원본 전체의 백업이 보장되지는 않습니다.
- `.gitignore`에 `.env`, `secrets.toml`, 가상환경, `artifacts/`, `output/` 제외 규칙이 존재합니다. 민감정보가 다른 이름으로 올라가지 않았는지 커밋 시 계속 확인합니다.

### 이미 확인된 기술적 구조

- 화면 진입점 `app.py`에 `대화 / 직접 입력 / 자료·도구` 3개 상위 탭과 `오늘과 나중 / 두 미래 출하안 비교` 하위 탭이 공존합니다.
- `FuturePairState.current_result()`는 조건 및 가격 자료 변경 상황에서 낡은 비교 결과를 그대로 현재 결과로 사용하지 않도록 상태를 관리합니다.
- `seasonal_threshold_ui.py`가 계산 결과와 사용자가 지정한 거래규격·시즌 자료 개정 상태를 연결합니다.
- `future_pair_ui.py`는 시장 근거를 보고서 엔트리로 묶고 PDF·JSON에 전달합니다.
- `market_export.py`는 시장 근거가 미조회/비교불가일 때 이를 임의 관측 결과로 대체하지 않습니다.

## 5. 사용자 PC에서 끝내야 할 최소 확인

프로젝트 루트 `C:\SKN projects\jeju`에서 **Windows CMD**로 실행합니다.

**① 커밋·푸시 및 변경 파일 상태**

```cmd
git fetch origin integration/agents && git branch --show-current && git status --short && git rev-parse --short HEAD && git rev-parse --short origin/integration/agents
```

- 출력 브랜치가 `integration/agents`인지 확인합니다.
- `git status --short`에 항목이 없고, 두 SHA가 같으면 **로컬과 원격의 현재 기준점이 일치**합니다.
- 차이가 있다면 즉시 커밋하거나 덮어쓰지 말고 먼저 변경 내용을 확인합니다.

**② 우선 회귀 테스트(한 줄)**

```cmd
python -m unittest discover -s tests -p "test_seasonal_prices.py" -q && python -m unittest discover -s tests -p "test_seasonal_threshold.py" -q && python -m unittest discover -s tests -p "test_market_export_report.py" -q && python -m unittest discover -s tests -p "test_integration_future_pair.py" -q && python -m unittest discover -s tests -p "test_integration_ui_journey.py" -q
```

- 모든 명령에 `OK`가 표시돼야 합니다. 실패하면 **기준점의 실제 결함**으로 기록합니다.
- 이 단계에서는 기존 기능을 수정하거나 새 UI 패치를 적용하지 않습니다.
