# 출하 판단 Agent 제품 방향 및 실행 계획

작성 기준일: 2026-11-16

## 제품이 해결할 문제

농가가 가진 물량과 출하 가능 기간을 바탕으로 **지금 출하하는 선택과 기다리는 선택을 비교하고, 무엇이 결론을 바꾸는지 설명한다.** 사용자가 모르는 값을 모두 입력해야만 작동하는 계산기가 되어서는 안 된다.

## 대화와 결론 원칙

- 먼저 사용자의 질문과 대화 맥락에 답한다. 가격 조회, 출하 조언, 용어 설명, 손익 계산을 구분한다.
- 이미 받은 값은 다시 묻지 않는다. 미확인 값은 비워 두고, 비교를 실제로 바꿀 핵심 값만 하나씩 확인한다.
- 사용자가 모른다고 하거나 입력 부담을 말하면 질문 수집을 멈춘다. 확인된 값으로 계산할 수 있는 손익분기 조건과 모르는 값이 결론에 주는 영향을 설명한다.
- 가격 자료는 사용자가 지정한 날짜·기간·품종에 맞춘다. 짧은 기간 질문에 연간 자료를 덧붙이지 않는다.
- 가격 전망 근거가 충분하지 않으면 특정 날짜를 순위 매기지 않는다. “늦출 이유가 없으니 가장 이른 날” 같은 기본 추천을 쓰지 않는다.
- 미래가격 전망과 농가 실수취액을 구분한다. 예측 구간이 넓거나 A/B 순위가 불확실하면 추천을 보류하고, 손익분기 가격과 판단이 달라지는 조건을 보여준다.

## 제주데이터허브 #855의 역할

제주데이터허브 출하량은 **가격을 직접 예측하는 핵심 엔진이 아니라, 출하 시기 판단에 곁들이는 과거 수급 참고자료**로 사용한다.

- API를 자료 갱신의 필수 원천으로 둔다. API에서 받은 원본을 버전·수집시각·마지막 관측일과 함께 저장하고, 사용 중인 화면에는 자료의 최신성을 드러낸다.
- 대화 중 매번 원 API를 호출하기보다 자료 수집과 사용자 응답을 분리한다. API 장애 때는 마지막 저장본을 쓸 수 있지만 오래된 자료를 최신처럼 표시하지 않는다.
- 사용자가 묻는 출하 날짜와 자료의 품종이 맞을 때 과거 신고 출하량의 한두 가지 요약만 제시한다. 전 기간 표를 자동으로 펼치지 않는다.
- 신고 출하량은 경매시장 반입량이나 농가 보유량이 아니다. 출하 품종과 경매 품종은 확인된 대응표 없이는 연결하지 않는다.
- 가격 예측 변수로 넣을지는 별도 검증 후 결정한다. 시점이 맞는 가격·출하량 자료로 계절을 나눠 검증하고, 가격 오차와 출하 선택의 손익 후회가 기준선보다 안정적으로 개선될 때만 예측 입력으로 채택한다.

현재 저장소의 `jeju_shipments.csv`는 2025-09-17까지의 스냅샷이다. 사용자는 2026-11-17에 제주데이터허브 #855 페이지가 갱신되지 않고 있음을 확인했다. 따라서 최신 파일을 사용자에게 요청하거나 해당 자료를 실시간 공급 신호로 취급하지 않는다. #855는 마지막 관측일까지의 과거 신고 출하량을 보여주는 보조 자료로 한정하고, 응답에 기준일과 자료 종료일을 함께 표시한다.

가격 전망 실험에서는 날짜가 계속 축적되는 경매 가격·거래량을 주 입력으로 사용한다. 제주데이터허브 출하량을 가격 입력으로 넣는 실험은 과거 한 시즌에서만 가능했고 안정적인 개선을 확인하지 못했다. 실제 산지 공급·도매시장 반입량을 더 평가하려면 제주농산물수급관리센터 등 다른 후보의 API 지원 여부, 과거 자료 보존 범위, 이용 조건을 먼저 확인한다. API에서 같은 오래된 자료만 돌려주면 갱신 성공으로 간주하지 않는다.

## 구현 순서

### 1단계 — 대화 신뢰와 입력 부담

- assistant 답변을 조건 버전이 바뀌어도 접지 않고 대화 안에 계속 표시한다.
- 범위가 명시된 질문은 그 범위 안에서 자료를 찾고, 날짜 범위를 벗어난 표를 자동으로 붙이지 않는다.
- 사용자가 “언제 팔까?”라고 물으면 손익계산 입력 폼으로 바로 몰지 않는다. 확인된 시장 자료와 한계를 먼저 설명하고, 결론을 바꾸는 값만 확인한다.
- 근거가 없을 때 임의로 빠른 출하를 권하지 않는다. 가격 예측과 순이익 비교가 없는 상태에서는 “판단 불가”와 필요한 판단 조건을 분명히 말한다.

### 2단계 — 비교 결과를 의사결정에 맞추기

- 확인된 수치로 가능한 부분 결과를 먼저 제공한다.
- 모르는 감모·수수료·보관비는 임의로 0이나 기본값으로 놓지 않는다. 필요하면 사용자가 명시한 가정 또는 손익분기 조건을 이용한다.
- 결론과 함께 주요 근거, 자료의 기간, 불확실성을 짧게 표시한다. 상세 계산과 원자료 표는 사용자가 펼치거나 요청할 때 제공한다.

### 3단계 — 데이터허브 API를 보조 근거로 연결

- #855 API 수집 경로와 자료 갱신 상태를 운영 데이터 계약으로 확정한다.
- 명시한 품종·후보일과 일치하는 경우 과거 신고 출하량 요약을 비교 화면에 보조 근거로 제공한다.
- 현재 API 스냅샷의 날짜 누락과 부분 관측을 노출하며, 없는 날짜를 0톤으로 만들지 않는다.

### 4단계 — 가격전망 실험

- 계절성을 포함한 단순 가격 기준선부터 유지한다.
- 최근 가격 흐름 및 시점이 맞는 출하량을 후보 변수로 추가해 계절 단위의 미래 시점 검증을 한다.
- 점수 하나만으로 자동 추천하지 않는다. 예측 구간, net return 차이, 결론의 안정성까지 확인하고 개선이 없으면 출하량은 참고자료로만 남긴다.

## 이번 수정에서 반영한 범위

- 대화에서 이전 조건 버전의 답변도 접지 않고 읽을 수 있게 한다.
- 데이터허브 출하량의 역할을 보조 근거로 제한하고, 짧은 사용자 질문에 연간 가격표를 덧붙이지 않도록 Agent 지침을 분명히 한다.
- 가격 전망이 없다는 이유로 가장 이른 날짜를 추천하지 않도록 한다.

이 계획은 구현·검증·외부 API 운영 확인 상태를 서로 구분한다. 미래가격 전망은 검증 기준을 통과하기 전까지 운영 추천 기능으로 표기하지 않는다.
