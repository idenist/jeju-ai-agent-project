# 출하 판단 Agent 제품 방향 및 실행 계획

작성 기준일: 2026-11-16

## 제품이 해결할 문제

농가가 가진 물량과 출하 가능 기간을 바탕으로 **지금 출하하는 선택과 기다리는 선택을 비교하고, 무엇이 결론을 바꾸는지 설명한다.** 사용자가 모르는 값을 모두 입력해야만 작동하는 계산기가 되어서는 안 된다.

## 대화와 결론 원칙

- 먼저 사용자의 질문과 대화 맥락에 답한다. 가격 조회, 출하 조언, 용어 설명, 손익 계산을 구분한다.
- 이미 받은 값은 다시 묻지 않는다. 미확인 값은 비워 두고, 비교를 실제로 바꿀 핵심 값만 하나씩 확인한다.
- 사용자가 모른다고 하거나 입력 부담을 말하면 질문 수집을 멈춘다. 확인된 값으로 계산할 수 있는 손익분기 조건과 모르는 값이 결론에 주는 영향을 설명한다.
- 가격 자료는 사용자가 지정한 날짜·기간·품종에 맞춘다. 짧은 기간 질문에 연간 자료를 덧붙이지 않는다.
- 가격 전망 근거가 충분하지 않으면 특정 날짜를 순위 매기지 않는다. “늦출 이유가 없으니 가장 이른 날” 같은 기본 추천을 쓰지 않는다.
- 미래가격 전망과 농가 실수취액을 구분한다. 예측 구간이 넓거나 A/B 순위가 불확실하면 추천을 보류하고, 손익분기 가격과 판단이 달라지는 조건을 보여준다.

## 제주데이터허브 #855의 역할

제주데이터허브 #855는 **과거 같은 시기의 신고 출하량을 조회하는 데** 쓴다. 확보한 `data/raw/jeju_shipments.csv`를 전처리한 일별·월별 집계를 이용한다. 관측 기간은 2018년 1월 1일부터 2025년 9월 17일까지다.

- 두 출하일이 정해지면 ‘같은 날짜의 과거 출하량 보기’에서 품종별 조회를 제공한다. 요약에는 후보일 주변 7일 출하량, 비교 연도와 출처가 나온다. 상세 결과에 원본 관측 기간을 표시한다. ‘자료·도구 → 자료 조회 → 과거 출하자료’에서는 월별 기록을 조회할 수 있다.
- 조회에는 신고 통계에 기록된 품종을 사용한다. 미관측 날짜는 결측으로 표시한다.

`data/seasons`는 여러 시즌의 경락가 조회와 손익분기 단가 비교에 사용한다. #855 출하량을 보탠 가격 예측 실험에서 안정적인 성능 개선을 확인하지 못했다. 가격·감모 연구 기록은 Git 커밋 `f8c3303`에 보존한다.

## 구현 순서

### 1단계 — 대화 신뢰와 입력 부담

- assistant 답변을 조건 버전이 바뀌어도 접지 않고 대화 안에 계속 표시한다.
- 범위가 명시된 질문은 그 범위 안에서 자료를 찾고, 날짜 범위를 벗어난 표를 자동으로 붙이지 않는다.
- 사용자가 “언제 팔까?”라고 물으면 손익계산 입력 폼으로 바로 몰지 않는다. 확인된 시장 자료와 한계를 먼저 설명하고, 결론을 바꾸는 값만 확인한다.
- 근거가 없을 때 임의로 빠른 출하를 권하지 않는다. 가격 예측과 순이익 비교가 없는 상태에서는 “판단 불가”와 필요한 판단 조건을 분명히 말한다.

### 2단계 — 비교 결과를 의사결정에 맞추기

- 확인된 수치로 가능한 부분 결과를 먼저 제공한다.
- 모르는 감모·수수료·보관비는 임의로 0이나 기본값으로 놓지 않는다. 필요하면 사용자가 명시한 가정 또는 손익분기 조건을 이용한다.
- 결론과 함께 주요 근거, 자료의 기간, 불확실성을 짧게 표시한다. 상세 계산과 원자료 표는 사용자가 펼치거나 요청할 때 제공한다.

### 3단계 — 제주데이터허브 과거 출하량 제공

- 기존 #855 일별·월별 집계로 과거 출하량 조회를 제공한다.
- 사용자에게 보여주는 결과의 출처·관측 종료일·단위를 명시한다.
- 관측이 일부인 구간에는 관측일 수를 함께 표시한다.

### 4단계 — 가격전망 실험

- 계절성을 포함한 단순 가격 기준선부터 유지한다.
- 최근 경락가와 시장 거래량으로 계절 단위의 미래 시점 검증을 한다. 날짜와 규격을 맞출 수 있는 새 자료를 확보하면 추가 효과를 평가한다.
- 예측 구간, 농가 실수취액 차이, 출하 선택의 안정성을 함께 확인한 뒤 추천에 연결한다.

## 이번 수정에서 반영한 범위

- 대화에서 이전 조건 버전의 답변도 접지 않고 읽을 수 있게 한다.
- 데이터허브 출하량의 역할을 보조 근거로 제한하고, 짧은 사용자 질문에 연간 가격표를 덧붙이지 않도록 Agent 지침을 분명히 한다.
- 가격 전망이 없다는 이유로 가장 이른 날짜를 추천하지 않도록 한다.

이 계획은 구현·검증·외부 API 운영 확인 상태를 서로 구분한다. 미래가격 전망은 검증 기준을 통과하기 전까지 운영 추천 기능으로 표기하지 않는다.
