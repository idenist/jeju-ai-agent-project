# 01. 요구사항 및 기능 명세서

> **기준:** 2026-11-07 · `seunghyuk` 브랜치의 현재 구현 · [README](../README.md) · [02 시스템 설계](02_시스템_설계서.md)
>
> **이 문서의 역할:** 무엇을 만들었고, 무엇이 아직 없으며, 어떤 입력에서 어떤 결과가 나와야 하는지 정의합니다. 코드의 내부 처리 방법은 02, 실행 방법은 05에서 설명합니다.

## 1. 문제·사용자·목표

- **사용자:** 출하 시점을 선택하고 보관비·감량에 따른 경제적 결과를 부담하는 농가·생산자조직, 그 의사결정을 지원하는 선과장·APC 담당자.
- **문제:** 경락가격만 조회해서는 ‘며칠 더 보관할 가치가 있는지’를 평가하기 어렵습니다.
- **현재 목표:** 동일 거래 조건의 최근 관측 경락가격과 사용자 보관 조건으로 **지연 출하 손익분기 가격**을 계산하고, 사용자 지정 미래 가격이 있으면 조건부 손익을 비교합니다.
- **비목표:** 미래 경락가격 예측, 수익 보장, 실제 농가 정산액 산출, 확정적인 출하 시점 추천.

## 2. 범위와 기능 상태

| ID | 기능 | 상태 | 담당 함수·구성 | 완료 판단 기준 |
|---|---|---|---|---|

## 3. 기능별 입력·출력 계약

### F-01. 자연어 입력과 도구 선택

- **입력:** 한국어 질문, 선택적으로 앞선 대화의 `previous_response_id`.
- **처리:** OpenAI Responses API가 도구 호출 여부와 인수를 선택합니다. 도구 호출은 Python에서 실행하고 결과를 API에 되돌려줍니다.
- **출력:** 검증된 분석 보고서 또는 부족한 조건을 묻는 한국어 답변.
- **예외:** 빈 질문은 함수 수준에서 오류, API 인증·네트워크 문제는 CLI에서 오류 안내. 매번 적절한 도구 호출을 한다는 보장은 없습니다.

### F-02. 경락가격 조회: `get_market_price`

| 입력 필드 | 형태 | 의미·예시 |
|---|---|---|
| `variety` | 문자열, 필수 | 품종: `조생귤` |
| `grade` | 문자열, 필수 | 원본 등급: `특` |
| `size` | 문자열, 필수 | 원본 크기: `소` |
| `package_kg` | 숫자, 필수 | 상자 한 개의 중량: `5` |

- **고정 조건:** 서울가락시장(`110001`), `경매`, 포장종류 `상자`.
- **처리:** `daily_prices.csv`에서 시장·품종·등급·크기·포장중량이 모두 일치하는 행만 조회합니다. 같은 날짜의 집계 행이 여러 개면 **총낙찰금액 합계 ÷ 총중량 합계**로 단가를 계산합니다.
- **출력:** 최근 관측일, 원/kg 가격, 거래건수, 거래중량, 데이터 품질 표시(`quality_flags`). 값이 없으면 `has_price=false`와 사유.
- **주의:** `미상`은 원본 거래의 누락값이지 사용자의 규격을 자동 추론하라는 의미가 아닙니다. 다른 규격의 가격을 섞어 평균내지 않습니다.

### F-03. 손익분기 계산: `compare_shipping`

F-02의 **4개 입력에 더해** 아래 필드를 받습니다. Function Calling 스키마는 엄격 모드라 **모든 키가 있어야 하고**, 선택적 가격 두 개는 값이 없을 때 `null`로 전달합니다.

| 입력 필드 | 형태 | 허용 조건·용도 |
|---|---|---|
| `quantity_kg` | 숫자 | **0 초과**, 전체 물량(kg) |
| `delay_days` | 정수 | **1 이상**, 지연 기간(일) |
| `daily_storage_cost` | 숫자 | **0 이상**, 하루 추가 보관비(원) |
| `loss_percent` | 숫자 | **0 이상 100 미만**, 전체 지연기간 누적 감량률(%) |
| `current_price_per_kg` | 숫자 또는 `null` | 사용자 기준 단가. `null`이면 CSV 최근 관측값 사용 |
| `future_price_per_kg` | 숫자 또는 `null` | 사용자 **가정가격**. `null`이면 차액 계산 생략 |

- **출력:** 기준가격 출처·관측일, 즉시 출하 가정 매출, 보관 후 물량, 총추가 보관비, 손익분기 단가, 원 단위 올림 가격, 필요 가격 상승률.
- **처리:** F-02와 같은 필터로 가격 자료를 찾습니다. 사용자가 기준가격을 명시했다면 그 가격을 우선합니다. 도구가 **내부에서 가격을 조회하므로 F-02를 별도로 먼저 호출할 필요는 없습니다.**
- **예외:** 일치하는 거래가 없고 사용자 기준가격도 없으면 계산 중단. 물량·가격·일수·비용·감량률이 범위를 벗어나면 오류를 반환합니다.

### F-04. 사용자 미래 가격 가정 비교

- **입력:** F-03 전체 입력 + `future_price_per_kg=2700` 등 사용자가 명시한 가격.
- **출력:** 지연 후 보관비 차감 금액, 즉시 출하 대비 차액(양수는 가정상 지연 출하 유리).
- **주의:** LLM이 임의로 미래 가격을 만들지 않으며, 사용자 가정가격을 예측가격으로 표시하지 않습니다.

### F-05. 조건 부족·오류 처리

- **정보 누락:** 품종·등급·크기·포장중량 또는 물량·기간·보관비·감량률이 부족하면 추가 질문하도록 프롬프트에 지시되어 있습니다.
- **범위 오류:** 보관기간 `0일`, 감량률 `100%` 등은 Python 계산 엔진에서 거부합니다.
- **현재 제한:** 누락값 여부를 확인하기 전 LLM이 `get_market_price`를 호출할 수 있습니다. 등록되지 않은 함수와 예상 밖 입력 필드도 거부하지만 **LLM 답변 자체의 사실성을 전부 검증하는 것은 아닙니다.**

### F-06. 과거 가격 변화 확인

- **입력:** 동일 조건 가격 관측 목록과 보관일수 N.
- **출력:** 최근 관측일과 **달력상 정확히 N일 전**의 원/kg 가격·변동률, 또는 ‘해당 날짜 거래 없음’.
- **주의:** ‘거래일 기준 N번째 이전’이나 ‘모든 N일 구간 평균’이 아닙니다. 미래 변동을 예측하지 않습니다.

### F-07. 수치 일관성·결과 표시

- **원칙:** 금액 계산에는 Python의 `Decimal`과 원본 총금액·총중량으로 계산한 **반올림 전 가격**을 사용합니다.
- **정상 도구 실행 시:** LLM이 다시 쓴 숫자 대신 `format_verified_result()`가 도구 결과를 보고서로 출력합니다.
- **도구를 호출하지 않았거나 오류가 발생한 경우:** LLM의 추가 질문·안내가 출력되므로 모든 문장의 정확성을 보장하는 강제 검증 계층은 아닙니다.
