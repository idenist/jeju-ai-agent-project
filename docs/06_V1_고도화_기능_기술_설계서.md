## 0. 먼저 확정할 개발 원칙

1. **V0는 수정하지 않고 평가 기준점으로 보존한다.** V1의 새로운 기능은 별도 모듈로 구현하고 기존 계산 함수를 재사용한다.
2. **기능적 확장과 정확도 개선을 따로 측정한다.** V0 평가의 30문항 29개 통과(96.67%, 단일 실행)는 현재 기능 수행의 결과이지 출하 전략의 우수성을 증명한 것이 아니다. EVAL-007은 추가 5회에서 모두 통과했으므로 반복 재현 오류로 단정하지 않는다.
3. **V1은 미래 가격 예측 모델이 아니다.** 과거 가격을 이용한 시뮬레이션은 ‘동일 조건에 이 가격들이 관측됐더라면’이라는 반사실적 가상 계산이며, 미래 수익 확률로 해석하지 않는다.
4. **자료가 없는 가정은 자동 생성하지 않는다.** 특히 3일·7일·14일의 누적 감량률을 서로 동일하게 두거나 선형 보간하지 않는다. 사용자 또는 명시된 가상 시나리오 값으로만 계산한다.
5. **LLM은 의도 파악과 도구 선택, Python은 가격 조회·수치 계산·검증을 맡는다.** V0에서 개선한 수치 일관성을 유지한다.
6. **팀 통합 인터페이스는 11월 9일 이후 팀원과 협의한다.** 독립 Agent 간 호출 규격이 확정되기 전에는 A2A/MCP 도입을 전제로 설계하지 않는다.

## 2. V1 기능 상세 명세 및 완료 조건

### V1-F01. 과거 지연 출하 가상 손익 분석 (`analyze_historical_delays`)

**목적:** 과거 두 시점의 가격 변동률을 보여주는 데서 나아가, **사용자 물량·보관비·감량률을 반영한 가상 원화 손익**을 여러 과거 구간에서 계산한다.

**입력 계약**

| 항목 | 자료형 | 규칙 |
|---|---|---|
| `variety`, `grade`, `size` | 문자열 | CSV의 표준 분류와 일치. 사용자가 모르는 규격을 `미상`으로 자동 치환하지 않음 |
| `package_kg` | 양수 | 포장중량(kg), 기본 포장종류는 `상자` |
| `quantity_kg` | 양수 | 출하 물량 |
| `delay_days` | 정수 | 1 이상. 최초 시연은 **7일**로 범위를 제한 |
| `daily_storage_cost_krw` | 0 이상 | 하루 추가 보관비 |
| `loss_percent` | [0, 100) | **해당 지연기간 전체의 누적 감량·폐기율(%)** |
| `market_code` | 문자열 | V1에서는 `110001`(서울가락)만 허용 |
| `as_of_date` | 날짜 또는 null | 해당 날짜 이후 거래는 사용하지 않는 데이터 조회 상한. null이면 데이터의 마지막 관측일 |
| `analysis_date` | 날짜 | 실제 분석을 수행한 날짜(시연에서는 실행 날짜). 최신 관측일의 경과 일수·오래된 가격 경고에 사용 |
| `min_transactions_per_day` | 정수 | 초기 정책값 5건; 연구적으로 검증된 신뢰도 임계값이 아닌 **개발용 품질 필터** |

**자료와 처리 규칙**

1. `daily_prices.csv`를 사용한다. 시장·품종·등급·크기·포장종류·포장중량·거래방식을 **완전히 동일하게** 맞춘다.
2. 날짜 `t`와 `t + delay_days`가 모두 관측된 경우에만 한 쌍으로 인정한다. **거래일 기준 N번째 이전**으로 바꾸거나 휴장일 가격을 임의 보간하지 않는다.
3. 양 끝 날짜 각각 거래건수가 초기 기준 5건 이상인 구간만 기본 분석에 포함하고, 제외 건수를 별도로 표시한다. 결측 등급·크기는 규격이 명시된 분석과 섞지 않는다.
4. 날짜별 가격 `P(t)`와 `P(t+d)`는 **각각 그 날짜의 총거래금액 ÷ 총중량**으로 구한다. *모든 과거 구간에 최신 기준가격 하나를 대입하지 않는다.*
5. 각 과거 구간의 **가상 손익 차액**을 계산한다.

```text
과거 구간 즉시 출하 가정 매출 = Q × P(t)
과거 구간 지연 출하 가정 순금액 = Q × (1 − r_d/100) × P(t+d) − d × C
과거 구간 가상 손익 차액 = 지연 출하 가정 순금액 − 즉시 출하 가정 매출
```

`Q`: 물량(kg), `d`: 지연일수, `C`: 하루 추가 보관비(원), `r_d`: 해당 기간 누적 감량률(%).

**출력 계약 (핵심 필드)**

- 분석 조건·관측 기간·입력 데이터 버전·시장/규격
- 전체 날짜쌍 후보 수, 제외된 낮은 거래건수 날짜쌍 수, 최종 유효 구간 수
- 날짜쌍별 시작·종료일, 시작·종료 가격, 거래건수, 가상 손익 차액
- 이익/손실/손익 동일(0원) 구간 수, 가상 차액의 최소·중앙값·최대값
- `simulation_type="historical_counterfactual"`, `is_forecast=false`
- 과거 구간의 중첩, 짧은 관측 기간, 실물 보관 이력 부재에 대한 안내

**예외 및 완료 조건**

- 동일 조건의 관측 날짜쌍이 0개이면 결과를 생성하지 않고 ‘분석 가능한 과거 구간 없음’을 반환한다.
- 유효 구간이 5개 미만이면 ‘사례 부족’으로 표시하고, 이익 사례 비율을 의미 있게 해석하지 않는다.
- 구간이 20개 이상이어도 **미래 이익 확률**이나 **통계적 신뢰수준**으로 표현하지 않는다. 날짜쌍은 중첩될 수 있고 관측기간이 짧기 때문이다.
- 계산에는 `Decimal` 사용. 결과는 도구가 직접 반환한 숫자로만 출력한다.
- 7일 보관 사례의 독립 검산·날짜 정확성·저표본 제외·손익부호·빈 데이터에 대한 테스트를 통과하면 완료로 본다.

**현재 데이터의 재현용 탐색 사례(아직 V1 구현 결과는 아님)**  
서울가락·조생귤·특·소·5kg 상자, 3톤·7일·하루 2만 원·누적 감량률 2% 조건에서, 보유 CSV의 정확히 7일 차이인 구간은 **21개**, 양 끝 거래건수 5건 이상으로 필터링하면 **20개**이다. 이 중 가상 지연 손익이 플러스인 구간 **7개**, 마이너스인 구간 **13개**이다. 2026-10-07 → 10-14 구간은 가격이 약 **1.54% 상승**했지만 가상 손익 차액은 약 **−173,791원**이다. *이 값은 검증용 예시이며 실제 보관 실험도, 미래 성공 확률도 아니다.*

### V1-F02. 데이터·근거 품질 게이트 (`assess_evidence_quality`)

**목적:** 수치가 계산 가능하다는 사실과 **의사결정 근거로 충분하다는 사실을 구분**한다.

| 검사 | 기준(초기 정책) | 동작 |
|---|---|---|
| 규격 일치 | 시장·품종·등급·크기·포장중량·거래유형 정확히 일치 | 불일치 자료를 섞지 않음 |
| 거래건수 | 구간 양 끝 각각 5건 미만 | 기본 시뮬레이션에서 제외, 제외 건수 출력 |
| 가격 관측일 | 실제 `analysis_date` 기준 마지막 거래 관측일이 3일 이상 이전 | ‘관측가격이 오래됨’ 표시. **시장 특성을 반영한 확정 기준 아님** |
| 유효 과거 구간 | 0개 / 1~4개 / 5개 이상 | 분석 불가 / 사례 부족 / 관측 요약 가능으로 구분 |
| 분류 누락 | 등급·크기 `미상`, `LOW_SAMPLE` 플래그 | 품질 경고; 실제 상품 등급 추정 금지 |
| 데이터 대표성 | 서울가락 1개 시장·약 한 달 데이터, 중첩 구간 | 어떤 수치도 미래 확률로 해석하지 않음 |
| 지연 보관 손실 | 현장 검증된 손실률 없음 | 사용자 지정 가정으로 명시 |

**출력:** `status = unavailable | limited | descriptive_only`, `warnings[]`, `excluded_count`, `observed_date_range`, `evidence_scope`. 이 구분은 **운영 정책상 표시 등급이지 통계적 신뢰도 점수나 검정 결과가 아님**.

**완료 조건:** 불일치/저표본/관측오래됨/결측/중첩/표본 0개 사례가 올바르게 분류되고, 경고 없이 ‘추천 확정’ 또는 ‘이익 확률’을 출력하지 않는다.

### V1-F03. 3·7·14일 선택지 비교 (`compare_delay_options`)

**목적:** 기간별 손익분기 조건을 같은 표에서 보여주되, 미래 가격을 알 수 없는 상태에서 임의의 최적 날짜를 단정하지 않는다.

- **입력:** 공통 품종·규격·물량, 하루 보관비(기간별 값이 다르면 개별 입력), `options=[{days:3,loss_percent:...},{days:7,...},{days:14,...}]`.
- **핵심 제약:** 각 기간의 **누적 감량률은 각각 받아야 한다**. 7일 2%를 3일과 14일에 자동 재사용하거나 선형 확장하지 않는다.
- **출력:** 각 기간의 남은 물량, 추가 보관비, 손익분기 단가, 필요한 상승률, 비교 기준가격의 출처와 관측일.
- **선택적 출력:** 기간별 과거 시뮬레이션 결과. 자료가 없는 기간은 `insufficient_data`로 표시한다.
- **완료 조건:** 3·7·14일 입력/누락 경로를 테스트하며, 결측 가정이 있으면 해당 기간은 계산 대신 추가 입력 요청 또는 건너뛰기 처리.

### V1-F04. 가정 민감도 분석 (`analyze_sensitivity`)

**목적:** 보관비와 누적 감량률의 가정이 바뀌면 결과가 얼마나 달라지는지 보여준다.

- **입력:** 기본 출하 조건 + 사용자가 지정한 보관비 목록·감량률 목록. 예: `storage_costs=[10000,20000,30000]`, `loss_rates=[1,2,3]`.
- **출력:** 조합별 손익분기 단가·상승률의 표, 최소·최대 범위, 손익분기 가격에 가장 큰 영향을 준 가정.
- **원칙:** 숫자 목록은 사용자 명시 또는 **‘예시 가정’이라고 표시한 시연 설정**에만 사용. 자동 추정값을 실제 보관 환경 데이터처럼 표현하지 않는다.
- **완료 조건:** 경계값·증가 방향(비용↑, 감량↑일 때 다른 조건이 같으면 손익분기 단가↓로 나오면 오류)·음수 입력 거부·수치 일관성 검증.

### V1-F05. 도메인 분류·입력 계약 검증

- CSV에서 **실제로 사용되는** 표준 품종/등급/크기 목록을 읽어 검증한다. `'하우스감귤'`은 본 데이터의 표준 분류명이다.
- `strict: true`가 보장하는 것은 **함수 인수의 JSON 스키마 준수**이지, 농산물 용어의 의미가 정확하다거나 사용자 입력값이 사실이라는 보장은 아니다.
- 사용자 발화에 규격이 없으면 임의의 `미상`을 채우지 않고 재질문한다.
- 100% 이상 감량률, 0 이하 출하량·보관일수, 음수 비용 등을 계산 전 검증한다.
- **기술 선택:** 현재 검증 함수의 반복·불일치가 확인되면 Pydantic 모델과 도메인 validator를 도입한다. 입력 검증을 위한 재설계 자체가 목적이 되어서는 안 된다.

### V1-F06. 분석 조합·근거 보고서

- LLM이 질문 유형을 판단해 필요한 도구를 호출할 수 있어야 한다: 가격 조회 → 손익분기 → 과거 사례 → 근거 품질 → 조건별 결과 요약.
- **보고서:** 사용한 시장·품종·규격·관측일·데이터 범위·가정값, 손익분기, 역사적 가상 손익, 해석의 한계를 포함.
- **불확실성 통제:** 도구가 실패했거나 표본이 없으면 계산값·‘상승 확률’·단정적 출하 지시를 지어내지 않는다.
- **완료 조건:** 동일 질문의 Tool Calling 경로가 재현되고, 숫자가 Python 도구 결과와 일치하며, 사용자에게 가정과 한계를 분리해 설명한다.

## 7. 확정 범위와 변경 관리

**이번 문서에서 확정한 것:** V1의 문제 정의, 핵심 신규 기능 세 가지(과거 구간 분석·기간/민감도 비교·근거 품질), 계산 규칙, 입력 가정의 출처, 평가 분리 원칙, 구현 순서. **아직 확정하지 않은 것:** 향후 가격 예측 모델, 실제 저장 감량률 추정 모델, 팀 간 Agent 통신 표준, LangGraph 도입 여부. 이는 필요성·데이터·평가 근거가 생길 때 결정한다.

새 기능을 구현하기 전에 `01_요구사항_및_기능명세서.md`에 V1 기능 ID를 반영하고, 구현 후 `02_시스템_설계서.md`, `05_실행_및_테스트_가이드.md` 및 평가 결과를 갱신한다. 단, **V0 버전의 코드와 골드셋은 수정하지 않는다.**

**최종 핵심 문장:** *V0는 손익분기 조건을 정확히 계산하는 Agent이고, V1은 동일 규격의 과거 가격 사례에서 가상 손익을 검증하고, 기간·비용·감량률의 변화와 자료 신뢰성을 함께 설명하는 Agent를 목표로 한다.*
