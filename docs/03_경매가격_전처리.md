# 제주 감귤 경매가격 전처리 파이프라인

> [문서 길잡이](../README.md#문서-읽는-순서) · [01 Agent 기술 설명서](01_Agent_기술설명서.md)

**목표:** API 수집 원본 `auction_trades.csv`를 Agent가 조회할 수 있는 일별 가격 데이터로 가공합니다. 원본은 수정하지 않습니다.

## 1. 입출력 파일

```text
jeju/
├── scripts/
│   ├── collect_auction_raw.py
│   └── preprocess_auction.py
└── data/
    ├── raw/
    │   └── auction_trades.csv
    ├── processed/
    │   ├── daily_prices.csv          # 동일 조건별 일일 경매가격
    │   └── daily_variety_prices.csv  # 품종별 평균가(현황 파악용)
    └── reports/
        └── auction_quality_report.json
```

현재 저장소에는 이미 결과 CSV가 포함되어 있습니다. **원본을 변경하거나 기간을 추가할 때만 전처리를 다시 실행**하세요.

## 2. 실행 방법 (Windows CMD)

프로젝트 최상위 폴더에서 실행합니다. 전처리 자체는 외부 pip 패키지가 필요 없습니다.

```bat
python scripts\preprocess_auction.py
```

추가 연도의 원본 CSV가 있다면 입력 파일을 여러 개 지정할 수 있습니다.

```bat
python scripts\preprocess_auction.py --input data/raw/auction_trades.csv data/raw/auction_trades_2025.csv
```

출력 폴더를 직접 지정하려면:

```bat
python scripts\preprocess_auction.py --input data/raw/auction_trades.csv --out-dir data/processed --report-dir data/reports
```

새 경매자료를 API에서 수집하려면 별도의 공공데이터포털 `DATA_GO_KR_KEY`가 필요합니다. 원본 수집 후 위 전처리를 다시 실행합니다. **OpenAI API 키와는 다른 키**입니다.

## 3. 데이터 처리 규칙

| 규칙 | 처리 방법 |
|---|---|
| 품목 | `gds_lclsf_cd=06`, `gds_mclsf_cd=14` |
| 원산지 | `plor_nm`이 제주특별자치도를 가리키는 거래만 분석 |
| 거래 방식 | `trd_se=경매`만 사용, 정가수의·전자거래 제외(원본에는 유지) |
| 날짜 | `trd_clcln_ymd` 거래정산일 사용. 농가 실제 출하일과 다를 수 있음 |
| 표준 품종 | `gds_sclsf_cd` 기준 8종. 법인별 자유입력 `corp_gds_vrty_nm`은 분류에 사용하지 않음 |
| 등급/크기 | `.` 또는 공란은 `미상`으로 표시하며 임의 보완 금지 |
| 가격 단위 | `총낙찰금액(sum(totprc)) / 총거래중량 kg(sum(unit_tot_qty))` |
| 무효 거래 | 수량·금액 0 이하, 수량×단가 불일치, 중량 불일치 등 제외 |
| 중복 | 원본의 **모든 필드가 완전히 같은 행**에 한해 제거 |

가격은 거래별 kg당 가격의 **단순평균이 아닌 물량 가중평균**입니다. 예를 들어 5kg 상자 2개를 각각 10,000원/상자에 판매했다면 총 10kg에 20,000원이므로 2,000원/kg입니다.

## 4. 결과 파일의 역할

### `data/processed/daily_prices.csv` — Agent가 실제 조회하는 데이터

한 행의 기준: `날짜 × 시장 × 표준품종코드 × 등급 × 크기 × 포장종류 × 포장중량 × 거래방식`.

주요 컬럼: `date`, `market_code`, `market`, `variety_code`, `variety`, `grade`, `size`, `package_kg`, `avg_price_kg`, `total_kg`, `total_amount_krw`, `transaction_count`, `quality_flag`.

**비교 시에는 동일한 `market_code`, `variety_code`, `grade_code`, `size_code`, `package`, `package_kg`, `trade_type`인 행만 사용**해야 합니다. `GRADE_UNKNOWN`, `SIZE_UNKNOWN`, `LOW_SAMPLE`은 데이터 해석 주의 표시입니다. `LOW_SAMPLE`은 거래 5건 미만을 뜻하며 통계적 정확도를 보증하지 않습니다.

### `data/processed/daily_variety_prices.csv` — 참고용

한 행의 기준: `날짜 × 시장 × 표준품종코드 × 거래방식`. 품종별 평균가, 거래량, 거래건수, 등급·크기 미상 물량비율을 확인할 수 있습니다. **규격 구성이 혼합되므로 일자별 가격 차이가 순수 시세 변화를 뜻하지 않을 수 있습니다.**

### `data/reports/auction_quality_report.json` — 검증 기록

원본 건수, 유효·제외 건수와 사유, 날짜 범위, 품종별 사용 건수, 결과 행 수를 확인합니다.

## 6. 해석상 주의

- **한 달 남짓한 자료만으로 미래 가격을 예측할 수 없습니다.** 3·7·14일 등 과거 날짜별 가격 비교는 과거 관측값일 뿐입니다.
- 도매시장 경락가격은 농가 실수취액이 아닙니다. 실제 비용·감량률은 별도로 반영해야 합니다.
- 표준 품종코드는 데이터 제공자의 분류이며, 실제 상품 품질이나 세부 계통의 완전한 동질성을 보장하지 않습니다.
