# 제주 감귤 출하량 데이터 전처리 안내

## 1. 목적과 입력 데이터

- **목적:** 제주데이터허브 **#855 「신고소별 감귤류 및 만감류 출하량 통계」**를 팀 공통 분석용 CSV로 정리
- **원본 파일:** `data/raw/jeju_shipments.csv`
  - 기존 `신고소별감귤류및만감류출하량통계.csv`를 **이름만 바꿔서** 저장
  - 원본 컬럼: `출하일자`, `품종대분류`, `품종소분류`, `신고소`, `출하량`
  - 원본 인코딩: CP949, 출하량 단위: **톤**
- **필요 환경:** Python 3.10 이상, 외부 패키지 설치 불필요

## 2. 프로젝트 폴더와 실행

```text
jeju/
├─ data/
│  ├─ raw/
│  │  └─ jeju_shipments.csv     ← 원본을 그대로 넣기
│  ├─ processed/
│  │  ├─ daily_shipments.csv
│  │  └─ monthly_shipments.csv
│  └─ reports/
│     ├─ shipment_unassigned_rows.csv
│     └─ shipment_quality_report.json
├─ scripts/
│  └─ preprocess_shipments.py
└─ docs/
   └─ 제주_감귤_출하량_전처리_실행안내.md
```

PowerShell에서 **프로젝트 최상위 폴더**로 이동한 뒤:

```powershell
python scripts/preprocess_shipments.py
```

파일명이 원래 한국어라면 경로를 명시해도 됨:

```powershell
python scripts/preprocess_shipments.py --input "data/raw/신고소별감귤류및만감류출하량통계.csv"
```

출력 폴더 변경:

```powershell
python scripts/preprocess_shipments.py --input data/raw/jeju_shipments.csv --output-dir data/processed --report-dir data/reports
```

## 3. 결과 파일: 어떻게 사용하는가?

| 파일 | 주요 컬럼 | 사용 목적 |
|---|---|---|
| `daily_shipments.csv` | `date`, `category`, `variety`, `shipment_tons`, `reporting_offices`, `positive_offices`, `source_rows`, `data_warning` | 특정 품종의 **일별 출하량** 추이 조회 |
| `monthly_shipments.csv` | `year_month`, `category`, `variety`, `shipment_tons`, `observed_days`, `source_rows`, `data_warning` | 계절별 **월간 출하 집중도** 분석 (주요 Agent 입력) |
| `data/reports/shipment_unassigned_rows.csv` | `exclusion_reason` 및 원본 5개 컬럼 | 날짜가 없어 일별·월별 합산에 포함할 수 없는 기록 보관 |
| `data/reports/shipment_quality_report.json` | 데이터 기간, 원본·제외 건수, 합계 검증, 누락 통계 | 품질 점검 및 분석 한계 확인 |

- **집계:** 동일한 `날짜 × 대분류 × 소분류`의 신고소별 출하량을 합산. 월별 출하량은 날짜가 있는 기록만 연월별로 합산.
- **단위:** 모든 집계 수치는 **톤(t)**. kg이 필요하면 `shipment_tons × 1,000`.
- **품종:** `노지온주`, `하우스온주`, `월동온주`, `한라봉`, `천혜향`, `레드향`을 원본 그대로 사용. 경매 API의 `조생귤`, `극조생감귤` 등과 **임의로 매핑하지 않음**.
- **미관측 일자:** 원본에 행이 없다면 0톤으로 채우지 않음. 원본에 명시된 0톤은 그대로 집계.

## 4. 실제 원본에 대한 검증 결과

| 검증 내용 | 결과 |
|---|---:|
| 전체 기록 | 46,836건 |
| 정상 날짜 기록 | 44,886건 |
| 날짜 누락 | **1,950건** (전부 한라봉) |
| 날짜 누락 기록 중 양수 | 816건 |
| 날짜를 배정할 수 없는 물량 | **21,617.86톤** |
| 처리 후 일별 집계 | 7,481행 |
| 처리 후 월별 집계 | 304행 |
| 정상 날짜 출하량 총합 | 2,209,217.71톤 |
| 자료의 날짜 범위 | 2018-01-01 ~ 2025-09-17 |

**주의:** 한라봉의 날짜 누락 1,950건은 기간을 알 수 없으므로 연월을 추정해 채우지 않았음. 한라봉의 월별 물량을 완전한 통계라고 해석하면 안 됨. 원본에 동일한 내용의 누락 행이 반복되더라도 각각 다른 날짜의 기록일 수 있어 임의로 중복 제거하지 않았음.

또한 **2025년 9월은 17일까지의 부분 월**임. `data_warning`에 `source_ends_mid_month` 표시. 한라봉은 `unknown_date_rows_excluded_for_variety` 표시.

## 5. Agent 활용 시 주의사항

- #855 자료는 **2025년 9월까지만** 있으므로, **2026년 실시간 출하량**으로 사용 금지.
- **신고소 기준 제주 출하량과 서울가락시장 경매 반입량은 다른 지표**이므로 무조건 같은 날 합쳐 분석하면 안 됨.
- 권장 사용: `monthly_shipments.csv`로 과거 품종별 출하 집중 시기를 설명하고, 실제 '지금 vs 7일 뒤' 비교는 **가격 자료 + 사용자 입력 보관비·감량률**로 계산.
- 입력에 동일한 `날짜 × 대분류 × 소분류 × 신고소` 키가 중복되면 이중 합산을 방지하기 위해 스크립트가 오류를 내고 중단함.
