# 3차 MVP — 사용자 흐름, Agent 도구 실험, 평가 기준

## 화면 사용

1. 첫 번째 탭에서 **두 미래 출하안 A/B 비교**를 시작합니다.
2. 두 출하일의 시작일·기간·물량과 단가를 입력합니다.
3. 과거 가격 근거를 사용하려면 명시적으로 같은 거래 규격을 선택합니다. 해당 값은 예측이 아니며 실수취액과 다릅니다.
4. 감모율·보관비·수수료를 확인합니다. 미확인 값은 0원으로 대체하지 않습니다.
5. A/B 결과를 비교하고 PDF·JSON으로 저장합니다. 실제 출하 권고가 아닙니다.

보조 흐름은 AI 대화, 오늘/나중 비교, 자료·도구 탭에 유지합니다.
이 패치에서 도구·계산 공식·원천 데이터는 삭제하지 않습니다. 검증된 실사용 시나리오가 확보되면 불필요한 기능을 별도로 제거합니다.

## Agent 최적화 실험

기존 기본 Agent의 전체 도구 제공은 **그대로 유지**합니다.
`JEJU_FOCUSED_TOOLS=1`인 경우에만 미래 A/B 의도가 명확한 입력에서 제공 도구를 네 개로 축소합니다.
축소 후 도구 목록은 `compare_future_pair`, `analyze_shipment_timing`, `get_price_history`, `explain_term`입니다.
정산·시장 탐색 등 복합 질의에는 사용할 도구가 부족할 수 있어 **기본값으로 승격하지 않습니다**.
도구 수 감소는 도구 선택 정확도나 토큰 비용 개선을 입증하지 않습니다.

선택 실험 실행 (Windows CMD, 새로운 터미널에서):

```cmd
set JEJU_FOCUSED_TOOLS=1 && .venv\Scripts\python.exe -m streamlit run app.py
```

## 평가

- 무과금: `python -m unittest discover -s tests -p "test_*.py"`
- 무과금: `python -m scripts.evaluate_integrated_agent --validate`
- 실제 모델 비교는 **동일 모델·동일 평가셋·동일 원천 데이터** 기준으로 정상 모드와 실험 모드를 각각 평가해야 합니다.
- `python -m scripts.evaluate_integrated_agent --live --all`은 API 비용이 발생할 수 있으므로 원클릭 스크립트에서는 호출하지 않습니다.
- 두 평가 폴더 비교: `python -m scripts.compare_model_runs BEFORE_FOLDER AFTER_FOLDER`
- 비교에는 성공률, 모델 호출, 토큰 사용량, 모델에 제공한 도구 개수·프롬프트 길이 지표가 포함됩니다.
- 실제 E2E 평가가 실행되지 않았다면 AI 정확도 개선을 주장할 수 없습니다.
