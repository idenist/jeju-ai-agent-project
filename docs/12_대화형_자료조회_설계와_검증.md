# 대화형 자료조회 개선 — 2026-11-16

## 사용자 문제와 코드 원인

“작년 감귤 가격”을 물었는데 상품 규격과 시장코드를 요구하고, 입력 예시를 물으면 출하 계산 조건을 다시 요구했다.

1. `AgentSession`은 도구 없는 LLM 답변을 거의 모두 버렸다. 예외도 A/B 단일 항목 확인 중이며 숫자가 없는 문장으로 한정됐다. 따라서 `5kg 상자` 같은 정상 설명도 탈락했다.
2. 표시할 도구 결과가 없으면 Python이 `compare_shipment_options`를 실행해 계산 입력 질문으로 대체했다. 사용자가 질문을 바꿔도 계산이 계속되는 직접 원인이다.
3. 도구 호출 직후 Python이 보여준 실제 답변은 다음 모델 요청에 온전히 포함되지 않았다. 짧은 답변을 Python이 처리하는 경로도 대화 이력에서 빠졌다.
4. 기존 가격 도구는 정확한 규격의 최근 가격 또는 일정 간격의 과거 가격쌍에 맞춰져 있었다. 시즌 자료는 있어도 연도별 시장 개요를 답할 도구가 없었다.

## 조사 후 선택한 기술

**단일 LLM의 function calling + 구조화된 자료조회 + 실제 대화 이력.** LLM이 발화 의도와 필요한 도구를 선택하고, Python이 데이터 필터·집계·손익 계산·상태 변경을 실행한다. 도구의 엄격한 JSON 스키마와 대화 문장의 자유도를 분리했다.

- OpenAI의 [Function calling](https://developers.openai.com/api/docs/guides/function-calling)은 도구 실행 결과를 모델에 돌려주고 최종 답변을 받는 흐름을 설명한다. 기존 앱은 이 마지막 해설 단계를 생략하거나 버리고 있었다.
- [Conversation state](https://developers.openai.com/api/docs/guides/conversation-state)는 후속 요청에 이전 사용자/assistant 대화를 전달하는 방식을 설명한다. 앱이 별도로 만든 답변도 실제 대화이므로 이력에 포함한다.
- Anthropic의 [Building effective agents](https://www.anthropic.com/research/building-effective-agents)는 필요한 복잡성만 도입하고 단순한 모델·검색·도구 조합부터 시작하라고 권한다. 기존 Responses 루프를 고칠 수 있어 새 프레임워크나 멀티에이전트를 도입하지 않았다.

이번 데이터는 날짜·품종·거래중량·거래금액이 있는 표이다. 검색 유사도로 가격 행을 고르는 벡터 RAG 대신 명시적 기간/필터 조회와 정확한 집계를 사용한다. 공개 자료에 근거한 해설은 LLM이 한다. 원문 문서·재배 지침 검색이 필요해지면 문서 RAG를 별도로 검토한다.

## 적용 범위

- `agents/prompts.py`: 대화 목적, 자료조회, 계산·상태 원칙을 구분한 프롬프트. 설명/예시/불만에는 직접 답하고 입력 수집을 강제하지 않는다.
- `agents/agent.py`: 자연어 답변을 전달하고, 답변 없는 경우 자동 계산 설문으로 전환하던 코드를 제거했다. 첫 도구를 강제했더라도 이후 호출은 모델 선택으로 돌린다.
- `agents/dialogue.py`: 실제 표시 답변과 Python이 처리한 짧은 사용자 답변도 기억한다. 정산·연구용 결과의 로컬 금액은 이력에 넣지 않는다.
- `get_price_overview`: 최대 366일 기간, 선택적 시장 이름/품종/등급/크기/포장 조건. 몰라도 조회한다. 시장·품종 코드별로 분리하고 총 거래금액/총 거래중량으로 집계한다. 거래중량 상위 6개를 표시하고 나머지가 있음을 알린다.
- 결과는 요청 기간, 실제 관측 월, 자료 없는 월, 품질 표시, 원출처를 포함한다. 자료의 실제 등급/포장 후보도 반환해 후속 설명에 사용한다. 원자료와 농가 비교 조건은 수정하지 않는다.
- 숫자 전체 차단 대신 대화 맥락에 없는 원화 금액을 탐지하는 좁은 방어를 둔다. 이는 모든 허위 주장을 검출하는 검증기가 아니다. 단위 예시·날짜·자연어 설명은 허용하며, 계산과 데이터 표는 Python 결과를 사용한다.

## 실제 모델 확인

앱 설정의 `gpt-6-luna`를 그대로 사용했다. 사용자가 Codex에서 Astra로 바꾼 것을 앱 모델 변경 요청으로 해석하지 않았다.

연속 네 턴의 실제 API 재현에서:

1. “작년 감귤 출하 가격이 어느 정도였는지 궁금해요” → `get_price_overview` 1회, 모델 요청 2회. 추가 입력 없이 2025년 자료 요약을 반환했다. 서울가락 조생귤 2,843원/kg 등의 품종별 관측값과 1~2월·10~12월만 확보됐다는 한계를 표시했다. 이 값은 자료가 있는 거래의 가중평균이며 연중 전체 평균이 아니다.
2. “시장코드를 제가 어떻게 알죠? 등급이랑 포장 종류의 입력 예시를 알려주세요” → 추가 도구 없이 시장 이름, 실제 후보와 5kg 상자 입력 예시를 설명했다. 계산 입력을 요구하지 않았다.
3. “아니 사용자한테 시장코드 알려달라는건 좀 아니지 않아요?” → 사용자 불편에 답하고 시장 이름으로 충분하다고 설명했다. 물량/단가 질문으로 돌아가지 않았다.
4. “보관비나 감모율을 모르는데도 출하 판단에 도움을 받을 수 있나요?” → 조건부 판단·손익분기 활용 가능성과 미확인 조건의 한계를 설명했다. 비용 입력 설문을 시작하지 않았다.

새 회귀 검증 8건은 위 후속 대화 경로, 실제 표시 이력, 로컬 정산 정보 분리, 근거 없는 금액 처리, 가중평균, 품종 분리, 시장 이름, 중복/없는 기간 처리를 확인한다. 모의 모델 검증과 실제 모델 한 대화 재현은 전체 농가 사용성 검증을 대신하지 않는다.

확인한 검증 결과:

- 신규 8건을 포함한 대화 루프·기존 가격조회/후속조회·도구 경계·실험모드·실행 경로 관련 94건 통과. `git diff --check` 통과.
- A/B 파일까지 포함한 첫 실행은 130건 중 실패 21개·오류 7개(하위 사례 포함)를 보고했다. 이 중 설명을 고정 문구로 대체해야 한다는 기존 기대는 새 대화 계약에 맞게 수정하고 위 94건에서 확인했다. **A/B 파일의 나머지 실패를 해결하거나 전체 통과로 판정하지 않았다.**
- A/B 실패에는 여러 누락값이 있을 때도 단일 항목 즉답 경로를 기대하는 사례, 새 기본 history 경로에서도 manual 질문을 기대하는 사례, 상자 단가 확인 뒤 완성 결과가 없는 사례, UI 비교 결과가 비어 있는 사례가 있다. 일부는 이전에 바뀐 질문/조건 정책과 테스트의 불일치지만, 변경 전 전체 기준 실행을 확보하지 않아 모두 기존 실패라고 단정하지 않는다.
- Windows 제한 환경에서 Streamlit 테스트의 `socketpair`가 대기하는 현상을 확인했다. 해당 실행을 중단하고 로컬 소켓 생성이 가능한 호스트에서 관련 검증을 완료했다. 이 검증은 실제 모델 API를 호출하지 않는다.

## 실행 중인 테스트 앱

기존 브라우저 대화(포트 8501)는 코드 수정 전에 만들어진 `AgentSession` 인스턴스였고, 같은 Streamlit 프로세스의 새 브라우저 세션도 이전 import를 계속 사용했다. 옛 계산 설문을 재현해 이 사실을 확인했다. 기존 프로세스와 그 대화를 보존하면서 수정된 모듈을 새로 읽도록 로컬 Streamlit 인스턴스를 포트 8502에서 실행했다. 이어지는 수동 확인은 `http://127.0.0.1:8502/` 새 세션에서 해야 한다. 기존 세션이 새 코드로 자동 교체된다고 앞서 안내한 것은 잘못이었다.

## 남은 제품 작업

이번 변경은 자료조회와 대화의 기반 복구다. 미래가격 예측 모델을 배포하거나 출하 추천의 정확도를 검증한 작업은 아니다.

기존 제품방향 계획의 다음 단계는 가격 전망의 시간순 평가와 불확실성 범위를 확보하고, 이를 감모·보관비 민감도와 연결하는 것이다. 서비스 완료 기준은 테스트 개수보다 사용자가 적은 입력으로 근거·판단이 바뀌는 조건을 이해하는지에 둔다. A/B 조건 수집의 기존 규칙 처리와 입력 카드에는 추가 개선 여지가 남아 있다.
