# 과거 가격 조회 후속 질문 계약 — STEP 5-2

**기준 브랜치:** `integration/agents` · **기준 커밋:** `86ac2c6`

## 문제

STEP 5-1에서는 과거 경락가격 조회의 실행·자료 검증·표시를 통합했지만, 이전에 사용한 조건을 Python에서 별도로 보관하지 않았습니다. 모델의 대화 기록에만 의존하면 “14일로 바꿔 줘”와 같은 후속 질문에서 품종·등급·포장 조건이 유실되거나 자동 적용값이 사용자 지정값처럼 굳어질 수 있습니다.

## 적용 규칙

1. `AgentSession.price_history_query`는 **이전에 도구에 전달한 명시적 조회 인수**만 보관합니다. 조회 결과의 가격, 변동률, 후보 목록, 자료에서 자동 적용한 시장·거래방식은 넣지 않습니다. 모델이 추출한 필드가 사용자의 발언과 정확하게 일치하는지는 실제 대화 평가로 추가 확인해야 합니다.
2. **새 조회**는 `follow_up=false`입니다. 이전 쿼리의 어느 조건도 가져오지 않습니다.
3. **기존 조회 변경**은 `follow_up=true`입니다. 유효한 이전 조회가 있을 때만 그 조건을 가져오고, 이번 호출에서 `null`이 아닌 필드만 덮어씁니다.
4. 기존 조건을 **명시적으로 철회**하려면 `clear_fields`에 해당 필드를 넣습니다. `null`은 후속 조회에서 유지, 새 조회에서 미지정을 뜻하며 철회와 다릅니다.
5. 이전 쿼리가 없으면 `NEEDS_INPUT`으로 재질문합니다. 현재 판매 단가, 출하 시나리오, 시장 참고 조회, 자료 후보로 빠진 과거 가격 조건을 자동 보충하지 않습니다.
6. `OK`, `NO_DATA`, `NEEDS_INPUT`인 정상 처리 결과에서만 다음 후속 질문용 쿼리를 갱신합니다. 사용자 입력 오류·원천 검증 실패는 이미 확인된 상태를 임의 교체하지 않습니다.
7. 활성 시장가격 자료 버전이 바뀌거나 대화가 초기화되면 기존 과거 조회 조건을 폐기합니다. **과거 가격 간격 `interval_days`와 보관 대안의 `delay_days`는 독립적**으로 유지합니다.
8. 표시 건수 `limit`는 새 조회에서 별도 지정이 없으면 3이고, 후속 조회에서는 이전 값을 유지합니다. 보관 일수·감모·미래가격·실수취 단가를 자동 수정하지 않습니다.

## 도구 호출 예시

처음 질문: “조생귤 특등급 소과 5kg 상자의 7일 과거 가격 변화”

```json
{
  "follow_up": false,
  "clear_fields": [],
  "variety": "조생귤",
  "grade": "특",
  "size": "소",
  "package": "상자",
  "package_kg": 5,
  "interval_days": 7,
  "limit": null
}
```

후속 질문: “14일로 바꿔줘”

```json
{
  "follow_up": true,
  "clear_fields": [],
  "variety": null,
  "grade": null,
  "size": null,
  "package": null,
  "package_kg": null,
  "interval_days": 14,
  "limit": null
}
```

`finish_turn`과 나머지 스키마 필드는 실제 모델 호출 시에도 요구됩니다. 위 예시는 바뀌는 부분만 이해하기 쉽게 축약했습니다.

## 한계 및 후속 검증

이번 테스트는 순수 Python 병합 규칙과 **모의 LLM 도구 호출**을 검증합니다. 실제 모델이 `follow_up`/`clear_fields`를 사용자의 문장에서 정확히 추출하는지는 STEP 7에서 다중 턴 평가로 확인해야 합니다. 명확하지 않은 요청을 임의로 과거 조회의 후속 질문으로 처리하지 않도록 지시했지만 자연어 의도 분류의 완전성을 보장하지는 않습니다.
