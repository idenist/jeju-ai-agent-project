# STEP 5-3 · 과거 가격 조회와 출하 손익 통합 검수

**기준 브랜치:** `integration/agents`
**검증 기준 커밋:** `a22dd0476206e72a02f8173fba9fd4593d24e6f7`

## 목적

STEP 5-1에서 연결한 정현님 과거 경락가격 조회와 STEP 5-2의 후속 조건 승계가 준억님 손익 계산과 충돌하지 않는지 확인합니다. 정현님 신규 B안 가정 단가 기능은 독립 모듈로 보존하고 **기존 통합 Agent에 자동 등록하거나 출하 시나리오에 자동 대입하지 않습니다.**

## 검수 항목

- 병합된 `price_comparison_report.json`의 비교표 해시와 STEP 3의 원천 전체 재계산 검증이 함께 통과하는지 확인
- 실제 조생귤·특·소·상자 5kg의 과거 7일/14일 비교와 통칭 품종·포장중량 충돌 확인
- 모의 Agent로 과거 7일 조회 → 후속 14일 조회 → 기존 7일 보관 손익분기 계산을 연속 실행
- 시장 자동 적용 조건과 과거 가격의 실제 숫자를 사용자 현재 단가·미래 가정으로 옮기지 않는지 확인
- 조회 데이터 오류가 발생하면 가격 조회를 차단하면서 이미 확인된 독립 손익 계산은 보존
- 정현님 신규 B안 가정 단가의 표기, 가정 출처, 감모·비용 미확인값 유지, 비지원 간격 시 가격 미재사용 확인
- Markdown 및 PDF에서 과거 관측 경락가격과 조건부 출하 손익을 별도 항목으로 표시

## 분리해야 하는 개념

| 개념 | 처리 |
|---|---|
| 과거 가격쌍의 7일·14일 간격 | 같은 규격의 서로 다른 과거 거래일 간 관측값 차이 |
| 손익 비교의 보관 7일 | 사용자가 선택한 보관 대안의 기간. 감모·비용 및 실행 가능성 별도 확인 |
| B안 가정 단가 | 과거 변동률을 사용자 A안 단가에 적용한 **가상 시나리오**. 미래 시장가격 예측 아님 |
| 실제 출하 가능 여부 | 저장시설·계약·납기 등을 별도로 확인. 경제성이 높아도 자동 권고하지 않음 |

## 테스트

Windows CMD에서 프로젝트 루트 기준으로 실행합니다.

```bat
.\.venv\Scripts\python.exe -m unittest discover -s tests -p "test_integration_cross_agent_boundary.py" -v
.\.venv\Scripts\python.exe -m unittest discover -s tests
.\.venv\Scripts\python.exe -m unittest discover -s evals -p "test_*.py"
git --no-pager diff --check
```

신규 테스트는 **12개**이며, 실제 OpenAI API를 호출하지 않습니다. 프로젝트의 기존 평가 테스트에는 실제 API를 호출하는 사례가 있을 수 있습니다.

## 범위와 잔여 과제

검수는 데이터 계약, 계산 경계, 모의 도구 호출, 화면과 보고서 재현성을 확인합니다. 실제 모델이 자연어에서 도구 선택·조건 추출을 정확하게 수행하는지, 실제 농가의 실행 조건이 맞는지는 별도 평가가 필요합니다. 정현님 B안 가정 단가를 팀 손익 시나리오에 자동 반영하는 기능은 구현 범위 밖이며, 사용자 확인·출처 구분·가격 기준·원가 계약이 정해지기 전까지 연결하지 않습니다.
