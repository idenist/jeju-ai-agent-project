## 수동 기록 검토에서 발견한 한계

### 1. INT-04의 명시 입력 누락 — 후속 개선 필요

사용자는 "품종은 그냥 감귤이에요. **특, 소, 상자 5kg**의 7일 과거 경락가격을 보려는데 ..."라고 요청했다.

모델은 수정 전과 달리 `get_price_history`를 선택했고 통칭 감귤을 임의 확정하지 않았다. 그러나 `grade=null`, `size=null`로 전달해 사용자에게 이미 제시된 등급과 크기를 다시 요청했다. 실제 필요한 재확인은 **세부 품종**뿐이지만 `missing_fields=["variety", "grade", "size"]`가 반환됐다.

기존 INT-04 채점 기준은 도구 호출과 `variety` 재확인 여부만 확인하므로 이를 통과로 판정한다. **12/12은 평가셋의 지정 기준 통과이지 모든 필드 추출의 완전성을 의미하지 않는다.** 채점 기준을 사후에 덮어쓰지 않고, 후속 버전에서 명시된 등급·크기의 보존을 별도 회귀 사례로 추가한다.

### 2. INT-11의 중량 모순 설명 — 사용성 개선 후보

사용자가 포장 표기 10kg와 포장 중량 5kg가 충돌한다고 말했을 때 모델은 `package_kg=null`로 전달했다. 결과는 `NEEDS_INPUT`이어서 임의 숫자를 선택하거나 계산하지 않았다. 다만 화면은 "포장 중량을 알려 달라"는 일반 재확인 문구를 보여, **10kg와 5kg 간 모순 자체를 직접 설명하지는 못했다.** 위험한 자동 확정은 없었으나 안내 문구의 명확성은 개선할 수 있다.

### 3. 평가 범위의 한계

- 12개 사례의 단회 평가이다. 다른 표현, 장기 대화, 새로운 가격 데이터, 모델 업데이트에서의 성능을 보장하지 않는다.
- 실제 농가 사용성, 출하 가능 여부, 미래 가격 예측 정확도, 경락가격과 실수취액의 차이 해소 여부를 평가한 것은 아니다.
- INT-08에서는 모델이 변경한 `interval_days=14`만 전달했고 나머지 필드는 Python이 유지했다. 기존 시험에서 발견된 불필요한 조건 재전달은 **이번 실행에는 없었지만**, 재발하지 않는다고 증명한 것은 아니다.
- 전체 회귀 테스트 531개 성공 로그는 본 결과 파일에 포함되어 있지 않다. 소스 커밋 전에 별도로 재실행해야 한다.
