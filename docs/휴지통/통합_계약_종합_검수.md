# 제주 감귤 AI Agent 공통 계약 종합 검수

**검수 기준:** `integration/agents` 커밋 `313aeb3` · **작성일:** 2026-11-10

## 검수 결과와 보완 사항

- **데이터 계약(3-1):** 원천 가격 데이터의 SHA-256과 과거 비교 파일의 컬럼·행 수가 일치해도, 비교 가격이나 변동률이 바뀐 것은 기존 검증에서 탐지하지 못할 수 있습니다. 이 문제를 보완하기 위해 `verify_integrated_price_sources()`를 추가했습니다.
- **응답 계약(3-2):** 독립 도구의 상태·오류 사유를 `normalize_tool_result()`로 변환할 수 있습니다. 이는 아직 실제 단일 Agent 도구 목록에 연결되지 않았습니다.
- **계산 계약(3-3):** 수수료·기타 비용을 제외한 동일 조건에서 두 계산기의 손익분기가 일치하는지 검사합니다. 수수료·별도 비용 조건은 준억님 확장 계산의 별도 계약으로 검증합니다.

## 가격 비교 원천 전체 검증

`agents/common/data_contract.py`의 `verify_integrated_price_sources(project_root, market_root=None)`는 다음을 읽기 전용으로 검증합니다.

1. 기존 원천 가격 CSV와 선택된 가격 스냅샷의 해시·비교 보고서 버전
2. 원본 가격 CSV로 3·7·14일 비교쌍을 다시 계산한 결과와 기존 보고서의 날짜·품종·품질 집계
3. `price_comparisons.csv`, `price_comparison_availability.csv`의 **모든 행·모든 필드 값**과 재생성 결과의 일치 여부

기존 `verify_price_pair_sources()`는 **경량 버전 검사**로 유지합니다. 실제 가격쌍을 서비스에 연결하는 STEP 5에서는 **전체 검증 함수**를 호출해야 합니다. 전체 검증 실패(`VERSION_MISMATCH`, `PAIR_CONTENT_MISMATCH`, `REPORT_CONTENT_MISMATCH` 등) 시 가격쌍 분석을 진행하지 않습니다.

검증은 보고서나 가격 CSV를 덮어쓰지 않으며 API 키도 필요하지 않습니다. 원천 또는 생성 규칙이 변경되면 같은 입력을 바탕으로 비교 자료를 재생성하고 테스트해야 합니다.

## STEP 4~5 진입 조건과 주의사항

- `ScenarioStore`와 단일 Agent 실행 구조를 기준으로 하고, 손익 계산 서비스 엔진은 한 개만 선택합니다. 두 계산 엔진의 기본 조건 교차 검산은 유지합니다.
- 거래조건 일곱 항목의 **원천 코드**와 표시명을 혼동하거나, 원본의 `미상`을 사용자 `null` 대신 자동 선택하지 않습니다.
- 가격쌍 조회는 전체 버전 검증을 **먼저 통과**해야 합니다. 과거 경락가격을 미래가격·실수취 단가·수익 확률로 바꾸지 않습니다.
- 도구 어댑터의 `data`는 **원본 전체 복사본**이므로 그대로 LLM에 전달하면 안 됩니다. 특히 실제 출하·정산 금액과 증빙은 기존 `model_receipt()` 정책대로 로컬에서만 처리해야 합니다.
- `OK`, `NO_DATA`, `NEEDS_INPUT`, `PARTIAL`, `CHECK_REQUIRED`의 의미를 하나로 합치지 않으며 화면·PDF·도구 결과의 예외 상태를 일치시켜야 합니다.
- `0일 즉시 출하`는 금액 비교 기준일 뿐 실제로 오늘 출하할 수 있다는 뜻이 아닙니다.
