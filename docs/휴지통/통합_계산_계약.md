# 통합 손익 계산 계약 — STEP 3-3

**기준:** `integration/agents` · `5e97b22` · 2026-11-10

## 검증 대상 및 원칙

- 승혁님 `agents/baseline.py`의 `calculate_break_even()`과 준억님 `agents/juneok/comparison.py`의 `compare_shipment_options()`를 비교합니다.
- **동일한 조건에서만 같은 수치를 요구합니다.** 수수료·항목별 비용이 없는 기본 비교에서 현재 금액, 남은 물량, 추가 보관비, 손익분기 단가, 사용자가 제시한 미래 단가에 따른 가상 차액을 대조합니다.
- 별도의 독립 수식도 테스트에 두어 두 엔진이 동일한 실수를 하더라도 무조건 통과하지 않게 합니다. 이 수식은 검증용이며 **세 번째 운영 계산 엔진이 아닙니다.**
- 이 단계에서는 기존 계산 함수·Agent·화면을 변경하거나 엔진을 최종 선정하지 않습니다.

## 기본 비교의 공통 범위

| 항목 | 기준 |
|---|---|
| 현재 단가 | `current_price_per_kg > 0`, 원/kg, 차감 전 총액 기준 또는 동일 비용 제외가 확인된 동등 기준 |
| 물량 | `quantity_kg > 0`, kg |
| 지연 기간 | **1~365일**(두 엔진 공통으로 유효한 범위) |
| 보관비 | `daily_storage_cost >= 0`, 전체 물량의 **하루 추가 비용**, 원/일 |
| 감모율 | `0 <= loss_percent < 100`, **해당 기간 전체 누적 감모율(%)** |
| 미래 단가 | 사용자가 지정한 값만 계산, 미입력(`None`)이면 예상 금액과 차액은 반환하지 않음 |
| 공통 비용 | 양쪽에서 같다고 확인한 비용만 제외. 출하 기준 0일은 계산상 기준이고 실제 오늘 출하 가능하다는 보장은 아님 |

기본 검증 시 준억님 엔진에는 `price_basis=gross`, 양쪽 수수료율 `0`, `cost_policy=equal_excluded`, 별도 비용 빈 배열을 명시합니다. 실제 수수료·비용이 있는 거래에 이 조건을 몰래 적용하지 않습니다.

수식은 다음과 같습니다.

```text
현재 비교 금액 = 물량 × 현재 단가
보관 후 물량 = 물량 × (100 - 전체 감모율) / 100
추가 보관비 = 지연 일수 × 하루 보관비
손익분기 단가 = (현재 비교 금액 + 추가 보관비) / 보관 후 물량
가상 지연 금액 = 보관 후 물량 × 사용자가 정한 미래 단가 - 추가 보관비
가상 차액 = 가상 지연 금액 - 현재 비교 금액
```

예시: 3,000kg·3,000원/kg·7일·하루 20,000원·감모 2%라면 기준 금액은 9,000,000원, 남은 물량은 2,940kg, 추가 보관비는 140,000원, 손익분기 단가는 약 3,108.84원/kg입니다. 원 단위 최소 단가는 올림한 **3,109원/kg**입니다.

## 확장 계산에서만 적용되는 계약

- `gross`: 수수료 **차감 전** 단가이며 현재·지연 대안에 서로 다른 수수료율을 사용할 수 있습니다.
- `commission_net`: 수수료를 이미 뺀 단가이므로 수수료를 다시 차감하지 않습니다.
- `cost_policy=itemized`: 현재와 지연 대안의 선별·포장·운송·보관 등 별도 비용을 항목별로 반영합니다. `None`은 미확인, `[]`는 해당 항목의 비용이 없음을 확인한 값입니다.
- 단가에 이미 포함된 비용의 중복 차감, 하루 보관비와 별도 `storage` 비용의 중복 입력을 거부합니다.
- 수수료율·감모율·보관비가 미확인인 경우 0으로 대체하지 않습니다. 단 `commission_net`에서 별도 수수료율은 필수 입력이 아닙니다.
- 보관기간 변경 시 감모율 재확인이 필요합니다. `storage_available` 또는 `shipping_flexible`가 거짓이면 수치 계산에 성공해도 실행 가능 여부는 `CONFLICT`입니다.
- 미래 단가 가정이 있더라도 미래 가격 예측·최적 출하일 추천으로 표시하지 않습니다.

수수료나 항목별 비용이 있는 확장 사례는 기본 엔진과 **동일 결과를 요구하지 않습니다.** 확장 엔진의 결과를 독립 수식으로 검증합니다. 실제로 어떤 엔진을 서비스에서 사용할지는 STEP 4에서 확정합니다.
