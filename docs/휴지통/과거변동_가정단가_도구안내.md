# 과거 변동 → B안 가정 단가 도구

`agents/jeonghyeon/price_scenario.py`

같은 규격의 과거 가격 변동(경고 없는 전체 사례)을 A안 단가에 대입해 B안의 **가정 단가**를 만든다. 가격 전망이 아니며, 결과의 모든 B안 단가는 `price_type: "assumption"`이다.

## 입력

| 필드 | 설명 |
|---|---|
| `variety`, `grade`, `size`, `package`, `package_kg` (+ 선택 `market_code`, `trade_type`) | 기존 과거 가격 조회와 같은 규격 조건 |
| `option_a_sale_date`, `option_b_sale_date` | A안·B안 예상 판매일 `YYYY-MM-DD`. 두 날짜의 차이가 비교 간격이 된다 |
| `option_a_price_per_kg` | A안 단가(원/kg, 사용자 가정). 없으면 과거 변동만 보여 주고 이 값을 묻는다 |

## 결과

| 상태 | 뜻 | 통합 응답 규격 |
|---|---|---|
| `OK` | 최솟값·중앙값·최댓값 변동률과 각각의 B안 가정 단가 | `OK` |
| `NEEDS_CLARIFICATION` | 판매일·규격·A안 단가 중 빠진 값을 묻는다 | `NEEDS_INPUT` |
| `INTERVAL_NOT_AVAILABLE` | 두 판매일 간격이 3·7·14일이 아님. B안 단가를 직접 입력하면 손익 비교는 계속 가능 | `NO_DATA` |
| `NO_DATA` / `NO_CLEAN_COMPARISON` | 같은 조건의 기록이나 경고 없는 사례가 없음. 직접 입력 안내 | `NO_DATA` |
| `ERROR` | 입력 오류(`INVALID_INPUT`) 또는 데이터 오류(`DATA_ERROR`) | 같음 |

실행 전에 두 파일을 `price_comparison_report.json`과 대조하고, 하나라도 다르면 계산하지 않는다(`DATA_ERROR`).

- `daily_prices.csv` ↔ `input_sha256`: 생성 당시 바이트 그대로의 해시. 줄바꿈(LF/CRLF)만 다르면 같은 자료로 본다.
- `price_comparison_availability.csv` ↔ `output_sha256`: 줄바꿈을 LF로 맞춘 뒤의 해시. `build_price_comparisons.py`가 비교표를 만들 때 같은 방식으로 기록한다. 가격 원본은 그대로인데 비교표만 예전 것으로 바뀐 경우도 막는다.

## 실행 예

```powershell
python -m agents.jeonghyeon.price_scenario --request '{"variety":"조생귤","grade":"특등급","size":"소과","package":"상자","package_kg":5,"option_a_sale_date":"2026-11-13","option_b_sale_date":"2026-11-20","option_a_price_per_kg":2500}'
```

7일 간격, 경고 없는 20쌍 기준으로 B안 가정 단가는 최솟값 −33.54% 적용 1,661.44원/kg, 중앙값 −3.63% 적용 2,409.37원/kg, 최댓값 +89.30% 적용 4,732.49원/kg이다.

## 주의
- 최솟값·최댓값은 각각 한 사례다. 중앙값은 사례 수가 짝수면 가운데 두 값의 평균이다.
- 날짜 구간이 겹쳐 사례 수를 확률로 해석하지 않는다.
- 경락가격 기준이며 농가 실수취액이 아니다.
- B안 단가를 손익 계산에 넘기는 연결은 팀 공통 입력 규격(A·B 모두 미래인 경우 포함)이 정해진 뒤 진행한다.
