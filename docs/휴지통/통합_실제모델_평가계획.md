# STEP 7-1 · 통합 제주 감귤 Agent 실제 모델 평가

**기준 브랜치:** `integration/agents`
**평가 도입 기준 커밋:** `3d9ef6b` (STEP 6-2 이후)
**평가 대상:** `agents/juneok/agent.py`의 실제 OpenAI Responses 도구 선택·실행과 `SharedWorkspace`의 Python 상태
**평가 버전:** `evals/integration_e2e_cases.json` V1, 12문항·16턴

## 기존 평가와 구분

- `evals/evaluate.py`의 30문항·33턴은 **초기 V0 베이스라인**의 평가입니다. 통합 Agent에 그대로 적용해 합격률을 주장하지 않습니다.
- `scripts/evaluate_juneok.py`의 25문항은 준억님 초기 Agent 중심의 기능 평가입니다.
- 이번 `scripts/evaluate_integrated_agent.py`는 **현재 실제 통합 Agent**의 과거 경락가격 조회·후속 조건·독립 손익 계산에 특화한 새 고정 평가셋입니다.
- `tests/test_integration_live_evaluation.py` 20개는 **평가기 자체의 무과금 테스트**이지, 모델 성능 점수가 아닙니다.
- STEP 6의 508개 단위 테스트는 모의 모델 및 실제 데이터 중심입니다. 본 평가로 대체되지 않습니다.

## 채점 기준

실제 모델이 내보낸 도구 호출 인수와 Python 실행 결과를 **각각 채점**합니다.

1. **도구 선택:** 사용자가 요청한 도구가 실제로 호출됐는지, 금지한 `update_scenario` 등을 시도하지 않았는지
2. **조건 추출:** `follow_up=true/false`, 7→14일, 규격 유지·철회, 명시되지 않은 시장/거래방식 자동 저장 여부
3. **결과 계약:** `OK`/`NEEDS_INPUT`/`NO_DATA`, 7일 20쌍·14일 15쌍, 3,109원/kg 등 실제 Python 결과
4. **상태 안전:** 과거 경락가격 조회가 현재 단가·보관일·미래 단가를 변경하지 않는지, 임의 미래가격 저장을 시도하지 않는지
5. **출처 무결성:** 통합 가격 원천 전체 검증이 성공한 조회만 `OK`로 인정
6. **독립 판정:** 문항의 모든 턴이 통과해야 문항이 통과합니다. 일부 성공은 별도 기록하되 최종 합격으로 처리하지 않습니다.

실제 가격은 동결 자료만 사용합니다. 과거 가격은 **미래가격 예측이 아니며 농가 실수취가격이 아닙니다**. B안 가정 단가 생성 도구(`get_price_scenarios`)는 통합 모델에 등록하지 않은 상태를 유지합니다.

평가셋을 실행한 뒤 예상치 못한 실패가 나왔다고 **질문이나 정답을 수정해 성공률을 높이지 않습니다**. 실패 원인을 소스·모델 인수·상태 전이 관점에서 먼저 검토하고, 변경 평가가 필요하면 별도 V2 파일을 만듭니다.

## 실행 방법 — Windows CMD

먼저 프로젝트 루트 `C:\SKN projects\jeju-ai-agent-integration`에서 다음 명령을 실행합니다.

```bat
.\.venv\Scripts\python.exe -m unittest discover -s tests -p "test_integration_live_evaluation.py" -v
.\.venv\Scripts\python.exe -m scripts.evaluate_integrated_agent --list
.\.venv\Scripts\python.exe -m scripts.evaluate_integrated_agent --validate
```

여기까지는 **OpenAI API를 호출하지 않으며 과금하지 않습니다**. `--validate`는 실제 가격 원천 전체 검사 및 7일·14일 비교쌍 검증까지 수행합니다.

### 실제 모델 호출 — 명시적 선택 시에만

프로젝트의 `.env`에 `OPENAI_API_KEY`가 설정돼 있어야 합니다. 모델은 기본적으로 앱의 `OPENAI_MODEL` 값을 사용하고, 없으면 통합 Agent 기본 모델을 사용합니다. 구체적인 가격은 모델·과금 설정에 따라 달라지므로 미리 임의의 금액으로 계산하지 않습니다.

```bat
REM 1문항만 실행 (첫 실제 모델 확인)
.\.venv\Scripts\python.exe -m scripts.evaluate_integrated_agent --live --case INT-01

REM 후속 조건과 손익 분리 검증 (선택 문항 3개)
.\.venv\Scripts\python.exe -m scripts.evaluate_integrated_agent --live --case INT-02 --case INT-07 --case INT-08

REM 전체 12문항 · 16자연어 턴 · 1회 반복
.\.venv\Scripts\python.exe -m scripts.evaluate_integrated_agent --live --all
```

모델 하나의 자연어 턴마다 하네스가 최대 6회 모델 요청을 허용합니다. **12문항·16턴 전체 반복 1회는 최악의 경우 모델 요청이 최대 96회**일 수 있으므로 스모크 평가 결과를 확인하기 전에 전체를 실행하지 마세요. `--repeat 2`는 유료 요청이 늘어납니다. 실평가만 `--live`로 실행하며, 대상은 반드시 `--case` 또는 `--all`로 명시합니다.

## 결과 파일과 전달할 내용

평가기 실행마다 새로운 `artifacts/integration-e2e/날짜_시각/` 폴더를 만들고 이전 결과를 덮어쓰지 않습니다. `artifacts/`는 `.gitignore`에 포함됩니다.

| 파일 | 내용 |
|---|---|
| `metadata.json` | 모델, 선택 문항, 소스·CSV·평가셋 SHA-256, 사전검증, 실행 시작 시각 |
| `summary.json` | 전체/범주별 통과 수, 실패 원인, 모델 요청·토큰 사용량, 중단 이유 |
| `cases.jsonl` | 문항별/턴별 모델 도구 인수, Python 결과, 사용자에게 표시한 문장, 상태 전이 |

**우선 `summary.json`과 `cases.jsonl` 두 파일**을 전달하면 실패 원인을 분석할 수 있습니다. `metadata.json`도 함께 보내면 비교 가능한 버전인지 확인할 수 있습니다. 전송 전에 평가 입력에 개인 정보를 추가하지 않았는지 확인하세요. 본 평가셋은 가상 시나리오만 사용합니다. 결과에는 API 키와 HTTP 요청 헤더를 저장하지 않습니다.

실행 도중 인증 오류·API 요청 제한·통신 오류 등이 발생하면 나머지 문항을 자동으로 계속 실행하지 않습니다. 평가 결과는 완료된 건까지 저장합니다. 결과의 `estimated_cost_usd`는 요금표를 확인하지 못한 상태에서 임의 계산하지 않기 때문에 `null`입니다.

## STEP 7 이후 통과 기준

모든 문항이 통과하면 **고정된 12개 통합 시나리오에서의 1회 실행 성공**까지만 주장합니다. 실제 농가 사용자 대상 실증·일반적인 프롬프트 성공률·미래가격 예측 정확도를 증명하는 것은 아닙니다.

실패 문항이 있으면 심각도를 나눕니다. **과거 가격을 미래 사실로 오인시키거나 무단으로 단가를 저장하는 상태 오염**은 우선 해결 대상입니다. 나머지는 도구 선택 실패/후속 맥락 오류/잘못된 자료 처리/단순 출력 계약으로 나눠 재현한 뒤 수정합니다. 이후 평가셋을 고정한 채 회귀 평가하고 전체 UI의 사람 검수로 넘어갑니다.
