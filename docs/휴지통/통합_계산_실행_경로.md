# STEP 4-1. 출하 손익 계산 실행 경로 통일

## 결정

- **서비스 계산 엔진:** `agents/juneok/comparison.py`의 기존 `compare_shipment_options()` 한 개를 사용합니다.
- **공통 진입점:** `agents/common/calculation_service.py`의 같은 이름 함수가 실행을 위임하고 STEP 3-2의 공통 응답 상태 계약을 점검합니다.
- **독립 검산:** `agents/baseline.py`의 `calculate_break_even()`은 회귀 테스트·교차 검산용으로 유지합니다. 서비스 요청마다 함께 실행하지 않습니다.
- **출력 호환성:** 계산 성공·입력 부족·입력 오류의 기존 반환값을 그대로 유지합니다. 공통 상태가 다르게 해석되면 `DATA_ERROR`로 종료합니다.

## 수정 범위

직접 계산 도구, 브리핑, 조건 설명, 민감도, 허용 조건 역산, Agent의 조건 부족 안내에서 같은 공통 진입점을 사용합니다. 계산 공식을 중복 구현하거나 기존 UI·가격 CSV·개별 CLI를 변경하지 않습니다.

## 검증 기준

1. 기존 3톤·7일·감모 2%·하루 2만 원 사례의 최소 정수 손익분기 단가는 **3,109원/kg**으로 유지합니다.
2. 단순 동일 조건에서 독립 검산 계산기와 소수점 반올림 전 값이 일치해야 합니다.
3. 원래 입력을 변경하지 않고, 하나의 계산 요청에 기본 계산기를 한 번 호출해야 합니다.
4. `NEEDS_INPUT` 등 기존 도구 출력은 변경하지 않으며, 알 수 없는 공통 상태는 성공으로 처리하지 않습니다.
5. 정산 기록은 기존과 같이 로컬에서 처리하고 모델에 상세 금액을 전달하지 않습니다.
6. 시장 경락가격을 사용자의 실제 판매 단가로 자동 대입하지 않습니다.

## 이번 단계의 한계

STEP 4-1은 기존 Juneok 실행 경로를 단일 계산 진입점으로 모읍니다. **정현님의 과거 가격 조회를 서비스 도구로 등록하지 않으며**(STEP 5), 3개 독립 대화 Agent를 하나의 LLM으로 합치는 작업도 추가로 수행하지 않습니다. 승혁님의 기본 CLI Agent도 그대로 보존합니다.
