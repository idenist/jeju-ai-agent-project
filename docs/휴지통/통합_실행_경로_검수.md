# 통합 실행 경로 종합 검수

**대상 브랜치:** `integration/agents`
**기준 커밋:** `0d8dc08`
**단계:** STEP 4-2

## 목적

STEP 4-1에서 통일한 손익 계산 진입점이 **직접 입력, 모델 도구 호출, 민감도, 역산, 종합 브리핑, 보고서, 정산 기록**에서도 일관되게 사용되는지 검증합니다. 신규 AI 기능이나 가격 예측을 추가하는 작업은 아닙니다.

## 변경 내용

- `agents/juneok/settlement.py`의 과거 비교 조건 검산도 `agents.common.calculation_service.compare_shipment_options`를 사용하도록 수정합니다.
- `agents/juneok/comparison.py`는 유일한 실제 서비스 손익 계산 엔진으로 유지합니다.
- `agents/baseline.py`는 별도의 기존 계산·평가 검증 기준으로 보존합니다.
- `tests/test_integration_execution_routes.py`를 추가하여 모의 모델 응답 및 오프라인 실행으로 경로를 검증합니다.

## 검증 기준

| 확인 항목 | 완료 조건 |
|---|---|
| 단일 계산 진입점 | 업무 실행 모듈은 공통 계산 서비스만 호출. 정산 초기 비교도 동일 |
| 직접 입력과 모델 호출 | 같은 시나리오에서 `3109원/kg` 등 계산 결과 일치, 모델의 임의 숫자 미사용 |
| 민감도·역산·브리핑 | 기존 조건 보존, 별도 서비스 엔진 생성 없음 |
| 보고서 | Markdown과 PDF가 동일한 검증 결과를 표시 |
| 상태 변경 | 시나리오 버전이 바뀌면 오래된 결과 숨김 |
| 정산 개인정보 | 사용자 카드의 상세 정산 금액·근거는 로컬 표시. 모델 요청에는 금액 없는 처리 상태만 전달 |
| 기존 기능 | 기존 테스트를 유지하고 새로운 회귀 실패 없음 |

## 실행 명령

Windows CMD, 프로젝트 루트:

```bat
.\.venv\Scripts\python.exe -m unittest discover -s tests -p "test_integration_execution_routes.py" -v
.\.venv\Scripts\python.exe -m unittest discover -s tests
.\.venv\Scripts\python.exe -m unittest discover -s evals -p "test_*.py"
git --no-pager diff --check
```

테스트는 모의 OpenAI 응답과 로컬 Python 계산을 사용합니다. 새로운 실제 API 과금을 유발하지 않습니다.

## 통합 범위와 한계

이 검증은 서비스 계산 실행 경로와 기존 UI/보고서의 재현성을 확인하는 것입니다. 실제 농가 수익, 미래 가격 예측, 운영 환경에서의 실증을 보증하지 않습니다.

정현님 과거 가격 조회 기능을 단일 Agent 도구로 등록하는 작업은 **STEP 5**에서 수행하며, 그 전에 STEP 3의 원천 해시 검증을 필수로 연결해야 합니다.
