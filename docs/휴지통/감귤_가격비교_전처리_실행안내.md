```powershell

```


파일·결과 폴더 또는 간격 변경:

```powershell
python scripts/build_price_comparisons.py --input data/processed/daily_prices.csv --out-dir data/processed --report-dir data/reports --intervals 3 7 14
```

간격은 1~366 사이 양의 정수를 받으며, 중복 간격은 한 번만 처리한다. 기본 범위는 3·7·14일이다. 기존 결과에 이어 붙이지 않고 새 입력 전체로 재생성한다.

## 4. 비교 규칙

### 비교 키

날짜를 제외하고 아래 **일곱 항목**이 같아야 연결한다.

```text
market_code, variety_code, grade_code, size_code,
package, package_kg, trade_type
```

`package_kg`는 숫자로 비교하므로 `5`, `5.0`, `5.000`은 같다. 다른 크기·등급·시장·품종·포장·거래방식으로 범위를 임의로 넓히지 않는다.

같은 날짜와 정규화한 비교 키가 중복되면 덮어쓰기·합산하지 않고 오류로 중단한다. 날짜·필수 컬럼·유한한 양수 가격/중량/금액/포장중량·양의 정수 거래 건수를 확인한다. 표시 가격과 `total_amount_krw / total_kg`가 0.01원/kg 넘게 다르면 중단한다. 계산 검증 후 결과를 저장하며 입력과 같은 출력 경로를 허용하지 않는다.

### 날짜와 가격 계산

- `target_date = base_date + interval_days`.
- **달력일 기준**이며 거래일 수를 세지 않는다. 정확한 날짜의 자료가 없으면 보간·가까운 거래일 연결을 하지 않는다.
- 가격차(원/kg) = 비교일 표시 가격 − 기준일 표시 가격.
- 변동률(%) = (비교일 표시 가격 / 기준일 표시 가격 − 1) × 100.
- 입력 `avg_price_kg`의 소수점 둘째 자리 표시값을 사용한다. 원거래로 돌아가 재집계한 가격은 아니므로 미세한 반올림 차이가 있을 수 있다.
- 변동률은 % 단위다. `10.000000`은 **10%**를 뜻하며 비율 0.1과 구분한다.

같은 물량을 7일 보관해 판 결과를 추적한 자료가 아니다. 다른 날짜에 같은 표준 분류로 관측된 거래 집계끼리 비교한다.

## 5. 결과 컬럼

| 컬럼 묶음 | 의미 |
|---|---|
| `base_date`, `target_date`, `interval_days` | 기준일, 정확한 비교 대상일, 달력일 간격 |
| 비교 키 7개 | 동일 조건 여부를 결정하는 값 |
| `market`, `variety`, `grade`, `size` | 기준행의 표시명. 같은 코드의 표시명이 두 날짜에서 다르면 경고 |
| `base_price_kg`, `target_price_kg` | 양쪽 원/kg 가격 |
| `price_change_krw_kg`, `price_change_pct` | 원/kg 차이, % 변동률 |
| `base_total_kg`, `target_total_kg` | 양쪽 집계 거래물량(kg) |
| `base_transaction_count`, `target_transaction_count` | 양쪽 원거래 건수 |
| `base_quality_flag`, `target_quality_flag` | 기존 정제 결과의 품질 표시 원문 |
| `both_source_ok` | 양쪽 기존 표시가 정확히 `OK`인지. CSV 문자열 `true` / `false` |
| `comparison_status` | 아래 비교 상태 |
| `comparison_warnings` | 기존·추가 경고를 세미콜론으로 연결 |
| `unavailable_reason` | 연결하지 못한 이유. 연결된 쌍이면 빈 값 |

### 비교 상태

| 값 | 뜻 | 권장 사용 |
|---|---|---|
| `COMPARABLE` | 동일 조건 연결, 현재 규칙에서 경고 없음 | 에이전트의 기본 사례 후보 |
| `COMPARABLE_WITH_WARNINGS` | 동일 조건 연결은 됐지만 품질·표시명 등 경고 있음 | 경고와 함께 참고로 제공, 무조건 기본 사례로 쓰지 않기 |
| `UNAVAILABLE` | 정확한 비교일·동일 조건이 없음 | 비교 불가 사유 설명 |

기존 품질 표시를 보존하면서 거래 5건 미만, 등급·크기 미상, 비교 키 일부 미상, 품질 표시 누락을 추가 확인한다. 같은 코드라도 표시명이 달라지면 `LABEL_MISMATCH`를 남긴다. 따라서 새 자료에서는 양쪽 원본 `OK` 쌍과 추가 점검 후 `COMPARABLE` 쌍의 수가 다를 수 있다.

`LOW_SAMPLE`의 5건은 기존 전처리와 맞춘 경고 기준이며, 정확성을 보장하는 통계적 기준은 아니다.

### 비교 불가 사유

| 값 | 뜻 |
|---|---|
| `OUTSIDE_OBSERVED_RANGE` | 비교일이 해당 시장의 정제 가격 최초·최종 관측일 밖 |
| `NO_MARKET_OBSERVATION_ON_TARGET_DATE` | 관측기간 안이지만 비교일에 해당 시장의 정제 가격 행이 전혀 없음 |
| `NO_MATCHING_CONDITION` | 비교일에 해당 시장의 가격은 있으나 일곱 비교 조건이 같은 행은 없음 |

이 구분은 **정제 가격 파일에 있는 정보만으로** 판단한다. 원본 수집 실패, 필터 제외, 휴장, 실제 거래 없음 중 무엇 때문인지는 별도 자료 없이 확정하지 않는다. 특히 `NO_MARKET_OBSERVATION_ON_TARGET_DATE`를 ‘휴장일’로 바꾸어 설명하지 않는다.

## 6. 에이전트에서 사용하는 예시

Python 표준 라이브러리만 쓰는 조회 예시:

```python
import csv

with open("data/processed/price_comparisons.csv", encoding="utf-8-sig", newline="") as f:
    candidates = [
        r for r in csv.DictReader(f)
        if r["interval_days"] == "7"
        and r["variety_code"] == "01"
        and r["comparison_status"] == "COMPARABLE"
    ]
```

품종·등급·크기·포장 등 사용자가 정한 조건까지 좁힌다. 결과가 없다면 `price_comparison_availability.csv`의 기준일·조건·간격을 조회해 비교 불가 이유를 설명한다. **불가 행의 비교가격·변동률 빈 값을 0이나 0%로 채우지 않는다.**

오늘을 기준으로 미래 7일 가격을 조회하는 용도가 아니다. 실제 관측된 과거 날짜쌍을 설명하고, 보관 손익은 별도의 사용자 가정·손익 계산 함수에서 처리한다.

## 7. 현재 스냅샷 실행 결과

입력: 2026-10-01 ~ 2026-11-03 서울가락시장 상세 가격 1,592행, 비교조건 161개.

| 달력일 간격 | 연결된 날짜쌍 | 양쪽 원본 OK | 추가 점검 후 경고 없음 |
|---|---:|---:|---:|
| 3일 | 843 | 291 | 291 |
| 7일 | 850 | 290 | 290 |
| 14일 | 606 | 214 | 214 |

연결된 날짜쌍 합계 2,299행, 전체 시도 4,776행, 비교 불가 2,477행이다. 날짜쌍은 기준일·규격이 겹칠 수 있으므로 독립 표본 2,299개로 해석하지 않는다.

7일 양쪽 원본 OK 쌍은 조생귤 80, 온주 76, 하우스감귤 134개다. 현재 극조생은 같은 조건으로 연결된 쌍이 82개 있지만 양쪽 원본 OK는 0개다. 원인·품질 표시와 데이터 범위를 확인해야 하며 극조생 전체가 분석 불가능하다고 일반화하지 않는다. 시연 품종 선택은 데이터 범위와 저장 적합성을 함께 검토할 팀의 판단사항이다.

상세 품종·규격과 대표 날짜쌍은 `data/reports/price_comparison_coverage.md`에 있다. 대표 사례는 변동률이 가장 큰 것을 고르지 않고 **품종별 양쪽 최소 거래 건수**, 양쪽 물량, 날짜·규격을 기준으로 재현 가능하게 고른다.

## 8. 검증 범위

`python -m unittest discover -s tests -v`로 17개 테스트를 통과했다.

- 상승·하락·가격 변화 없음의 변동률 계산.
- 달력일·정확한 날짜 연결, 가까운 날짜 임의 선택 방지.
- 일곱 비교 키 각각의 불일치 차단.
- 5와 5.000의 중량 동등성 및 같은 날짜·키의 중복 차단.
- 품질 미상·적은 거래 건수·원본 경고·표시명 불일치 처리.
- 잘못된 날짜·숫자·거래 건수·가격/금액/중량 불일치·빈 입력·컬럼 누락 거부.
- 출력이 입력을 덮어쓰지 않음, 파일 해시·보고서·반복 실행 일치.
- 현재 CSV를 독립적인 키·날짜 연결 방식으로 재계산한 쌍 수와 대조.

기존 경매 원본 수집의 완전성·품종 코드의 농업적 동등성·저장 손실 가정의 타당성은 이번 가격 비교 작업의 검증 범위 밖이다. 기존 전처리 스크립트와 원본·정제 CSV는 변경하지 않았다.
