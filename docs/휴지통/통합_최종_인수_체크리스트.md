# STEP 8 통합 Agent 최종 인수 체크리스트

**대상:** `integration/agents` 브랜치. **현재 확인된 기준 커밋:** `9e4acd5`(STEP 7 실제 모델 평가 및 도구 선택 개선). 이후 수정 시 커밋과 검증 기록을 다시 확인합니다.

## 1. 인수 판단의 기준

단계별 단위 테스트 성공과 실제 모델 평가 성공은 서로 다른 근거입니다. 또한 **기술 검수 통과는 실제 농가 배포 또는 `main` 병합 승인과 다릅니다.** 검증된 사실과 아직 검증되지 않은 판단을 다음처럼 나눕니다.

| 확인 항목 | 현재 근거 | 인수 시 처리 |
|---|---|---|
| 원천 가격 데이터 | `daily_prices.csv`와 동일 규격 과거 가격쌍 4,776행 전체 재생성 검증 | 점검 명령에서 `full_content_verified=true` 확인 |
| 손익 계산 | 단일 `agents/common/calculation_service.py` 경유, Decimal 계산과 독립 검수 | 전체 단위 테스트 재실행 |
| UI | API 키 없는 과거 경락가격 조회·조건 카드·PDF 및 대화 전환 | Streamlit 자동 검수와 사람의 화면 확인 구분 |
| 모델 평가 | `gpt-6-luna` 실제 API, 정해진 12문항·16턴을 수정 후 1회 평가하여 12/12 통과 | 기록의 소스 SHA-256이 현재 코드와 일치하는지 재검증 |
| STEP 7 회귀 테스트 | 수정 전 UI 단계 508개 통과 확인, STEP 7 신규 검사 23개 추가 | 최종 전체 테스트 **531개+이번 인수 테스트 12개 = 543개** 예상, 실제 로그로 확정 |
| 외부 사용성 | 실제 농가·비전문가 검증 없음 | 배포 성공이라고 표기 금지 |

## 2. 실행 환경과 시작

Windows CMD, 프로젝트 루트에서 실행합니다. Python **3.13 x64 및 Python launcher**로 제공된 설치 스크립트를 사용합니다.

```bat
REM 새로운 설치 환경
 git clone --branch integration/agents https://github.com/idenist/jeju-ai-agent-project.git
 cd jeju-ai-agent-project
 setup-center.cmd
 run-juneok.cmd
```

이미 `C:\SKN projects\jeju-ai-agent-integration`에서 개발 중이라면 기존 `.venv`를 사용하고, `integration/agents` 브랜치가 최신인지 `git status --short`와 `git log -1 --oneline`으로 확인합니다. 모델 대화에만 `.env`의 `OPENAI_API_KEY`가 필요하며, **자료 조회·조건 카드·검증 스크립트에는 실제 모델 호출 비용이 발생하지 않습니다.** 새 clone의 가격 자료는 실시간 가격이 아니라 동결 CSV입니다.

- 사용자 진입점: `app.py` (`run-juneok.cmd` 실행)
- 손익 도구의 단일 경유점: `agents/common/calculation_service.py`
- 과거 경락가격: `agents/common/price_history_service.py` → `agents/jeonghyeon/price_history.py`
- 평가 셋과 실행기: `evals/integration_e2e_cases.json`, `scripts/evaluate_integrated_agent.py`
- 기존 V0 평가기와 베이스라인: `evals/evaluate.py`, `agents/baseline.py`. **현재 통합 Agent 전체 E2E 점수로 대체해서는 안 됩니다.**
- 정현님 `get_price_scenarios`는 독립 연구·변환 모듈로 보존되어 있지만, 통합 Agent의 활성 도구와 손익 카드에는 **자동 연결하지 않았습니다.**

## 3. 최종 인수 점검기 (무과금)

`artifacts/integration-e2e`에 12문항 전체 평가 결과가 남아 있어야 합니다. 가장 최근 **전체 12문항 실행**을 자동 선택하므로, INT-04 단건 재실험을 실수로 선정하지 않습니다.

```bat
.\.venv\Scripts\python.exe -m scripts.verify_integration_handoff --full
```

기록 경로를 명시하려면:

```bat
.\.venv\Scripts\python.exe -m scripts.verify_integration_handoff --full --evidence "artifacts\integration-e2e\전체평가_폴더명"
```

검증기가 자동으로 확인하는 사항:

1. 평가 메타데이터의 모델·12문항·16턴·실제 API 호출 표시가 `summary.json`, `cases.jsonl`과 일치하는지 확인합니다.
2. 평가 당시 `app.py`, Agent, 공통 서비스, 평가셋, 데이터 등 핵심 파일의 SHA-256이 **현재 로컬 작업본**과 일치하는지 확인합니다. 코드 변경 후 옛 결과를 현재 성능으로 재사용하지 않습니다.
3. 원천 CSV에서 과거 가격쌍 전체를 다시 만들었을 때 데이터·보고서·기존 가격쌍이 동일한지 확인합니다. 활성 `get_price_scenarios` 오연결도 차단합니다.
4. 전체 `tests` 회귀 테스트, `evals`의 평가 코드 테스트, 통합 평가셋 `--validate`를 순서대로 실행합니다. 모두 **실제 모델 API 호출 없이** 실행합니다.
5. `.env`, `.venv`, `artifacts/` 등의 추적 금지 파일과 현재 Git 브랜치, 작업트리 청결 여부를 확인합니다.

실행 결과는 `artifacts/integration-handoff/<실행시각>/summary.json` 및 `검증_1.log` ~ `검증_3.log`에 남습니다. `status=PASS`는 **기술 검증**만 통과했다는 뜻입니다. `--full` 없이 실행했을 때는 `PREFLIGHT_PASS`이며 전체 테스트 완료를 의미하지 않습니다.

검증 파일을 커밋한 뒤 **작업트리까지 깨끗한 상태**에서 다시 확인하려면:

```bat
.\.venv\Scripts\python.exe -m scripts.verify_integration_handoff --full --require-clean
```

`artifacts/`는 Git에서 제외됩니다. 평가 원문을 다른 사람에게 전달하기 전에 질문·대화·로컬 경로 등 민감 정보가 없는지 확인합니다. 평가 요약은 [`통합 실제모델 전체평가 결과`](통합_실제모델_전체평가_결과_20261110.md)에 이미 기록돼 있습니다.

## 4. 수동 검토가 필요한 잔여 문제

- **INT-04 입력 누락:** 사용자 명시 등급 `특`, 크기 `소`를 모델이 `null`로 넘겨 품종 이외 조건도 다시 물었습니다. 기존 채점 기준 12/12 통과를 취소할 이유는 없지만 **입력 추출이 완전하다는 증거는 아닙니다.** 후속 개선 시 독립 평가셋을 추가하고 기존 고정 평가셋은 조용히 수정하지 않습니다.
- **INT-11 중량 충돌 안내:** `10kg` 포장 표기와 `5kg` 별도 중량 간 모순에서 숫자 자동 확정은 하지 않았으나, 일반적인 재질문만 표시했습니다. 모순 원인을 직접 설명하도록 개선할 필요가 있습니다.
- **실제 출하의 실행 제약:** 0일 기준은 즉시 출하가 가능하다는 뜻이 아니며, 저장시설·계약·납품 시점·운송 가능성은 별도로 확인해야 합니다. 과거 시장 경락가격은 동일 물량 보관의 효과나 농가 실수취가가 아닙니다.
- **데이터 활용 조건:** 제주데이터허브 #855 원본 데이터의 개별 재배포·이용조건과 외부 자료 출처 표기를 최종 확인해야 합니다.
- **사람 사용성:** 실제 농가/비전문가를 통한 화면 이해도·오류 복구·농가 수익 효과는 아직 검증하지 않았습니다.

## 5. `main` 병합 전에 반드시 남길 증거

| 단계 | 산출물/결정 | 판정 |
|---|---|---|
| 소스 동결 | 작업트리 깨끗함, 원격 `integration/agents` 최신 커밋 | 미확인 시 중단 |
| 기계적 검증 | `scripts.verify_integration_handoff --full --require-clean`의 `PASS` 결과 | 필수 |
| 실제 모델 결과 | 평가 메타·요약·전체 문항의 소스 해시 일치 | 필수 |
| 데이터·라이선스 | 해시 검증·#855 이용범위 확인 | 대외 배포 전 필수 |
| UX 위험 | INT-04/INT-11 알려진 한계의 처리 결정 | 팀 인수 시 명시 |
| 팀 승인 | 통합 Agent를 대표 서비스로 채택하는지 명시적 합의 | **승인 전 `main` 병합 금지** |

승인과 검증을 마친 뒤에는 `integration/agents`에서 `main`으로 Pull Request를 올려 변경 내역을 리뷰합니다. 베이스라인·개인 브랜치는 삭제하지 않습니다. `main`에 병합했다고 자동으로 배포가 끝난 것은 아닙니다.
