# 02. 시스템 설계서

> **기준:** 2026-11-07 · `seunghyuk` 브랜치 실제 코드 · [01 기능 명세](01_요구사항_및_기능명세서.md) · [05 실행·테스트](05_실행_및_테스트_가이드.md)
>
> **이 문서의 역할:** 기능이 실제로 어떻게 구현되어 있는지, 어떤 데이터가 어디를 거쳐 흘러가는지를 설명합니다. 미래에 만들 기능은 현재 구조에 섞어 쓰지 않습니다.

## 1. 구성 요소와 책임

```text
사용자(CMD: 질문>)
    │ 자연어 질문
    ▼
agents/agent.py
    ├─ main()               환경변수·CLI·대화 상태 관리
    ├─ run_turn()           Responses API 요청/응답·도구 실행 반복
    │    ├─ get_market_price()   ← 가격만 문의할 때
    │    └─ compare_shipping()   ← 경제성 비교(내부 가격 조회 포함)
    │           │
    │           ▼
    └───── agents/baseline.py
              ├─ load_price_observations()   동일 규격의 날짜별 가격 조회
              ├─ calculate_break_even()     Decimal 기반 경제성 계산
              └─ fixed()                    결과 표시용 반올림
                        │
                        ▼
         data/processed/daily_prices.csv
                        │
                        ▼
         Python 검증된 숫자 보고서 또는 LLM 추가 질문
```

| 요소 | 현재 역할 | 주의 사항 |
|---|---|---|
| `agents/agent.py` | LLM 대화와 호출 조정, JSON 인수 처리, 최종 보고서 | 예측모델·자체 가격 DB 없음 |
| `agents/baseline.py` | CSV 조회, `Decimal` 손익 계산 | LLM 없이도 CLI 단독 실행 가능 |
| `data/processed/daily_prices.csv` | 실제 도매시장 경매 기록의 일자별 동일 조건 집계 | 최신 **확보된** 관측값이지 실시간 시세 아님 |
| `data/processed/daily_variety_prices.csv` | 품종별 참고용 가격 동향 | **현재 Agent 미사용**, 등급·크기 혼합 |
| `data/processed/daily_shipments.csv`, `monthly_shipments.csv` | 과거 신고소별 제주 출하량 집계 | **현재 Agent 미사용**, 가격자료와 기간·분류 다름 |
| `scripts/` | 추가 원본 수집 및 전처리 | Agent 실행 시 자동 실행하지 않음 |
| `tests/` | 계산·도구호출·환경·수치 테스트 | 온라인 모델 전체 행위를 보증하는 테스트는 아님 |

## 2. 실제 Tool Calling 처리 단계

1. `main()`이 프로젝트 루트 `.env`를 읽고 OpenAI API 클라이언트를 생성합니다. 이미 OS에 동일 환경변수가 있으면 해당 값이 우선합니다.
2. 사용자가 질문하면 `run_turn()`이 **시스템 지침**, **등록된 도구 2종**, 사용자 질문을 Responses API에 전달합니다. `tool_choice="auto"`, `parallel_tool_calls=False`로 설정합니다.
3. 모델의 `response.output`에서 `function_call` 항목을 찾습니다. 모델은 도구를 **선택하고 인수를 작성**하지만 Python 코드를 직접 실행하지는 않습니다.
4. Python이 `call.arguments`의 JSON을 읽고 `execute_tool()`의 **허용된 함수 목록**에서 이름을 확인합니다. 요구된 입력 필드와 실제 JSON 필드가 정확히 일치하는지 검사합니다.
5. 선택된 `get_market_price()` 또는 `compare_shipping()`이 `baseline.py`를 통해 CSV를 읽거나 손익을 계산합니다. 예외는 `{"error": ...}` 형태로 도구 결과에 담깁니다.
6. Python이 `function_call_output`에 **같은 `call_id`**를 넣어 도구 결과를 API로 반환합니다. `previous_response_id`를 이용해 동일 대화 흐름을 이어갑니다.
7. 모델의 최종 응답까지 반복합니다(최대 도구 호출 라운드 5회). **도구가 성공했다면** LLM의 숫자 문장을 사용하지 않고 `format_verified_result()`가 Python 결과를 표시합니다. 도구 호출이 없거나 오류가 있으면 모델의 질문·설명을 그대로 사용합니다.

**중요:** `compare_shipping`이 내부에서 가격을 조회하므로, 시연에서 `[도구 호출] compare_shipping`만 표시되어도 정상입니다. 대화가 이어질 때는 이전 `response.id`를 보관해 후속 질문의 문맥을 연결합니다.

## 3. 도구별 데이터 흐름

### `get_market_price` (F-02)

`_validated_options()` → `load_price_observations()` → `_observation_info()` 순서로 실행합니다.

- **입력:** `variety`, `grade`, `size`, `package_kg` (모두 필수).
- **필터:** 시장코드 `110001`, 품종·등급·크기, 포장 `상자`, 포장중량, `trade_type=경매`가 일치해야 합니다.
- **날짜:** CSV에 있는 관측일을 정렬한 뒤 가장 마지막 날짜를 반환합니다.
- **단가:** 해당 날짜의 `sum(total_amount_krw) / sum(total_kg)`으로 계산합니다. CSV의 표시용 `avg_price_kg`를 다시 평균내지 않습니다.
- **반환:** 최신 관측일, 가격(원/kg), 총중량, 거래건수, 품질 경고. 일치 거래가 없으면 `has_price=false`.

### `compare_shipping` (F-03·F-04·F-06)

`_validated_options()` → 기준가격 결정 → `calculate_break_even()` → `_observation_info()` → 결과 사전 반환.

- `current_price_per_kg=null`: CSV의 최근 가격 사용. 해당 규격 거래가 없으면 오류.
- `current_price_per_kg`에 값이 있으면: 사용자 입력 기준가격 사용. CSV가 존재하면 관측일·관측가격은 참고로 따로 제공.
- `future_price_per_kg=null`: **미래 단가를 예측하지 않음**. 손익분기 조건만 제공.
- `future_price_per_kg`에 값이 있으면: 그 가격을 가정했을 때 지연 후 순금액 및 즉시 출하 대비 차액을 계산.
- `delay_days=N`: 최근 관측일로부터 정확히 N **달력일 전**의 동일 규격 거래가 있으면 과거 한 구간의 가격 변동을 표시. 없으면 생략.

### `calculate_break_even()`의 수학적 의미

```text
현재 매출         = Q × P₀
보관 후 물량      = Q × (1 − r/100)
추가 보관비       = d × C
손익분기 단가     = (현재 매출 + 추가 보관비) / 보관 후 물량
필요 상승률(%)    = (손익분기 단가 / P₀ − 1) × 100
가정 순금액       = 보관 후 물량 × 사용자 가정가격 − 추가 보관비
가정 손익 차액    = 가정 순금액 − 현재 매출
```

- `Q`: 물량(kg), `P₀`: 현재 비교 기준단가(원/kg), `r`: 전체 감량률(%), `d`: 보관일수, `C`: 하루 보관비(원).
- 계산에는 **Python `Decimal`**을 사용하고, 표시할 때만 반올림합니다. 원/kg 정수로 안내할 때는 손익분기 단가를 **올림**합니다.
- 운송비·수수료 등 **두 선택지에 공통인 비용**은 비교에서 제외합니다. 보관으로 추가되는 기타 비용은 현재 모델에 상세 반영되지 않습니다.

## 4. 왜 LLM 숫자를 그대로 출력하지 않는가?

실제 관측자료의 `117,667,000원 ÷ 48,090kg`는 표시용 단가로 약 `2,446.81원/kg`입니다. 화면에 표시된 단가에 3,000kg을 곱하면 **7,340,430원**이지만, **원래 나눗셈의 반올림 전 값**으로 계산하면 원 단위 매출은 **7,340,424원**입니다.

이 때문에 `run_turn()`은 성공한 분석 도구의 결과를 따로 보관하고, **LLM이 생성한 숫자 포함 응답 대신** `format_verified_result()`가 검증된 필드를 보고서로 구성합니다. 이는 정상 도구 결과에 대한 보호이며, 도구를 호출하지 않은 모든 LLM 서술까지 보증하는 장치는 아닙니다.

## 5. 예외·보안·운영 설계

| 상황 | 현재 처리 |
|---|---|
| 필수 규격 누락 | LLM에 추가 질문하도록 지시. 호출 후 빈 값은 `_validated_options`가 오류 처리 |
| 금액·감량률·일수 오류 | `calculate_break_even`에서 범위 검사 후 오류 반환 |
| 일치하는 시장가격 없음 | 가격 조회는 `has_price=false`, 비교는 사용자 기준가격도 없으면 오류 |
| 모델이 등록되지 않은 도구 요청 | `execute_tool`에서 거부 |
| 도구 입력 JSON 오류·필드 불일치 | 오류 결과를 LLM에 반환 |
| API 인증·권한·호출량 문제 | CLI에서 오류 종류에 맞는 안내 출력 |
| 인증키 보호 | `.env`는 Git 제외, 예외에서 요청 전문·키를 노출하지 않도록 처리 |
| 도구 반복 | 최대 5회 라운드로 제한 |

**기술적 제한:** 데이터베이스·검색 인덱스·LangGraph·예측 모델·웹 UI·출하량 Tool은 구현하지 않았습니다. 도구 실행은 로컬 Python 프로세스에서 이뤄지며 분석에 사용하는 CSV는 저장소의 기존 처리 파일입니다.

## 6. 코드 읽는 순서(복기용)

1. `agents/baseline.py`의 `load_price_observations()` — 어떤 행을 선택하고 왜 가중평균을 쓰는지.
2. `agents/baseline.py`의 `calculate_break_even()` — 계산식과 입력 검증.
3. `agents/agent.py`의 `compare_shipping()` — 계산 엔진과 도구 응답 연결.
4. `agents/agent.py`의 `run_turn()` — LLM ↔ Python 함수 왕복.
5. `agents/agent.py`의 `format_verified_result()` — 숫자를 재계산하지 않는 출력.
