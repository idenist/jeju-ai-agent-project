# 통합 Agent의 과거 가격 비교 도구 연결

**단계:** STEP 5-1 · **기준 브랜치:** `integration/agents`

## 목적

정현님이 구현한 `get_price_history`를 기존 Juneok Agent의 허용 도구로 등록합니다. 정현님 별도 LLM Agent를 실행하지 않고 검증된 Python 조회 함수만 호출합니다. 사용자가 직접 제공한 비교 조건을 유지하고 미래가격·보관 수익률은 추정하지 않습니다.

## 실행 순서

1. Agent가 `get_price_history`의 조건을 추출합니다. 지정하지 않은 값은 `null`이며 포장 종류와 포장중량을 구분합니다.
2. `verify_integrated_price_sources()`로 선택된 시장 원천과 동결된 과거 가격쌍을 **전체 재생성 검증**합니다. 원천·품질 구분·집계·관측일이 다르면 중단합니다.
3. 기존 `agents.jeonghyeon.price_history.execute_tool()`로 과거 동일 규격의 실제 비교쌍만 조회합니다. 조회 뒤 원천을 다시 검증하고 중간 변경이 확인되면 결과를 폐기합니다.
4. `normalize_tool_result()`로 상태를 통일합니다. 기존 `source_status`는 남기며 정상/품질 경고/비교 불가 건수, 원본 예시, 조회 출처는 수정하지 않습니다.
5. 채팅, Streamlit 및 Markdown·PDF 보고서는 같은 Python 결과를 출력합니다. 모델에는 상태·추가 확인 조건·비교 건수의 요약만 전달하고 개별 가격행은 전달하지 않습니다.

## 상태와 사용 제한

| 원래 조회 상태 | 통합 상태 | 화면 처리 |
|---|---|---|
| `OK` | `OK` | 경고 없는 과거 비교쌍과 가격 변동 범위 표시 |
| `NEEDS_CLARIFICATION` | `NEEDS_INPUT` | 필요한 조회 조건·후보 표시. 자동 선택 금지 |
| `NO_CLEAN_COMPARISON` | `NO_DATA` | 경고 있는 사례 개수만 표시하고 정상 사례처럼 사용하지 않음 |
| `INTERVAL_NOT_AVAILABLE`, `NO_DATA` | `NO_DATA` | 지원 간격 또는 해당 결과가 없음을 명시 |
| `AMBIGUOUS_CODES`, 원천 검증 실패 | `DATA_ERROR` | 가격 비교 결과 표시 중단 |
| `ERROR` / 사용자 입력 오류 | `INVALID_INPUT` 또는 `DATA_ERROR` | 기존 오류 구분 유지 |

**제약:** 과거 7일 경락가격 차이는 같은 감귤을 7일 보관한 후 판매한 결과가 아닙니다. 지금 출하·보관 여부 및 실제 수취단가를 결정하는 입력으로 자동 전환할 수 없습니다. 최신 원천 선택값이 기존 비교쌍과 다르면 새 비교쌍 생성·검증 전에는 조회를 차단합니다.

현재 단계는 자연어 도구의 **모의 실행 경로**를 연결하는 작업입니다. 실제 모델의 조건 추출 정확도나 유료 API 전 구간 성능은 STEP 7에서 별도로 평가해야 합니다.

## 실행

Windows CMD, 프로젝트 루트:

```bat
.\.venv\Scripts\python.exe -m unittest discover -s tests -p "test_integration_price_history.py" -v
.\.venv\Scripts\python.exe -m unittest discover -s tests
.\.venv\Scripts\python.exe -m unittest discover -s evals -p "test_*.py"
```

기존 계산 결과 및 정산 기록은 변경하지 않습니다. 기존에 정현님 브랜치에서 독립 실행하던 자연어 조회 Agent는 회귀 검증 자료로 보존합니다.
