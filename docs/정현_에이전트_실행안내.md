# 감귤 과거 가격 비교 · B안 가정 단가 에이전트

저장소 최상위 폴더에서 실행한다. Python 3.10 이상을 사용한다.

```powershell
python -m agents.jeonghyeon.agent --demo
```

데모는 준비된 조회 조건과 실제 CSV로 조건 확인, 비교 결과, 자료 부족 화면을 보여준다.
이어서 B안 가정 단가(A안 2,500원 · 7일 뒤), B안만 14일 뒤로 바꾼 결과, 지원하지 않는 10일 간격 화면을 보여준다.
자연어 질문은 OpenAI SDK를 설치하고 터미널에 `OPENAI_API_KEY`를 설정한 뒤 입력한다.
조회 에이전트와 조건 추출 평가의 기본 모델은 `gpt-6-luna`다. `--model`, `OPENAI_MODEL`, 기본값 순으로 적용한다.
저장된 21턴 평가 기록은 `gpt-5-mini`로 수집한 결과다. Luna에서 새 결과를 얻으려면 `--model gpt-6-luna`로 실제 평가를 실행한다.

```powershell
python -m pip install openai
python -m agents.jeonghyeon.agent
```

1. “조생귤의 과거 7일 가격 변화를 알려줘.”
2. 되묻는 질문에 “특등급, 소 크기, 상자 5kg으로 비교해 줘.”
3. “같은 조건에서 2026년 11월 3일 기준으로 비교해 줘.”
4. “그럼 A안을 2,500원으로 가정하면 7일 뒤 B안 단가는?” (B안 가정 단가 도구로 전환)
5. “B안만 14일 뒤로 바꿔 줘.” → “10일 뒤면?” (지원하지 않는 간격은 가격을 만들지 않음)

## 두 도구의 역할

| 질문 예 | 모델이 고르는 도구 | 답변 |
|---|---|---|
| 조생귤 과거 7일 가격은 어땠어? | `get_price_history` | 과거 사례와 변동 범위 |
| A안 2,500원이면 7일 뒤 B안은? | `get_price_scenarios` | 과거 변동을 대입한 B안 가정 단가 3개 |
| 일주일 보관하면 얼마 더 남아? | `get_price_scenarios` (`asks_profit`) | B안 가정 단가 + 손익은 팀 손익 기능 연결 후 제공 안내 |
| 다음 주 가격 오를까? | `get_price_history` (`intent=unsupported`) | 예측은 하지 않는다는 안내 |

- 모델은 두 도구 중 하나를 반드시 고르고(`tool_choice="required"`), 조건만 추출한다. 단가와 문장은 Python이 만든다.
- 날짜는 모델이 계산하지 않는다. 모델은 말한 숫자를 그 기준의 필드에 그대로 넣는다. “오늘·지금”은 `option_a_days_from_today=0`, “A안보다 7일 뒤”는 `days_after_option_a=7`, “A안은 오늘부터 3일 뒤, B안은 오늘부터 10일 뒤”는 `option_a_days_from_today=3`, `option_b_days_from_today=10`이다. Python이 한국 시간 기준 오늘로 두 판매일을 만들고 그 차이로 간격을 정한다.
- A안 판매 시점을 말하지 않으면 오늘로 두고 답변 첫 줄에 밝힌다. 월·일만 말한 날짜는 오늘 이후 가장 가까운 날짜로 본다.
- 판매일 간격(B−A)은 가격 비교에만 쓴다. 손익의 보관 일수(`delay_days`)는 팀 손익 쪽 입력이며 섞지 않는다.
- 매 턴 새로 계산하므로 간격을 바꾸면 이전 턴의 B안 가격이 다시 나오지 않는다.

## 구현 방식 비교

| 방법 | 장점 | 제약 |
|---|---|---|
| JSON 조건을 직접 입력 | 설치나 키 없이 재현 가능 | 사용자가 필드 이름과 형식을 알아야 함 |
| 모델이 조건을 추출하고 Python이 결과 출력 | 자연어와 검증된 수치 출력을 함께 지원 | 자연어 해석에 API 필요 |
| 조회 후 모델을 한 번 더 호출해 설명 | 답변 표현이 유연함 | API 호출이 늘고 수치 재서술을 점검해야 함 |

두 번째 방법을 사용했다. `run_turn()`은 도구 호출에서 조회 조건을 받고,
`price_history.py`는 CSV를 필터링한다. `format_result()`는 경고 수와 사례 가격을
조회 결과 그대로 표시한다. 도구 스키마에서 빠진 입력은 null로 표현한다.
호출 형식은 [OpenAI Docs의 함수 호출 가이드](https://developers.openai.com/api/docs/guides/function-calling)를 따랐다.

### 직접 확인하기

- 포장 중량을 빼고 어떤 조건을 되묻는지 본다.
- 10일을 지정해 현재 확보된 비교 간격이 어떻게 표시되는지 확인한다.
- 2026년 10월 27일을 기준일로 지정해 전체 사례 조회와 날짜 하나의 조회를 비교한다.

## 평가

```powershell
python -m scripts.evaluate_price_extraction --dry-run
python -m scripts.evaluate_price_extraction --dry-run --cases scripts/scenario_extraction_cases.json
python -m scripts.evaluate_price_extraction --model gpt-6-luna --cases scripts/scenario_extraction_cases.json --output data/reports/evaluation/scenario_result_1.json
```

- 기존 21턴(`price_extraction_cases.json`)은 회귀 검증용이다. 손익을 묻는 한 문항만 B안 가정 단가 도구로 기대값을 바꿨다.
- 새 14턴(`scenario_extraction_cases.json`)은 도구 선택, 두 안 모두 오늘 기준인 날짜 추출, 빠진 A안 단가·B안 시점 되묻기, 후속 턴 조건 유지, 지원하지 않는 간격, 가정 표시를 확인한다.
- 조건 일치와 별도로 사용자가 보는 답변에 꼭 있어야 할 문구(`reply_includes`)와 남으면 안 되는 문구(`reply_excludes`)를 검사한다. 평가 기준일은 2026-11-10으로 고정한다. 표준화 후 채점은 시점 필드 대신 실제 판매일을 비교한다(같은 날짜를 다른 기준으로 말해도 정답).

이 버전의 범위는 과거 가격 비교와 B안 가정 단가까지다. 손익 계산은 팀 손익 함수와 통합 후 연결하고, 제주데이터허브 출하량 설명은 별도 도구가 필요하다.
