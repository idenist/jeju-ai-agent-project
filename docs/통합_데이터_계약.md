# 제주 감귤 Agent 통합 데이터 계약 — 1차

**기준 브랜치:** `integration/agents` · **기준 커밋:** `aea0287` · **작성일:** 2026-11-09

## 목적

세 브랜치의 **데이터 의미와 원천 버전**을 통일합니다. 기존 Agent의 실행·출력 형식은 이 단계에서 수정하지 않습니다. 가격 조회·출하 손익·과거 가격 비교 도구를 연결하기 전에 다음 계약을 통과해야 합니다.

## 1. 데이터와 단위

| 구분 | 기준 파일 | 의미·단위 |
|---|---|---|
| 상세 시장가격 | `data/processed/daily_prices.csv` | 확보된 서울가락시장 경매 관측 단가 **원/kg**. 실시간 시세·농가 실수취 단가 아님 |
| 과거 가격 비교 | `price_comparison_availability.csv`, `price_comparisons.csv` | **같은 거래조건**, 정확히 3·7·14 **달력일** 간격의 과거 관측가격 비교 |
| 과거 제주 출하량 | `data/processed/daily_shipments.csv`, `monthly_shipments.csv` | 신고소 기준 출하량 **톤**. 경매 거래량과 다른 지표 |
| 사용자 가격·비용 | `ScenarioStore` 입력 | 사용자가 확인한 **가정 또는 실제 입력값**. 관측 경락가격으로 자동 대체하지 않음 |

**주의:** 현재 가격 원본은 2026-10-01~2026-11-03, 과거 출하량은 2018-01-01~2025-09-17 범위입니다. 시점과 품종 분류가 달라 자동 결합하거나 인과관계를 추론하지 않습니다.

## 2. 동일 거래조건 식별

시장가격의 비교 키는 `market_code`, `variety_code`, `grade_code`, `size_code`, `package`, `package_kg`, `trade_type` **일곱 개**입니다.

- 원천 **코드**를 문자열로 보존합니다. 표시명이 같아도 원천 코드가 다르면 합치지 않습니다.
- `package_kg`는 양수 유한소수로 비교합니다. `5`, `5.000`은 같은 무게입니다.
- `variety`·`grade`·`size` 등 표시명은 사용자 안내용입니다. 사용자가 모른다는 `null`과 원본의 **`미상` 데이터**는 다릅니다.
- 품종 별칭은 입증된 1:1 대응에서만 정규화합니다. 경매의 `조생귤`과 출하통계의 `노지온주`를 임의로 연결하지 않습니다.
- 등급·크기·시장·거래방식·포장 단위를 생략한 가격 평균을 같은 조건의 가격처럼 사용하지 않습니다.

## 3. 원천 버전 일치 필수

`agents/common/data_contract.py`의 `verify_price_pair_sources(project_root, market_root=None)`가 다음 사항을 검사합니다.

1. 비교 보고서 `data/reports/price_comparison_report.json`의 입력 SHA-256과 공통 명세 `data/metadata/juneok_manifest.json`의 상세 가격 파일 해시가 일치하는지 확인합니다.
2. 동결된 공통 `daily_prices.csv`의 실제 파일 해시를 확인합니다.
3. **현재 선택된 시장가격 스냅샷**의 해시가 과거 비교 자료 생성에 사용한 원천 해시와 같은지 확인합니다.
4. 과거 비교 파일의 필수 컬럼과 기록 수가 보고서와 일치하는지 확인합니다.

불일치하면 `DATA_ERROR`와 세부 `reason`을 반환합니다. 특히 스냅샷 불일치는 `VERSION_MISMATCH`로 표시하며 **최신 가격에 과거 가격쌍 결과를 조용히 결합하지 않습니다.** 과거 가격 비교 기능을 연결할 때 이 검사를 필수 관문으로 사용합니다.

**STEP 3-4 보완(2026-11-10):** 위 `verify_price_pair_sources()`는 원천 SHA-256·행 수 등을 검사하는 **경량 확인 함수**입니다. 가격쌍 CSV의 행 개수는 같으나 가격·변동률·비교불가 사유가 변조된 경우 탐지하지 못할 수 있습니다. 실제 서비스 연결 전에는 새 `verify_integrated_price_sources()`를 사용해 **원본에서 재계산한 모든 비교 행·필드와 보고서 집계까지** 검증해야 합니다. 실패 시 과거 가격쌍 조회·조합 분석을 차단합니다.

현재 동결 공통 가격 CSV와 정현님의 비교 보고서에 기록된 원천 해시는 `d8076c3590a898953e312faf1d0f69237e65a6f0fef7d6616e2c9e42076a4589`입니다. 새 자료로 갱신할 때는 같은 원천에서 비교쌍을 재생성하고 보고서·품질 검증을 다시 수행해야 합니다.

## 4. 계산에 관한 사전 합의

- **경락가격 ≠ 농가 실수취가격.** 기준가격 출처와 수수료 차감 전후(`gross` / `commission_net`)를 분리합니다.
- 현재·지연 출하의 공통 비용은 사용자가 동일하다고 **확인한 경우에만** 제외합니다. 이미 포함된 수수료·보관비를 재차 빼지 않습니다.
- 감모율은 **해당 보관기간 전체의 누적 감모율(%)**입니다. 예: `2`는 2%이지 0.02%가 아닙니다. 기간이 바뀌면 다시 확인합니다.
- 미입력(`null`)은 0이 아닙니다. 미래 가정가격은 사용자 가정이지 예측치가 아닙니다.
- 즉시 출하(0일)는 **경제적 비교 기준**일 뿐, 실제 오늘 출하 가능하다는 보장은 아닙니다.
- 수치 계산은 `Decimal` 기반 Python 함수에서 수행하고 모델이 재계산하지 않습니다.

## 5. 이번 변경 범위와 다음 단계

**이번 단계:** 읽기 전용 원천 검증 도구, 원천 거래조건 키 정규화, 자동 테스트 및 이 문서를 추가합니다. 기존 `app.py`, Agent, 전처리 스크립트, 원본 CSV는 수정하지 않습니다.

**다음 3-2:** 각 도구의 `OK`, `NEEDS_INPUT`, `NO_DATA`, `INVALID_INPUT`, `DATA_ERROR`와 정현님 도구의 `NEEDS_CLARIFICATION`, `NO_CLEAN_COMPARISON`, `INTERVAL_NOT_AVAILABLE` 등을 **원래 상태·오류 사유를 보존하는 공통 응답 형식**으로 매핑합니다.

**3-3:** 승혁님 기본 손익 계산과 준억님 확장 계산의 동일 조건 결과를 교차 검증하고, 서로 다른 비용 기준을 잘못 비교하지 않도록 계약 테스트를 추가합니다.
