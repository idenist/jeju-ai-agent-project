## 1. 프로젝트 소개

### 1.1 개발 목적

감귤 출하를 결정할 때는 판매가격뿐 아니라 보관 중 발생하는 감모, 보관비, 수수료와 출하 일정도 고려해야 합니다. 이 프로젝트는 농가와 출하 담당자가 **현재 판매와 보관 후 판매의 경제적 조건을 비교**하도록 돕는 AI Agent입니다.

사용자가 제시한 물량·가격·비용·감모 조건으로 **보관 후 출하에 필요한 손익분기 판매단가**를 계산하고, 제주 출하통계와 도매시장 경락가격을 참고자료로 제공합니다. 미래 판매단가가 필요한 분석에서는 **사용자가 설정한 가정값**을 활용합니다.

### 1.2 대상 사용자와 이용 흐름

주요 사용 대상으로 감귤 농가, 생산자 조직, 선과장·APC 및 출하 담당자를 가정합니다. 실제 현장 사용성은 후속 검증 대상입니다.

1. 현재 판매조건과 비교할 보관기간·감모·비용을 입력합니다.
2. 현재 출하 기준과 보관 후 출하 대안의 손익분기 단가를 확인합니다.
3. 필요하면 같은 거래규격의 과거 경락가격과 제주 출하통계를 조회합니다.
4. 미래 판매단가·감모에 대한 가정을 바꾸어 결과를 비교합니다.
5. 보고서를 저장하고, 실제 출하 이후에는 정산내역을 기록·검산할 수 있습니다.

이때 **0일은 손익 비교를 위한 기준 시점**입니다. 현실의 출하 가능 날짜는 계약·운송·보관 여건 등을 함께 확인해야 합니다.

## 3. 팀 통합 내용

개별 구현을 하나의 **Streamlit 화면과 활성 대화 Agent** 아래 연결했습니다. 모델이 사용자 요청을 해석해 도구를 선택하고, 가격 조회·손익 계산·상태 변경은 Python이 수행하는 구조입니다.

| 팀원 | 기존 개발 내용 | 통합본에서의 역할 |
|---|---|---|
| **승혁** | 초기 시장가격 조회·손익 계산 베이스라인, 평가 기반 | 계산 결과의 독립 검산과 회귀 테스트 기준으로 활용. [`agents/baseline.py`](../agents/baseline.py) |
| **정현** | 동일 거래규격의 과거 경락가격 비교 및 가격 변동 기반 가정 단가 도구 | 과거 가격 조회를 통합 Agent와 Streamlit 직접 조회에 연결. [`agents/jeonghyeon/price_history.py`](../agents/jeonghyeon/price_history.py) |
| **준억** | Streamlit, 대화 Agent·하네스, 조건·손익 계산, 보고서·저장·정산 | 사용자 화면과 활성 Agent의 실행 기반으로 사용. [`agents/juneok/`](../agents/juneok/), [`app.py`](../app.py) |

### 통합 과정에서 정리한 공통 구조

- **데이터 계약:** 거래규격·단위·원천 버전과 과거 가격 비교 데이터의 일치 여부 검증
- **응답 계약:** 각 도구의 상태·오류·품질·출처 정보를 공통 형식으로 연결
- **계산 서비스:** [`agents/common/calculation_service.py`](../agents/common/calculation_service.py)를 손익 계산의 공통 진입점으로 사용
- **과거 가격 서비스:** 정현님 조회 모듈을 원천 검증·후속 조건 관리·보고서 출력과 연결
- **UI 및 평가:** 직접 조회와 대화 도구를 하나의 작업공간에서 제공하고 통합 평가·인수 점검 코드 추가

정현님의 **과거 변동 기반 B안 가정 단가 모듈**은 저장소에 유지되어 있습니다. 통합 화면에서 사용하는 가격 조회 기능과 역할이 달라 활성 Agent에 연결할지는 별도 검토 항목으로 두었습니다.

상태 관리와 도구 호출의 상세 경로는 후속 문서 `02_시스템_아키텍처.md`에서 설명합니다.
